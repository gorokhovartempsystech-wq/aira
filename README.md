# AIRA — AI Requirements Assistant

Десктопный редактор требований с локальными нейросетями. Аналитик пишет или вставляет
требования, по кнопке получает ревью (формулировки, дубли, противоречия) и — главное —
видит, **что ещё в документации задето его правкой**. Документы не покидают компьютер:
модели работают локально на CPU.

Учебный стартап команды С15 (МФТИ, трек «Стартап», НИР 3).

## Как устроено

```
app/  ── десктоп (редактор, панель замечаний) ──HTTP 127.0.0.1──▶  engine/  (ML-движок, sidecar)
                                                                      │
                                       contracts/engine-api.md ◀──────┘  договор между ними
```

- **`engine/`** — ML-движок: разбор документа, ревью, влияние правки (Python; в рантайме только
  onnxruntime + tokenizers + numpy, без PyTorch). Обучение моделей — там же, `engine/README.md`.
- **`app/`** — десктопное приложение. Запускает движок как дочерний процесс и говорит с ним по
  локальному HTTP — см. `app/README.md`.
- **`contracts/`** — контракт «приложение ↔ движок»: описание, JSON Schema, примеры. Меняем
  только через PR, который ревьюят обе стороны.
- **`design/`** — макеты и решения по интерфейсу.
- **`docs/`** — продукт (MVP, пилот), исследования (кастдев, ресерч), журнал решений.

## Быстрый старт

```bash
git clone <адрес репозитория> && cd aira
# движок: окружение и тесты
cd engine && python -m venv .venv && . .venv/bin/activate
pip install -r requirements-engine.txt -r requirements-test.txt
pytest -q
# пакет моделей (≈ 400 МБ) — из GitHub Releases, см. engine/README.md
python -m aira_ml.engine serve --models ../models/models-0.1
```

## Как работаем

Коротко (подробно — `CONTRIBUTING.md`):
1. Задача — в **GitHub Projects** (доска «AIRA»). Без задачи не начинаем.
2. Ветка `<кто>/<номер>-кратко`, например `artem/12-impact-api`.
3. Pull Request в `main` → ревью владельца папки → слияние. В `main` напрямую не пушим.
4. Раз в неделю — созвон команды: что сделано, что мешает, план. Итоги — в `docs/decisions/`.

## Чего в репозитории нет и не будет

- **Ключей и паролей** (`.env` в `.gitignore`).
- **Реальных документов компаний** (рабочие документы респондентов и пилотов) — только у себя,
  локально. В репозитории — синтетические данные и публичные наборы с лицензией.
- **Весов моделей** — они в GitHub Releases (большие файлы).
