# AIRA — AI Requirements Assistant

Локальный помощник системного аналитика для проверки одного документа требований. Пользователь импортирует DOCX, запускает анализ, разбирает подсказки с цитатами, вручную исправляет текст, повторяет проверку и сохраняет документ. Решение о том, является ли замечание ошибкой, принимает человек.

Учебный стартап команды С15, МФТИ, НИР 3. Актуальные продуктовые границы: [current-product-scope](app/backend/docs/current-product-scope.md).

## Что есть в коде

- `app/backend/` — backend Никиты: DOCX-редактор, сохранение и восстановление, очередь проверки, native worker и проверка координат результатов. Добавлен явный режим реальной локальной модели; fixture остаётся отдельным тестовым режимом.
- `engine/aira_ml/` — правила формулировок, семантический поиск, NLI для возможных противоречий и исследовательский анализ влияния правки. NLI рассчитывает каждое направление пары отдельно, чтобы соседние строки пакета не меняли оценку.
- `engine/experiments/numeric_candidate/` — отдельный эксперимент: числовые ограничения, привязка объектов и условий, общие правила, исключения и отрицание. Этот модуль не подключён к рабочему API/UI и не включается по умолчанию.
- `tools/prepare_ml_bundle.py` — сборка native ML-пакета из уже полученных весов с проверкой manifest/sha256. Существующий пакет не перезаписывается.

Windows и macOS — целевые платформы. Код и локальные проверки не доказывают готовность установщиков, лицензирования или совместимость со всеми документами Word. Проверенный Windows-сценарий и ограничения описаны в [инструкции ML-кандидата](docs/research/ml-candidate-20261105.md).

## Проверить движок

```bash
cd engine
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-engine.txt -r requirements-test.txt
python -m pytest -q
# Отдельный исследовательский браузерный прототип:
python -m aira_ml.proto --models /path/to/models-0.2m --port 8780
```

Этот прототип не является основным редактором команды. Подключение модели к DOCX-приложению и подготовка native bundle описаны в [инструкции](docs/research/ml-candidate-20261105.md). Работа native worker поддерживается на Windows/macOS; Linux/WSL используется для части тестов и ML-исследований.

Пакет весов `0.2m`: rubert-tiny2 + pair2 + nli5, ONNX int8 на CPU. Веса не входят в Git. Стабильный режим меняет способ вычисления, но не веса и не порог NLI. Качество подсказок следует проверять отдельно от воспроизводимости оценок.

## Ограничения качества

Найденные моделью противоречия — возможные расхождения. В CRM остаются ложные сравнения альтернативных причин отказа; роль фрагмента и справочника ещё нужно учитывать. Числовой эксперимент поддерживает ограниченный словарь объектов и формулировок; неизвестные условия дают отказ от сравнения. Совместимость одного числа не доказывает совместимость составного требования.

Полный CRM DOCX проверялся локально: reader → модель → координаты → правка → повторная проверка. Дополнительные числовые находки пока сохраняются отдельно, без нового API-контракта. Вопросы о недостающих бизнес-условиях и генеративная LLM не объявляются готовой функцией. Данные с предварительной разметкой ассистента не являются независимым экспертным тестом.

Текущий объём: ручные исправления, один документ, DOCX. PDF/OCR, Confluence/Jira, командное облако и автоматическое применение AI-правок не входят в эту версию.
