# Контракт: приложение ↔ ML-движок (v1)

Движок — отдельный процесс на компьютере пользователя. Приложение запускает его, читает первую
строку stdout и дальше говорит с ним по HTTP на `127.0.0.1`. Документы никуда не уходят.

Схема данных: `engine.schema.json`. Реальные примеры: `examples/`. Изменения — только через PR с
меткой `contract` и ревью обеих сторон.

## Запуск

```bash
python -m aira_ml.engine serve --models <папка пакета моделей> --port 8765 --threads 4
```

Первая строка stdout (JSON):

```json
{"ready": true, "port": 8765, "token": "<одноразовый токен>"}
```

Каждый запрос должен нести заголовок `X-Aira-Token: <token>`, иначе `401`. Так страница в браузере
пользователя не сможет обратиться к движку. Сервер слушает только `127.0.0.1`.

## Методы

| метод | что делает | время (CPU, 4 потока) |
|---|---|---|
| `GET /health` | версия движка и пакета моделей | — |
| `POST /v1/parse` | текст → фрагменты (абзацы и пункты, со статусами) | мгновенно |
| `POST /v1/review` | ревью документа: формулировки, дубли, противоречия | ~3–4 с на 50 фрагментов |
| `POST /v1/impact` | что ещё задето правкой одного фрагмента | ~0,2 с |

### Вход

Любой метод принимает **либо** `text` (движок сам разберёт), **либо** `fragments` (уже разобранные,
например из `/v1/parse` — так `id` фрагментов стабильны между вызовами).

```json
{"text": "# Раздел\n- Требование…",
 "disabled_types": ["formulation"],
 "dismissed": ["iss-1a2b3c4d5e"]}
```

- `disabled_types` — типы замечаний, которые пользователь выключил («не показывать грамматику»).
- `dismissed` — id замечаний, которые пользователь отклонил: движок их больше не вернёт.
  Приложение хранит отклонения у себя (это же — оценки качества для нас).

`/v1/impact` дополнительно: `new` (новый текст фрагмента) и `fragment_id` (что правили). Если
`fragment_id` нет — передайте `old`, движок найдёт ближайший по тексту фрагмент.

### Фрагмент

| поле | тип | что это |
|---|---|---|
| `id` | строка | `F001`… — стабилен, пока не меняется разбиение |
| `text` | строка | текст пункта без маркера списка |
| `document` | строка | раздел (последний заголовок `#`) |
| `status` | `active` · `exception` · `deprecated` · `delta` · `discussion` | архив, черновики доработок и обсуждения в проверках не участвуют |
| `type` | строка | «функциональное требование», «поле API», «критерий приёмки»… (эвристика) |
| `offset` | число | позиция начала текста фрагмента в исходном `text` — для подсветки в редакторе |

Статус определяется по заголовку раздела («Архив…», «Доработки…», «Обсуждение…») и маркерам
в тексте («Обсуждается:», «Исключение…»).

### Замечание (`issues[]`)

| поле | что это |
|---|---|
| `id` | стабильный id (одно и то же замечание — один id между вызовами) |
| `type` | `formulation` · `duplicate` · `contradiction` · `affected` |
| `severity` | `info` · `warning` · `critical` |
| `light` | `red` — уверенно; `yellow` — «проверьте» (подсветка сомнений) |
| `confidence` | 0–1, откалиброванная уверенность модели (для правил — 1.0) |
| `fragment_id` | где замечание |
| `span` | `{start, end, quote}` — позиции **внутри текста фрагмента**; в документе: `offset + start` |
| `related` | второй фрагмент-основание `{fragment_id, quote, status}` или `null` |
| `explanation` | почему, одним предложением |
| `rule` | правило (ISO/IEC/IEEE 29148…) или `null` |
| `suggestion` | `{before, after}` для кнопки «исправить» или `null`. Для формулировок `after` — шаблон с `<…>`, который пользователь заполняет сам |
| `question` | вопрос к бизнесу или технике, если уместно, иначе `null` |

Ответ `review` содержит ещё `questions[]` — уникальные вопросы для списка «что уточнить», и
`checked` — сколько фрагментов проверено и сколько пропущено по статусу.

Ответ `impact` содержит `source` (какой фрагмент правили), `search_terms` (что исчезло из текста),
`issues[]` типа `affected`, отсортированные: сначала `red`, по убыванию уверенности.

## Чего движок не делает (v1)

- Не правит текст сам: только `suggestion`, применяет пользователь.
- Не читает картинки, сканы и PDF без текстового слоя.
- Противоречия внутри документа — пока только между похожими по смыслу пунктами; для «правило
  поменяли, а старые упоминания остались» — `/v1/impact`.
- Не ходит в интернет.

## Версии

- `engine` — версия кода движка, `models` — версия пакета моделей (из `manifest.json` пакета).
- Ломающее изменение контракта → `/v2/...`, `/v1` живёт до переезда приложения.
