# Пилот AIRA в Yandex Cloud

Цикл F02-UPDATES-02. ВМ `aira-pilot` работает на Ubuntu 24.04, публичный статический IPv4 — `51.250.81.70`. TCP 80 и 443 открыты для сайта и получения сертификата. SSH-вход — пользователь `ubuntu` с ключом. PostgreSQL использует локальный сокет, а HTTP-сервис лицензий слушает `127.0.0.1:8766`.

## Подготовка

Из проверенного checkout монорепозитория подготовьте пакет из файлов лицензирования, без модели, документов и окружения. Передайте его, контрольную сумму и два скрипта из этой папки в закрытый staging-каталог на ВМ по проверенному SSH.

```sh
tar -czf backend.tar.gz -C app/backend \
  pyproject.toml requirements.lock src/ara/__init__.py src/ara/licensing
shasum -a 256 backend.tar.gz > backend.tar.gz.sha256
```

В staging не должно быть `__pycache__`, файлов окружения и локальных данных. На ВМ запустите `sudo bash install-license.sh`. Скрипт ставит PostgreSQL 18 и Python-зависимости, создаёт служебного пользователя и постоянный pepper в его `~/secrets.env`, и проверяет локальный маршрут. Повторный запуск сохраняет существующую базу и pepper. Для переноса ранее выданных ключей нужны обе резервные копии — база и pepper.

Запустите `sudo bash install-https.sh /absolute/staging/Caddyfile` с файлом из `sites/aira-download`. Caddy получает короткоживущий сертификат Let's Encrypt для IP и продлевает его автоматически. Проверьте HTTPS извне до публикации. Пустой JSON на обоих маршрутах лицензий должен давать 422.

## Публикация и приёмка

Положите проверенные установщики и контрольные суммы в `/srv/aira-public/downloads`. Перед публикацией сверяйте SHA-256 на сервере. После этого разместите подписанный Mac appcast в `/srv/aira-public/updates/macos-arm64.xml` и статические файлы сайта из `sites/aira-download`. Образ Mac 0.2.5 содержит новый адрес лицензий и обновлений. Из 0.2.4 и более ранних сборок переход ручной. Windows 0.2.0 — прежний пилот, Windows appcast остаётся пустым до выпуска нового EXE.

Из внешней сети проверьте TLS, страницу, обе загрузки, appcast и оба маршрута лицензий. На новом Mac-профиле активируйте одноразовый ключ и подтвердите повторный вход без повторного ввода ключа. Отключите тестовый ключ после прогона. Секрет подписи обновлений остаётся у оператора, он не нужен ВМ.
