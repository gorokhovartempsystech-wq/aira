# Автоматическая публикация сайта

Задача SITE-DEPLOY-01, решение Никиты в чате 14 ноября 2026.
После слияния изменений `sites/aira-download/**` в `main` workflow
`Publish website` проверяет файлы и публикует сайт на https://51.250.81.70.
Изменения самого workflow и `infra/site-deploy/**` также запускают проверку
и публикацию; серверная часть обновляется оператором отдельно.
Вкладка Actions → Publish website → Run workflow позволяет повторить публикацию
из `main`. Pull request выполняет проверки без публикации.
Проверочный job всегда вызывает `publish.py --check`: системные переменные
`GITHUB_*` не используются для переключения режима. Регрессия проверяет запуск
валидации при настоящем `GITHUB_EVENT_NAME=push` без OIDC-доступа и сети.

Публикуются ровно `index.html`, `styles.css`, `app.js`, `favicon.svg` и
`third-party.txt`. При добавлении нового ресурса нужно согласованно изменить
allowlist клиента, сервера и Caddy, затем обновить сервер. Установщики,
подписанные каналы обновлений, конфигурация Caddy и сервисы лицензирования
остаются в отдельном процессе выпуска.

## Доступ

GitHub выдаёт короткоживущий OIDC-токен задаче публикации. Секретов репозитория,
SSH-ключей и токенов доступа для этого workflow нет. Сервер проверяет подпись
RS256 по ключам фиксированного провайдера GitHub, issuer, audience, неизменяемые
ID репозитория и владельца, точный workflow, ветку `main`, тип события,
GitHub-hosted runner и срок токена. URL ключей из токена не используется.
Запрос без корректного токена получает 401. Источник механизма:
[GitHub OIDC reference](https://docs.github.com/en/actions/reference/security/oidc).

Локальный сервис слушает `127.0.0.1:8768`, Caddy проксирует только
`/_deploy/site`. Процесс `aira-site-deploy` может записывать только каталог
с версиями сайта `/var/lib/aira-site-deploy`. У него нет доступа к данным
лицензирования, секретам и каталогу установщиков. Запрос ограничен 1 МБ,
каждый файл — 256 КБ. Имена файлов заданы в коде; пути из запроса не принимаются.

## Публикация и проверка

Пакет содержит SHA коммита и все пять файлов. SHA должен совпасть с подписанным
claim GitHub. Сначала сохраняется целая новая версия, затем атомарно меняется
символическая ссылка `current`. Публичные файлы в `/srv/aira-public` указывают
через неё. Старые версии сохраняются. Старый запуск не может заменить новый;
повтор того же запуска разрешён только с тем же содержимым. После публикации
workflow сверяет SHA-256 всех пяти файлов, полученных по публичному HTTPS.
При ошибке workflow красный; предыдущий каталог версии остаётся доступен.
Ошибка внешней проверки после переключения не откатывает версию автоматически.
Публикуйте страницу через workflow: ручная замена файлов в `/srv/aira-public`
может заменить символические ссылки обычными файлами. После такого выпуска
оператор должен сохранить актуальную страницу в `main` и восстановить ссылки,
прежде чем возобновлять автопубликацию.

Первичная настройка оператором: отдельный системный пользователь, каталог
`/opt/aira-site-deploy` с root-owned кодом и venv (Python 3.12,
`cryptography==47.0.0`), unit `aira-site-deploy.service`. Включить unit,
проверить его и добавить перед публичным обработчиком Caddy:

```caddy
@site_deploy path /_deploy/site
handle @site_deploy {
    request_body {
        max_size 1MB
    }
    reverse_proxy 127.0.0.1:8768
}
```

Перед заменой публичных файлов сохранить резервную копию и проверить, что они
не менялись с момента подготовки. Первый каталог версии содержит эти же файлы.
Валидировать Caddy перед reload; существующие маршруты оставить без изменений.
Новые изменения в серверном Python не устанавливаются workflow автоматически:
их проверяет и устанавливает оператор. Проверка локально:

```sh
python -m unittest discover -s infra/site-deploy -p 'test_*.py' -v
python infra/site-deploy/publish.py --check
```

Для оперативного отката оператор переключает `current` на сохранённый каталог
версии атомарным `mv -Tf` временной ссылки. Следующий выпуск делается новым
запуском workflow из актуального `main`. Для остановки автопубликации отключить
workflow в GitHub Actions и сервис `aira-site-deploy`; публичные файлы останутся.
