# Backend AIRA

Текущий продукт: локальный DOCX-редактор с проверкой требований по кнопке. Решения принимает аналитик, исправления ручные. Основные границы — [current-product-scope.md](docs/current-product-scope.md).

В коде есть API документов и версий, импорт/экспорт и редактор DOCX, сохранение/восстановление, задания проверки, native worker Windows/macOS, контроль версии источника и привязка замечаний к исходному XML. Отдельный явный режим подключает реальный локальный ONNX-анализатор. Fixture сохранён для тестов и не выдаётся за реальную проверку.

## Реальная модель

Подготовка installer-owned `ml_bundle`, запуск Windows-стенда, результаты и ограничения: [инструкция ML-кандидата](../../docs/research/ml-candidate-20261105.md). Веса отдельно от Git; сервер не подменяет их fixture при ошибке. Числовой исследовательский кандидат пока не подключён к рабочему API/UI.

`python scripts/serve_local_model.py --help` показывает параметры локального стенда. Путь модели задаётся подготовленной структурой bundle, а не содержимым документа. Runtime использует native guardian/lease/stop, отдельную тестовую БД и loopback HTTP. Скрипт запуска Windows не является установщиком и не доказывает готовность лицензирования.

## Разработка и проверки

```bash
bash scripts/bootstrap.sh
bash scripts/postgres.sh start
bash scripts/check.sh
```

`check.sh` выполняет Ruff, форматирование и всю pytest-батарею. Acceptance-тесты PostgreSQL создают собственные одноразовые базы и требуют локальный кластер по описанному в fixtures защищённому протоколу. Native-тестам нужна соответствующая ОС. Нельзя считать полную проверку пройденной по одному smoke-тесту или небольшому набору unit-тестов.

`bash scripts/dev.sh --documents` — прежний development API с явным локальным пользователем и тестовым режимом; это отдельный запуск от native реальной модели. Он не является production-авторизацией. Общая инструкция PostgreSQL: [local-postgres.md](docs/local-postgres.md).
