## Недостающий мост local deadline → SQL

C1F §3 фиксирует D_enqueue до B3 admission, поэтому он раньше SQL created_at+300s на время admission и guard; отдельно учитывается сон компьютера. Когда локальный D истёк, SQL deadline ещё может быть жив. [C1A](../src/ara/docx_analysis_worker/control/_controller.py) отзывает публикацию в RAM, но не записывает SQL status. [F2 retire_queued](../src/ara/docx_analysis_worker/supervisor/lifecycle.py) пишет failed/interrupted, [B3 cancel_run](../src/ara/docx_analysis_runs/_lifecycle.py) пишет cancelled/cancel_requested, old expire использует SQL wall clock. Ни один из этих путей сам не является точным сохранением continuous timed_out.

Нужен exact internal finalization contract: какое scoped proof разрешает timed_out/deadline_exceeded до SQL wall deadline, как различать queued/no-create/created, кто владеет proof и в какой момент его можно передать DB worker. Прямо вызывать terminal() по произвольному UUID/reason нельзя. Если permit уже taken/committing/unknown — только C1B settlement/reconciliation и сохранение actual committed success; дополнительный terminalizer не должен обойти эти правила. При DB outage RAM Stop и native cleanup продолжаются, а durable result остаётся pending, без раннего cancelled/success ACK.

## Остальная exact композиция, требующая фиксации до source

- Пять fixed job lanes из C1F, одна result cell на lane, dispatcher loop отдельно; Thread.start unknown не делает replacement thread и не освобождает registry. Зависший SQL/native job после caller5s остаётся активным до фактического завершения, не считается rollback/no-create.
- F1 PublicationPort ждёт50ms, тогда как старый общий tick ориентировался на250ms. Задать wake/servicing contract: публикация не должна систематически timeout из-за выбранного scheduler cadence. Fresh clocks переходов, Stop priority, settle ACK-loss и provisional/taken cell остаются frozen F1; не переписывать его ради нового loop.
- Явно связать admission key/original anchor/unknown ACK и registry16queued+один active. Повтор accepted run не переякоряет D; unresolved admission не вызывает новый enqueue/inference. B3 lookup имеет scoped document lock, но точный negative-barrier/retry protocol нужно записать, прежде чем реализовывать job transitions.
- Native driver factory/observe/close — platform lifecycle lane; renew/Stop — platform control. Mac factory может не вернуть handle при pending Popen; Windows factory возвращает holder/driver до фонового native результата. Unknown pre-return сохраняет armed и slot. Не делать foreign endpoint/process polling и не объявлять Exception доказательством no-create.
- Candidate захватить в live native window до Mac close/discard, физический proof и own I/O quiescence перед child_closed; C1A heartbeat после natural completion отдельно от G renew. Native opaque b'fixture-response' не B1. Portable valid B1 fixture success и actual native invalid_result — отдельные честные gates, без подмены payload.
- Drain/SQL reconciliation/slot release+probe/clean CAS и lost ACK имеют разный порядок. Existing release_slot(False) уже закрывает caller slot reference: нельзя повторно использовать stale lease. Не придумывать physical proof по free slot/terminal SQL. Startup drained может reconcile без inference; armed после crash по-прежнему quarantine без verified boot provider.
- Public bootstrap/admission/stop/shutdown API, server-owned scope и ticket/metadata retention; все heavy callbacks/DB/native waits вне dispatcher mutex. Production provisioning остаётся вне runtime, no force-reset/new UUID escape, main V8 не мигрировать.

Перед реализацией F3: exact allowed paths/API, trusted finalization authority, state transition/cut-point matrix, новая independent acceptance/freeze/red. Никаких F3 source/тестов до закрытия недостающего контракта. Native Windows/boot recovery/Word и real model gates сохраняются; новых продуктовых функций из старых спецификаций не добавлять.
