# D03-07 — отмена и повтор в открытом фрагменте

30 октября 2026. Одна задача F05 после D03-06, прямое продолжение на Sol 6.1 High. Добавить Undo/Redo текста открытого span, включая переход через успешное автосохранение. Это локальная история редактирования, не пользовательская история версий документа. Manual save/закрытие/смена фрагмента заканчивают сессию. После восстановления D03-05 доступны исходный текст и восстановленная замена как один шаг, прежняя последовательность ввода не сохраняется.

## Модель

Чистый ES module history.js без DOM/I/O/таймеров экспортирует HISTORY_LIMIT=64, HISTORY_TEXT_BUDGET=2000000 и createHistory(initial). Snapshot — ровно text:string, start/end:integer 0<=start<=end<=text.length (UTF16 offsets, без trim/Unicode преобразования). Возвращаемые значения отделены от внутреннего состояния, внешняя мутация не меняет историю. current(), canUndo(), canRedo(), record(next,{before,inputType,time}), capture(snapshot), undo(), redo(). Пустая граница undo/redo возвращает null. capture меняет только selection текущего snapshot с тем же текстом и разрывает группу. record с тем же текстом не добавляет шаг и не удаляет redo. Настоящий новый ввод после undo удаляет redo. Неверные snapshots/before отклоняются до мутаций.

Каждый paste/cut/replacement/composition — отдельный шаг. Последовательные insertText/deleteContentBackward/deleteContentForward одного типа объединять в течение 750 ms, только при явном before, совпавшем с предыдущим post-caret, collapsed before/after и без смены направления времени. Выделение/перемещение caret, другой тип, пауза больше 750 ms, undo/redo/capture разрывают группу. Первый шаг не затирает baseline. record обновляет selection исходной точки для корректного undo. Хранить до 64 snapshots и 2000000 суммарных UTF16 units, удаляя старые целые состояния; текущий текст не обрезать. Если единственный текущий snapshot сам больше бюджета — сохраняется целиком, undo недоступен. В реальном UI действует прежний textarea max 200000 units.

## Интерфейс и сохранение

Две отдельные доступные кнопки «Отменить изменение»/«Повторить изменение», подсказки сочетаний. Прежняя «Отменить правку» остаётся discard всего draft. Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Ctrl/Cmd+Y только в textarea, без Alt; перехватывать native history даже на пустой границе, чтобы не смешать два стека. Другие поля не перехватывать. Невероятный/неизвестный chord не трогать. Кнопки/горячие клавиши не меняют текст при busy/pending/IME composition. Историю одного фрагмента не переносить в другой.

beforeinput фиксирует предыдущий текст/selection; input записывает snapshot и использует прежний путь checkpoint/autosave. Compositionstart удерживает baseline, промежуточные input не добавляют шаги/копии и не запускают POST; compositionend записывает одну итоговую замену, последующий дублирующий input не добавляет шаг. Пока composition активна, save/auto-save/переключение не выполняются. Физическую IME не выдавать за проверенную без реальной проверки.

Undo/Redo меняют textarea/selection и тот же draft.replacement, возвращают focus, затем сохраняют страховочную копию и заводят прежний таймер. Самостоятельно не вызывают POST text-edit. После auto-save стек остаётся прежним, а initialInput/expected text/revision/anchor — подтверждённые D03-06: undo к старому тексту становится обычной dirty-правкой на **новой** базе. Последующий save проходит прежний CAS, ошибки/чужие изменения не обходятся. Pending payload/ключ неподтверждённой операции не меняются через историю. Паузы при конфликте документа сохраняются. Unchanged redo снова делает draft clean, save не отправляется. Никаких новых backend/БД/browser storage/dependencies.
