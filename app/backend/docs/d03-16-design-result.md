# D03-16 — результат проектного цикла

31 октября 2026, Astra 6 High, исходный код на b44e03d. Созданы [проект сохранения/recovery](d03-16-design.md) и [ограниченный контракт реализации D03-16A](d03-16a-contract.md); обновлена очередь. Продуктовые границы не менялись. Реализация persistence, миграции и endpoints не выполнялись; executable acceptance D03-16A ещё предстоит зафиксировать перед кодом.

Решение: отдельный versioned checkpoint-slot с exact working bytes/selection/base, постоянная CAS revision даже после очистки, явная арбитрация со старым single-span /draft, prepare/commit/finalize с прежним durable receipt ledger. RAM session epoch и отдельная command sequence защищают повтор команд/курсора; восстановление сохранённого digest не создаёт ложный clean или fake undo. Autosave — две минуты, вне checkpoint возможна потеря ещё не записанного RAM-хвоста. Полная undo history между restart не обещана.

Проверены текущие session/editor/storage/recovery/receipt/ORM/migration boundaries. Синтетическая проба подтвердила: changed EditorSession is_dirty=true, обычный конструктор из тех же working bytes даёт is_dirty=false/revision0; dedicated restore пока отсутствует. Поэтому первым выделен pure restore, а не интеграция через обычный constructor. Проба .runtime/d03-16-design-restore-probe.json; первоначальный запуск без src в sys.path не импортировал ara, после указания project src выполнен успешно. Секреты/пользовательские документы не использовались.

Небольшая абстрактная модель исследовала **2383 состояния / 73148 переходов** (глубина состояний до 7, checkpoint revision до 5, storage revision до 4, два operation IDs и два абстрактных содержимых). Assertions прошли: monotonic revisions, неизменность существующих receipts, отсутствие записи при старом replay, невозможность позднего commit после discard, конфликт после внешней новой revision даже при равных bytes, finalize только matching receipt/current. Получены все семь recovery classifications таблицы. Это проверка последовательной модели выбранных переходов, не доказательство реальных SQL locks/crash/HTTP/Unicode/ограничений памяти. Скрипт и JSON в ignored .runtime/d03-16-model.py / d03-16-design-model.json.

При review дополнительно уточнены: retry prepare/finalize распознаётся до запрета phase pending; tombstone устраняет ABA; legacy PUT fence сохраняет чужую RAM-копию; transport serialization после commit считается lost ACK; conflict имеет приоритет над dirty=false; live reconcile продолжает исходную command identity; close/410 не доказывает сохранение.

Обязательный `bash scripts/check.sh`: **1897 passed, 24 subtests passed**, 69 предупреждений, **171,93 секунды**, exit 0; Ruff/format также проходят. Лог .runtime/d03-16-design-full-check.log. Production source/tests не менялись, новые реализованные функции этим gate не заявляются. Baseline схемы/ревизии/счётчиков совпал, ara_test пуста, временных ara_check_* нет.

Следующие шесть реализационных циклов: A restore, B1 schema, B2 checkpoint/legacy CAS, C keyed save/reconcile, D runtime controller, E HTTP/handoff.
