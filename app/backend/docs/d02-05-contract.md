# D02-05 — рабочая сессия DOCX с отменой и повтором

29 октября 2026. Один ограниченный цикл после D02-04, часть F05/F10/F11 [текущего объёма](current-product-scope.md). Пользователь попросил продолжить разработку. Сессия связывает проверенные операции DOCX в основу редактора: актуальный файл и адреса, последовательные правки, отмена/повтор, признак несохранённых изменений. Это история действий открытого документа в памяти, а не отложенный интерфейс пользовательской истории версий.

## Границы и API

Новые файлы только в `src/ara/docx_package/session/**` и `tests/docx_session/**`. Существующие package/projection/editing/ranges, HTTP, БД, ML, зависимости и runner не менять. Стандартная библиотека. Сессия не читает/пишет файлы, не сохраняет данные при закрытии процесса, не создаёт фоновые потоки, не использует сеть/секреты/БД/логирование содержимого. Вызывающая сторона последовательно выполняет команды одной сессии; многопоточная синхронизация не входит в контракт.

Модуль `ara.docx_package.session` экспортирует:

```python
SessionLimits(max_history_states=100, max_history_bytes=134217728)
SessionSnapshot(revision, data, projection, is_dirty, undo_depth, redo_depth)
SessionError
DocxSession(data: bytes, *, limits: DocxLimits | None = None,
            projection_limits: ProjectionLimits | None = None,
            session_limits: SessionLimits | None = None)

session.snapshot() -> SessionSnapshot
session.apply(edits: tuple[RangeEdit, ...], *, expected_revision: int,
              range_limits: RangeLimits | None = None) -> SessionSnapshot
session.undo(*, expected_revision: int) -> SessionSnapshot
session.redo(*, expected_revision: int) -> SessionSnapshot
session.mark_saved(*, expected_revision: int) -> SessionSnapshot
```

SessionLimits и SessionSnapshot — frozen/slotted dataclasses. Поля data и projection исключены из repr. repr сессии также не раскрывает содержимое. Snapshot содержит bytes текущего DOCX, свежую авторитетную DocxProjection для этих bytes, неотрицательные целые revision/depths и bool is_dirty. У Snapshot ровно перечисленные поля; наружу не выдаются изменяемые списки истории. Новые классы не заменяют DTO D02-01…04.

## Открытие и изоляция состояния

Конструктор проверяет исходник через существующий project_docx и сохраняет точные bytes. Начальное состояние: revision=0, is_dirty=False, обе глубины=0. Повреждённый или превышающий заданные лимиты исходник отклоняется с существующими DocxError/ProjectionError. Для открытия защищённого документа или документа с revisions достаточно доступности чтения; запреты редактирования остаются в нижнем слое.

limits/projection_limits принимаются строго соответствующих типов или None; как существующие DTO, содержат настоящие положительные int без bool. Неверная форма даёт соответственно DocxError/ProjectionError с invalid_input. SessionLimits принимает только настоящие положительные int; неверная форма — SessionError invalid_input. Проверять также переданные объекты, изменённые/повреждённые обходом frozen. Конструктор сохраняет независимые копии настроек: последующая мутация переданных объектов не меняет открытую сессию. RangeLimits применяется только к текущему вызову apply, проверяется существующим экспортом.

Ранее возвращённые snapshots не меняются после команд. Изменение возвращённого snapshot или его вложенного DTO обходом frozen не должно повреждать текущую сессию, историю, следующие snapshots или другую сессию. Реализация может хранить внутри только bytes и заново строить проекцию либо безопасно отделять наружные объекты от внутреннего состояния. Private-атрибуты самой сессии не являются публичным API.

## Правки и ревизии

Каждая изменяющая команда сначала проверяет expected_revision: настоящий int >= 0, не bool; иначе invalid_input. Несовпадение с текущим revision даёт stale_revision до выполнения правки/перемещения истории/подтверждения сохранения. Это защищает от запоздавшей команды и ABA после undo, когда bytes снова совпали с прежними, но ревизия уже другая.

Для всех четырёх команд результат, включая возвращаемый snapshot, полностью подготавливается до фиксации изменений. Ошибка подготовки ответа также оставляет прежними bytes, revision, историю и сохранённую отметку.

apply вызывает существующий export_docx_ranges для текущих bytes с сохранёнными DocxLimits/ProjectionLimits и переданными RangeLimits. Все правила диапазонов, исходных адресов, конфликтов, оформления и безопасных ошибок наследуются без ослабления. После экспорта заново получить корректную проекцию результата. Пользовательские правки не являются автоматическим принятием замечаний AIRA или Word revisions.

Если результат побайтово совпал с текущим файлом, команда является no-op: revision, is_dirty, undo/redo и сохранённая отметка не меняются. Это относится к пустому набору и взаимно компенсирующимся заменам. При фактическом изменении старые текущие bytes добавляются в конец undo, redo очищается, новые bytes становятся текущими, revision увеличивается ровно на 1. Ошибка любого шага не меняет сессию, включая redo и сохранённую отметку. Возвращённый snapshot описывает уже новое состояние.

undo перемещает текущие bytes в redo и восстанавливает последнее undo-состояние побайтово. redo выполняет обратный переход. Каждый успешный переход увеличивает revision на 1; номер ревизии не является индексом истории и не уменьшается. При пустой соответствующей истории — nothing_to_undo/nothing_to_redo без изменений. Отмена и повтор не пересчитывают прежний DOCX через текстовые операции и не теряют его оформление.

## Сохранённая отметка и память

is_dirty сравнивает текущие bytes с последним подтверждённым сохранённым содержимым; допустим SHA-256 точных bytes. Начальная отметка соответствует импортированному файлу. Поэтому undo до сохранённого содержимого автоматически убирает is_dirty, redo снова устанавливает его; после mark_saved новая точка также распознаётся при undo/redo.

mark_saved вызывается внешним слоем **только после успешной записи** bytes текущего snapshot. Сама функция ничего не пишет: она подтверждает текущее содержимое как сохранённое. revision и история не меняются, повтор идемпотентен. Запоздалое подтверждение с другой ревизией отклоняется stale_revision и не очищает is_dirty. При ошибке внешней записи mark_saved не вызывают. Это протокол для будущего хранилища, а не реализованное автосохранение или восстановление после перезапуска.

SessionLimits задаёт технические бюджеты удерживаемой истории, не продуктовый предел документа. max_history_states включает undo + текущее состояние + redo. max_history_bytes — сумму длин сжатых DOCX bytes этих состояний; повторяющиеся состояния считаются по одному разу на позицию истории. Это не обещание ограничения всей RAM, временной проекции или объектов, удерживаемых вызывающим кодом.

При открытии или новом фактическом apply текущий файл сам должен помещаться в max_history_bytes, иначе session_limit_exceeded без изменения состояния. При успешной новой правке redo удаляется; затем из начала undo удаляются самые старые состояния, пока оба бюджета не выполнены. Текущий файл никогда не удаляется. max_history_states=1 допустим, тогда отмена недоступна. Удаление старых состояний не изменяет сохранённую отметку; не нужно удерживать полный сохранённый файл вне бюджета ради is_dirty. Undo/redo перемещают существующие состояния без дополнительного расхода бюджета. No-op и ошибки историю не очищают и не сокращают.

## Ошибки и приёмка

SessionError.code: invalid_input, stale_revision, nothing_to_undo, nothing_to_redo, session_limit_exceeded. У каждого code постоянный безопасный непустой message; str == message, без текста документа, путей или сырой цепочки parser exceptions. Ошибки D02-01…04 сохраняют исходные классы и codes.

Независимая приёмка родителя фиксируется красной до запуска: `tests/acceptance/test_docx_session.py` и `test_docx_session_boundaries.py`. Исполнитель меняет только новый модуль и собственные тесты. Полный `bash scripts/check.sh` обязателен. Проверки должны покрыть последовательные правки по новым адресам, точный undo/redo, ветвление и сохранение redo при no-op/ошибке; ревизии/ABA/запоздалое сохранение; обе точки сохранения, лимиты и вытеснение, независимость snapshots/настроек/сессий, наследование защиты/ограничений и отсутствие I/O.

Синтетический rich-source.docx пройти через session apply → undo → redo → mark_saved. Сверить bytes со штатным D02-04 экспортом и с исходником после undo. Для изменённого файла проверить нетронутые части/оформление и визуальное отображение bundled LibreOffice. Если экспорт побайтово совпал с ранее просмотренным контрольным файлом D02-04, существующий рендер допустим как доказательство при точном подтверждении hash и повторном просмотре страницы. Microsoft Word не считается автоматически проверенным. Не читать архив пользователя, output/ или .artifact-build/. После одного цикла остановиться.
