# D03-02 — структурный просмотр содержимого DOCX

30 октября 2026. Одна задача после D03-01, часть F05/F11/F12 текущего объёма. Добавить чтение содержимого выбранного DOCX в локальном интерфейсе: абзацы, текст, таблицы и явные обозначения непоказанных элементов. Это упрощённое представление основного тела, а не рендер Word и не редактор. Прямая разработка в текущем чате, без запуска Ralph и изменения его журналов/статусов.

## API и представление

GET `/docx-documents/{document_id}/view` только с явным DocumentRuntime. Неправильный UUID и любые query-параметры — прежний безопасный 422 до доступа к хранилищу. Использовать неизменный get_docx и project_docx с default limits; синхронный handler работает в threadpool. Чужой/отсутствующий документ/проект — прежний 404, corruption — 500, недоступность БД — 503. Не выполнять DML, не закрывать caller engine и не читать секреты. Новые модули импортируются без I/O; модели Pydantic deferred.

Ответ 200 содержит ровно: document_id, title, storage_revision, current_sha256, current_size_bytes, created_at, updated_at, body_anchor, coverage_scope, has_unprojected_content, blocks, notices. Metadata относится к одному полученному snapshot текущего DOCX. **storage_revision — десятичная строка**, чтобы будущий JS-клиент мог хранить точную BIGINT-ревизию. Остальные старые HTTP-контракты не менять. Даты — ISO с часовым поясом; coverage_scope равен `main-body-structural-v1`.

`blocks` и `notices` передают все поля существующих доменных records проекции (Paragraph/Table/Row/Cell/OpaqueBlock/Span/Hyperlink/SourceAnchor/Notice) без интерпретации стилей или ссылок; tuple превращаются в JSON arrays, kind остаётся discriminator. Сохранить source_sha256, part_name, element-only path и Unicode start/end, текст/spans, properties_anchor, style/numbering IDs, grid_span/vertical_merge и причины opaque. Не включать DocxSource, исходные/текущие bytes, original_sha256, ZIP entries/relationships inventory, owner/project, source_url или локальные пути. Точность связей с исходником нужна для следующего этапа редактирования; не добавлять editable-флаг без проверки существующим экспортом.

Технические пределы просмотра: максимум **5000 доменных records**, считая каждый dataclass проекции, включая anchors/hyperlinks, и **1000000 Unicode-символов суммарно во всех строковых полях** передаваемой проекции. Metadata отдельно ограничено существующим сервисом. При обходе проверять бюджеты до продолжения построения ответа. После сериализации максимум **8 MiB UTF-8 JSON**. При превышении целиком отказать 413 `view_limit_exceeded`, message `DOCX view exceeds a technical limit`, retryable=false, без частичных blocks. Это предел текущего средства просмотра, не запрет импорта/скачивания и не продуктовый предел размера документа. Ошибки построения/проекции/сериализации нормализовать в прежний безопасный storage_error 500; DocumentError сохранить.

Полный OpenAPI response-model с рекурсивными структурами, anchor schema, строковой ревизией и ошибками 404/413/422/500/503. Cache-Control no-store на 200. Существующие wrappers OpenAPI сохраняются.

## Интерфейс

В существующий экран добавить раздел «Содержимое документа» с пометкой «Упрощённый просмотр · без редактирования». После выбора/импорта получить свежие metadata и view. Сведения и скачивание остаются доступны при отказе именно просмотра. Перед выбором другого документа очистить прежнее содержимое; ошибка не оставляет чужой текст под новым названием. Успешный импорт остаётся подтверждённым при ошибке просмотра/обновления списка.

Абзацы показывать с сохранением пробелов/переносов, таблицы — HTML-таблицами с рекурсивными блоками ячеек и горизонтальной прокруткой внутри контейнера. Не притворяться, что восстановлена вёрстка Word, шрифты, нумерация или объединения ячеек. Для списков/объединённых ячеек достаточно нейтральных подписей, без выдуманных номеров. Непоказанные блоки/inline opaque и has_unprojected_content обозначать явно: они остаются в исходном DOCX. Гиперссылки не превращать в активные внешние ссылки, стили/HTML/содержимое документа не выполнять. Все строки через textContent/DOM API, без innerHTML/eval. По ошибке просмотра показать понятное сообщение и оставить возможность скачать исходный текущий файл. Полное содержимое не хранить в browser storage.

Предыдущие загрузка/повтор/скачивание/пагинация и глобальная блокировка операций сохраняются. Адаптивность без горизонтального переполнения всей страницы. Записи, редактирование, undo/redo UI, автосохранение, анализ, шаблон AIRA и desktop-упаковка вне задачи.

## Разрешённые пути и приёмка

Реализация: `src/ara/docx_documents/view.py`, `view_schemas.py`, импорт/установка в app.py, три существующих workspace static-файла. Собственные тесты при необходимости `tests/docx_documents/test_http_view.py`. Подготовка: этот контракт, независимый `tests/acceptance/test_docx_view.py`, одно добавление нового адреса в исторический строгий список test_http_boundaries. После фиксации приёмку/критерии не менять ради успеха. Старые source/DTO/storage/проекции/редактирование/API, schema БД, зависимости, runner/tasks/progress неизменны. Архив пользователя, output/ и .artifact-build/ не читать.

Проверки: точная rich/synthetic проекция и XML-адреса, Unicode, вложенные таблицы/opaque, отсутствие DML, изоляция, ошибки, точная MAX-ревизия, бюджеты и неизменность скачиваемых bytes после просмотра. Полный bash scripts/check.sh. В браузере — чтение реального synthetic DOCX, таблицы/подписи, literal HTML в тексте, смена документа, отказ на объёмном файле с доступным скачиванием и отсутствие старого текста. Screenshot и отчёт; QA только в собственных disposable DB. После одной задачи остановиться.
