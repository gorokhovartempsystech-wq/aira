## Следующая граница: C1 design на Astra6 High

SQL lifecycle не является работающим desktop worker. Следующий архитектурный pass должен определить exact supervisor/IPC/lifetime protocol **до** implementation:

1. Windows job/process handles и macOS owned process group/lifetime primitive; parent-death/control-pipe EOF, безопасные terminate/grace≤2s/kill, защита от PID reuse и подтверждение выхода прежнего child до нового. Проверка macOS не доказывает Windows readiness.
2. Closed length-prefixed bounded IPC, доверенные executable/pack paths, environment allowlist без DB credentials/secrets, отдельные bounds stdout/stderr и no content logging. Synthetic child до настоящей модели; current team engine partial/pairwise требует отдельной версии C2 adapter.
3. Monotonic budget от claim DB time/deadline, heartbeat≤5s параллельно CPU-heavy validation/child supervision, preload/cold-start policy и resource bounds. Five-minute SQL decision не обещает мгновенный OS syscall/fsync.
4. **Local irreversible Stop latch при DB unavailable и in-flight publication.** Нынешний complete_attempt сам валидирует reply и выполняет commit, не принимает local latch. SQL cancel race проверен только когда durable fence доступен. C1 нельзя просто вызвать complete после разовой проверки RAM-флага и объявить Stop безопасным: latch может измениться во время validation/commit. Нужен явный publication gate/координационный протокол с linearization и reconciliation unknown commit, возможно новый отдельный guarded publication API. Старые successful results/контракт не переписывать молча. Это открытая интеграционная граница будущего process layer, не доказанный end-to-end Stop при отказе БД.
