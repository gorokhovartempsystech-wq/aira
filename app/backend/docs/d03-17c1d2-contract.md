## API и ownership

- Private `OwnedChild` в `_ownership`: конструируется только из retained Popen после успешного spawn; сам создаёт отдельный kqueue только для NOTE_EXIT child. `_poll(now_ns,stop=False,force=False)` — nonblocking advance; readonly свойства `exited`, `exit_code`, `fault`, `lost`. `close()` закрывает kqueue только после запрета сигналов; никаких automatic destructors/reaper. В тестах native functions подменяются независимо. Не принимать PID из client DTO/файла. Object не copy/pickle, repr без PID/argv.
- NOTE_EXIT exact ident/filter/no EV_ERROR закрывает signals до wait. Stop — один TERM, grace2s от первого stop; force/clock/kqueue fault — один final KILL. После последнего сигнала, любой signal error или observed exit — только waitpid(exact,WNOHANG). Return0 pending, real terminal сохраняет returncode, ECHILD/неожиданный статус — lost, без дальнейших сигналов. Никаких Popen.poll/wait/send_signal для M. При signal error fault latch; не повторять signal другим API. Регистрация NOTE_EXIT после spawn может не удаться: GO запрещён, остаётся один owned final KILL и wait. Close не подтверждает cleanup.
- `_bootstrap.TokenReader(kind, eof_required=True)` с kind prepared/gate/armed; incremental `.feed(bytes)` и `.finish()`; `.ready` только exact8-byte token и при eof_required после EOF. Prefix/wrong/extra/invalid input fault; максимум8 retained bytes, errors sanitized runtime_unavailable, poisoned. Gate token даёт readiness до EOF, последующий byte/EOF запрещает дальнейшую работу M.

## Launch helper для D2 tests и будущего D3

`_launch.launch_fixture_guardian(slot:SlotLease,binding:WireBinding,*,deadline_ns:int,lease_ns:int,mode='success')->FixtureGuardian`. Явный процессный запуск на Darwin; validates exact scalar/binding/closed mode до I/O. D/L signed63, `0<L<=D`; фактическую живость и интервалы проверяет G своим clock. Modes — closed synthetic enum success/wait/ignore_term/result_hang/nonzero/tail/error/stderr_flood/early_exit/prepared_missing/prepared_extra. Ни одного user-defined path/argv/env/code/reply. Это **fixture factory**, приложение к ней не подключается как к реальной модели.

FixtureGuardian — process-local issued object, repr без paths/FD. Содержит retained `.process` (G — прямой child S), `.control_fd` writer, `.request_fd` writer, `.events_fd` reader, `.status_fd` reader, `.armed_fd` reader. Эти handles принадлежат caller; `.close()` закрывает оставшиеся pipe references ровно один раз и не ждёт/не убивает G. Для EOF после request caller использует `.close_request()`, для Stop EOF — `.close_control()`. Caller ждёт G и не закрывает raw fd самостоятельно. Все S endpoints nonblocking; slot.borrowed FD не закрывается helper. Только allowlisted opposite endpoints+slot передаются G, runtime.owner не наследуется. Никаких bytes в diagnostics.

G/M entries запускаются absolute current interpreter `-I -B`, fixed trusted entry, cwd package root, env создан с нуля `{LC_ALL:'C',LANG:'C'}`. Source root для import вычисляется из fixed entry __file__, не из cwd/document/env. CLI только canonical UUID/D/L, enum fixture mode и FD integers. G stdio DEVNULL; M stdin=request/stdout=events/stderr=private G pipe. Raw request/spec/reply/paths документов/DB settings в argv/env отсутствуют. Не применять preexec_fn/shell.

`_guardian.run(...)` исполняется **только в G** с inherited channels, binding/D/L/mode. SIGCHLD=SIG_DFL до spawn; initial clock+permit seq0 с exact D/L до M. Continuity check перед buffered controls, D fixed, L<=D и <=now+15s, D initial<=now+300s; old L equality прекращает, поздний permit не оживляет. EOF/Stop/malformed control — stop. Control seq/caps из C1C, private bootstrap по C1D. Не более одного M и одного G loop, poll<=100ms. Clock fault final KILL, не новый grace.

M minimal gate watcher thread запускается до prepared. Ни adapter import, ни request read до GO. Initial L/D ограничивают ожидание gate; после GO только G обновляет lease. M читает один valid run+EOF, binding/spec digest из C1C; затем импортирует synthetic adapter. Gate EOF/extra bytes -> safe immediate exit; это дополнительная защита, не гарантия при GIL/native hang.

Fixture reply exact `b'fixture-response'`, явно не реальный B1 ML reply. Success ready/loading/analyzing/result→exit0; error code adapter_error и nonzero; tail/nonzero/result_hang deliberately invalid success path. ignore_term/result_hang используют bounded5s native/GIL fixture, чтобы проверить независимость G; никакого бесконечного orphan. wait≤5s natural fallback, malformed prepared≤initial lease. Fixture не порождает subprocess/daemon/сеть.

G drains/discards stderr ≤64KiB lifetime; +1 -> fault/teardown, включая tail после M exit. Перед closed обязательно stderr EOF/ограниченный drain после exit (2s), чтобы flood не превратился в clean. Exact wait -> закрыть G slot, closed с actual code/cleanupTrue. fault приоритетнее stopped, затем clean только0. При lost ownership/no M — status EOF без придуманного code и nonzero G exit. Status send bounded2s (one nonblocking try при clock fault), EPIPE не задерживает cleanup. G exits0 после нормальной отправки closed любого kind; failure status delivery ненулевой. Parent candidate gate — D3, SQL publication — C1B/F.

## Frozen acceptance

До source compile/collect/review новой acceptance, отдельный freeze/red. Pure token split/EOF/extra/poison; fake syscall sequences NOTE_EXIT/TERM/KILL/EPERM/ESRCH/ECHILD/wait0/invalid event, никаких сигналов после wait и никакого Popen poll. Native harness со своими private pipes/temporary slot: complete fixture, Stop EOF/explicit frame, initial expired, bad/missing permit, missing/extra prepared, ignored TERM/native hang, result+hang, stderr flood. Проверить status actual exit и отсутствие лишнего spawn, owner/slot hold, отсутствие content/env в diagnostics; subprocesses bounded и всегда reaped. Ожидание readiness через pipe/select, без sleep-угадывания как доказательства. Harness знает, что fixture не B1 analysis.

Targeted/own/native и `bash scripts/check.sh`, read-only DB comparison, result/local commit. Native failure/skip не объявлять pass. Далее D3 на Sol6.1 High по отдельному contract/freeze. При реальном архитектурном противоречии не ослаблять frozen tests.
