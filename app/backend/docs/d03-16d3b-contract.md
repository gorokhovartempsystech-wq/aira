# D03-16D3B — dirty save, recovery reconcile и exact SavedTarget

31 октября 2026, после 971f496, Sol 6.1 High. F05/F06/F11/F12, d03-16d-design.md §§5–8. Подключить готовые C1/C2/C3, сохранив history и full request identity при unknown outcome. Без HTTP/ML/timers/миграций и изменений B/C/native source.

## Public behaviour

Registry.save теперь поддерживает dirty редактор: prepare→commit→finalize, затем local mark_saved на заранее подготовленном fork, base=receipt/CP=final, sequence+1/latest receipt/active=None одной publication. Core revision/position/history/selection не меняются из-за save. Равный hash при чужой storage revision/CP не даёт права save. Clean save прежний selection checkpoint, без current revision/SQL receipt.

Registry.reconcile существующего live attempt продолжает тот же command ID/исходные counters. Когда local active нет, а actor восстановлен из pending, reconcile — новое local command с новым ID/current counters и старым durable SaveHandle. Historical origin не заменяет новый registry/session/core revision0. Новый local SaveTarget связывает реальные восстановленные bytes/selection/counters; precomputed mark_saved ожидает local revision, не historical revision. Не запускать save из snapshot/open автоматически.

Новый `registry.saved_target(*,document_id,session_id,command_id,expected_command_sequence,expected_session_revision)->SavedTarget`. Здесь counters РЕЗУЛЬТАТА accepted save/reconcile, не исходного запроса. Доступ только пока это latest successful save command, ID/counters exact и active нет; иначе409 stale_command/editor_operation_pending. Scope before existence/replay/error. Immutable SavedTarget frozen/slotted: registry/document/session IDs, command_id, command_sequence, session_revision, storage_revision, sha256, data bytes repr=False. Strict bounds/types/actual digest. Clean target берётся из точного checked base bytes, dirty/recovered — из замороженного candidate с подтверждённой receipt identity. Не новый GET latest и не arbitrary DOCX setter. Более новый external head не подменяет target. Новый accepted command/checkpoint очищает saved target, старый binary read становится stale.

## Attempt и proof

Private immutable SaveAttempt имеет прежнюю control identity/hash/SaveTarget, exact current data/working metadata/base/CP, prepare request_id, operation_id, finalize request_id, полный ожидаемый SaveHandle и precomputed marked EditorSession. Handle вычислить ДО первого C1 dispatch каноническим codec/pending_fingerprint/SaveHandle; actual C1 response обязан совпасть целиком. marked fork не публиковать до подтверждения полного результата. Packages в нём общие immutable references и учтены в live/candidate union; не удерживать projection/StoredDocx.

Свежая попытка сначала C1 с теми же bytes/metadata/IDs, затем C2/C3. После любой ошибки dispatch active сохраняется и новые edits/capture/undo/save блокируются. Retry/reconcile сначала C2(expected_handle): receipt replay не зависит от текущего checkpoint. Только при checkpoint_conflict без подтверждения в fresh attempt допустим один повтор исходного C1, затем C2/C3. Не обновлять expected CP/IDs и не трактовать storage/idempotency/corruption error как отсутствие prepare. Recovered pending не делает C1 вообще: он уже был durable; исчезнувший slot не воскрешать.

C2/C3 calls владеют своими transactions; никакого outer SQL lock. Full matching receipt/finalize proof и current_matches_receipt обязательны для RAM publication. Receipt может подтвердить старый save при новом head/slot, но тогда conflict/active и исходная копия сохраняются; не mark_saved как актуальную работу. Exception/DTO failure после SQL commit не откатывает current вручную; повторить ту же identity. Stage descriptor save_pending содержит operation_id, optional save_state из read-only proof (ready/conflict/exhausted/committed/committed_outdated/superseded), без текста/bytes. Snapshot активного save не пишет/не finalize-ит.

Read-only active-save proof собирается согласованно под одной project/document transaction. Matching receipt проверяется до full checkpoint/legacy; при receipt может читаться только CP fence metadata для view. Receipt replay не зависит от другого draft payload. Для отсутствующей receipt pending проверяется whole record/handle/CP, legacy mode учитывается. Не склеивать get_save_status+get_checkpoint из разных transactions. Stored corrupt receipt не ремонтируется. Current/CP conflict отражается отдельно от save_state; false dirty/saved ACK нет.

До first dispatch guard sequence<MAX и fresh prepare резервирует CP finalize шаг/base storage increment по C1. Existing receipt/completed proof повторяется и на final counters, без нового increment. Native MAX допустим для save (не меняет core revision). Recovered exhausted pending read/release доступны; fresh commit не обходить guard C2. Target bind проверяется перед dispatch и публикацией (epoch/sequence/native counters/hash/size/selection). SavedTarget data/identity целиком готовятся до final RAM assignment; failure оставляет active.

## Совместимость и тестовая миграция

В D3A `save` временно отвергал dirty с editor_save_requires_commit; его контракт прямо назначил расширение того же метода D3B. Это расходится с одной frozen D3A assertion, которая требовала временный отказ. В рамках уже разрешённого пользователем продолжения D3B разрешено ТОЛЬКО в test_clean_save_only_checkpoints_and_dirty_save_is_not_claimed_ready заменить dirty-refusal tail более сильными проверками: actual save clean=true, current revision+1/exact changed bytes, receipt1, history/selection прежние. Все предшествующие clean-save assertions остаются. Никакие иные old tests не менять. Эта узкая миграция фиксируется до production code вместе с новым freeze; это не ослабление требований ради green.

Native latest replay/ordering/D1 recovery/D3A checkpoint/close прежние. Private published state получает saved target, native command/checkpoint publication его очищает. DTO constructors сохраняют defaults, CommandReceipt semantic action save допускает recovered reconcile (fingerprint его исходного endpoint reconcile); repeated reconcile без active возвращает matching latest proof. Изменение operation_id или исходного request body запрещено.
