## Изменённое поведение

`POST /docx-documents/{document_id}/import?title=...` принимает raw DOCX и сохраняет точный оригинал и рабочую копию. Клиентский ID позволяет безопасно повторить запрос: совпадающий исходник и название возвращают последнюю рабочую версию без сброса правок. Несовпадение даёт прежний конфликт импорта; чужие документы остаются недоступными.

`PUT /docx-documents/{document_id}/content?expected_storage_revision=...` сохраняет текущий файл только с актуальной ревизией. При двух конкурирующих сохранениях с одной ревизией проходит одно; другое получает конфликт. Оригинал, название и дата создания сохраняются. Оба метода возвращают семь полей метаданных из snapshot завершившейся операции, без bytes и повторного чтения хранилища. Ответ имеет `Cache-Control: no-store`.

Загрузка принимает бинарный DOCX или application/octet-stream без multipart и временных файлов. Накопление тела ограничено существующим пределом пакета **32 MiB**. Большая заявленная длина отклоняется до чтения; поток без длины останавливается при первом превышении. Проверяются повторные заголовки, MIME, Content-Encoding, ASCII-числа, совпадение фактической длины с заявленной и обрыв передачи. ZIP/XML-проверка, работа с БД и подготовка метаданных выполняются в threadpool после ограниченного чтения. Ошибки входящего пакета/проекции получают безопасный 422, ошибки хранения сохраняют прежнюю классификацию. Новые глобальные обработчики не добавлялись.

Реализация — новый `src/ara/docx_documents/writes.py` и две строки подключения в `app.py`. Хранилище D02-06, DTO, чтение D02-07, схема БД, зависимости и ML-контракты не изменены. Модули импортируются без I/O. OpenAPI описывает оба бинарных MIME, обязательные параметры и ошибки; граница BIGINT передаётся точным целым.

## Приёмка

Подготовительный коммит **`46d1b20`** содержит контракт и **47 новых случаев**. До реализации заранее обновлены два исторических ожидания: точный список адресов дополнен `/import`, а `/content` в проверке D02-07 ожидает GET+PUT. Остальные утверждения и проверки старого чтения сохранены. Это зафиксировано до красного прогона, без последующего ослабления приёмки.

Окончательный красный целевой прогон: **49 failed**, 5 предупреждений, 7,39 секунды — 47 новых случаев и два исторических ожидания отсутствующих маршрута/метода. После реализации те же новые тесты вместе со всей HTTP-приёмкой D02-07 и границами старого API: **75 passed**, 5 предупреждений, 11,56 секунды. Логи `.runtime/d02-08-frozen-red.log`, `.runtime/d02-08-targeted.log`.

Финальный **`bash scripts/check.sh`: 1301 passed, 24 subtests**, 59 предупреждений, **108,27 секунды**, exit 0. Предупреждения не подавлялись. Лог `.runtime/d02-08-full-check.log`. Отдельное сравнение подтвердило неизменность подготовленного контракта и приёмки, а также старых файлов хранилища, чтения, моделей и runner.

Синтетический rich-source.docx прошёл цепочку HTTP-импорт → правка `DocxSession` → HTTP-save → новый app/engine → скачивание. Оригинал сохранился побайтово; скачанные bytes совпали с текущим файлом сессии, хеш и ревизия соответствовали ему. Повтор импорта сохранил правки, устаревший save отклонён. Проверены чужие проекты/ID, некорректные пакеты, классы ошибок, последняя допустимая ревизия bigint и отсутствие event loop у storage-вызова.

Прямые ASGI-тесты проверили ранний отказ без чтения тела, остановку потока на превышении, дубли заголовков и обрыв соединения. Дополнительный probe без БД передал rich-source.docx тремя chunks без Content-Length в POST и PUT: каждый callback получил точные **48126 bytes** и выполнялся вне event loop. Storage в этом probe явно замокан; проверка реальной БД выполнена независимой приёмкой. Скрипт `.runtime/d02-08-chunked-probe.py`, отчёт `.runtime/d02-08-chunked-qa.json`.

Новый визуальный рендер не выполнялся: этот транспорт передаёт исходные/отредактированные bytes без преобразования. Совместимость с Word и качество произвольных правок этим не подтверждены. Пользовательский архив не использовался.
