# D01-02 — HTTP API локального черновика

28 октября 2026. Часть F05/F12 из [текущего объёма продукта](current-product-scope.md). Предоставить будущему редактору HTTP-доступ к существующему сервису D01-01. Этот цикл не закрывает редактор или автосохранение целиком.

## Границы

Добавить только GET и PUT `/documents/{document_id}/draft` в приложение с явно переданным локальным DocumentRuntime. Использовать `ara.drafts.read_draft` и `save_draft`, сохранив их [контракт](d01-01-contract.md) и реализацию. Не дублировать SQL, транзакции и контроль ревизии в маршрутах.

Без runtime приложение по-прежнему предоставляет только health из продуктовых маршрутов. С runtime сохраняются прежние маршруты, local-dev middleware, ограничения окружения, безопасные ошибки и отсутствие настоящей авторизации. Это транспорт для локальной разработки, не готовая безопасность desktop-приложения. Не добавлять аккаунты, лицензию, CORS, внешнюю публикацию, UI, таймер, создание пустого документа, новые версии, анализ, Merge или интеграции.

Модели БД, миграции, старые API/ML-контракты и зависимости не менять. Существующие документы и версии не преобразовывать. Сервис черновика по-прежнему требует существующий документ и его базовую версию.

## GET

`GET /documents/{document_id}/draft`:

- доступный документ с черновиком → 200 и JSON-снимок из пяти полей ниже;
- доступный документ без черновика → 200 и JSON `null`, без записей в БД;
- неизвестный или недоступный документ → общий безопасный 404/not_found;
- неверная UUID-форма пути → безопасный 422/validation_error до доступа к БД.

Читать текущий черновик, не синтезировать его из сохранённой версии и не возвращать виртуальную ревизию 0. Ответ не содержит history, blocks, авторизационные данные или результат анализа.

## PUT

`PUT /documents/{document_id}/draft`, тело JSON — объект ровно с тремя обязательными полями:

```json
{
  "expected_revision": 0,
  "base_version_id": "f0ec805a-dcad-4f51-9643-7621ab373411",
  "content_markdown": "Незавершённый текст\r\n"
}
```

expected_revision — JSON integer, не bool, float или строка, от 0 до 9223372036854775806 включительно. base_version_id — строка с корректным UUID; на границе HTTP она преобразуется в UUID-объект для сервиса. Допустимые UUID-формы соответствуют Python UUID, в ответах используется каноническая строка. Не принимать число, null, массив или объект вместо UUID.

content_markdown — строка без NUL и Unicode-суррогатов. Пустой текст, пробелы, CRLF, Unicode, незакрытая разметка и текст длиннее миллиона символов сохраняются дословно. Не переносить лимит старого CreateDocument, не нормализовать, не обрезать и не преобразовывать чужие типы в строки.

Неизвестные поля (включая document_id, user_id, project_id, revision и updated_at), отсутствующее тело/поле, null/массив вместо объекта, неверные типы, некорректный JSON/UTF-8 → безопасный 422 до доступа к БД. Ошибка не возвращает исходный input или детали валидатора. Существующий middleware генерирует свой request_id; присланный X-Request-ID не используется как ID ответа.

Успешный первый и последующий PUT → 200 с зафиксированным в БД снимком. Сервис получает document_id только из пути, владельца/проект только из server-owned runtime. Заголовки и query-параметры user_id/project_id не переключают доступ. Запрос с валидной формой проверяет доступ до базы и конфликта ревизии, согласно D01-01.

Сохранение передаёт полный текст. expected_revision=0 создаёт первый черновик; актуальная ревизия обновляет его; устаревшая возвращает 409/draft_conflict. Повтор со старой ревизией, даже с тем же текстом, не является успешным replay. Две конкурентные HTTP-записи от одной ревизии дают один 200 и один 409. Текст и ревизия ответа должны совпадать с последующим GET.

База должна принадлежать этому документу, но не обязана быть его последней версией. Разрешена явная смена базы при актуальной ревизии. Нельзя создать документ, версию или задание анализа через PUT черновика.

## JSON-снимок и ошибки

Успешный снимок содержит ровно пять полей: document_id и base_version_id — канонические UUID-строки; revision — положительный JSON integer; content_markdown — точная строка; updated_at — ISO 8601 datetime с timezone, полученный от сервиса. Ответ приходит только после успешного commit.

Все ошибки используют существующий JSON-envelope ровно из code/message/retryable/request_id и заголовок `X-ARA-Auth-Mode: local-dev`. request_id — новый серверный UUID на каждый запрос. Не выдавать SQL, DSN, stack trace, input, чужие идентификаторы или содержимое черновика.

| Случай | HTTP / code / retryable |
|---|---|
| Неверный запрос | 422 / validation_error / false |
| Неизвестный/чужой документ или база | 404 / not_found / false |
| Конфликт ревизии | 409 / draft_conflict / false |
| OperationalError хранения | 503 / storage_unavailable / true |
| Другой сбой хранения, commit или повреждённая строка | 500 / storage_error / false |

Сообщения берутся из существующего безопасного обработчика и DocumentError. Ошибки чтения/записи/commit не превращаются в успешный ответ или частично сохранённый документ. Ошибки формы должны выявляться до подключения к хранилищу; валидные запросы используют проверки доступа D01-01.

## Подключение и независимая приёмка

OpenAPI описывает оба метода, обязательные поля/типы/границы входа, отсутствие лишних полей, снимок и nullable GET. Для новых методов явно описать реальные error-envelope: GET — 404/422/500/503, PUT — также 409. Не оставлять для них автоматическую схему 422 с detail, не соответствующую безопасному ответу. Имена классов схем не фиксируются. Не добавлять поле status или сохранять «сохранено» в БД: интерфейс сможет показывать подтверждение по успешному ответу с ревизией и временем. Существующие health/OpenAPI не открывают БД и не dispose engine. Импорты всех модулей `ara.drafts`, включая новые, остаются инертными; прежнюю проверку импорта не ослаблять. Учитывать отложенное построение Pydantic-схем и отсутствие необходимости импортировать HTTP-зависимости до установки маршрутов.

Parent до цикла расширяет точный набор путей в `tests/documents/test_http_boundaries.py` только новым draft-путём с GET/PUT. Новая независимая приёмка проверяет реальный HTTP через TestClient и PostgreSQL в собственных ara_check_*: null без записи, PUT/GET и новый engine, точный пустой/длинный текст, CAS/конкуренцию, область доступа, старую/новую базу, неизменность старых таблиц, безопасные ошибки и rollback. Отдельно — строгий malformed input без подключения к БД и инертный OpenAPI. Синтетические данные, без рабочего архива.

Разрешённые пути внутреннего цикла: `src/ara/drafts/api.py`, `src/ara/drafts/http_schemas.py`, `src/ara/app.py`, `tests/drafts/http/**`. В app.py — только подключение draft-маршрутов при явном runtime. Не изменять старые drafts storage/schemas/__init__, documents/runs/reviews/worker, модели, миграции, зависимости, независимую приёмку, контракт, инструкции, runner/prompt/задачи/журнал. Полный gate — `bash scripts/check.sh`. Остановиться после D01-02; статус пишет runner.
