# Разделы и ссылки на колонтитулы

`ara.docx_analysis.sections.read_section_catalog` строит отдельный immutable
`docx-sections/current-header-footer-definitions-v1` из исходных bytes и их SHA256.
Это каталог ссылок: он не выдаёт текст, признак complete или разрешение игнорировать
непрочитанные части документа. Его использование для анализа требует следующего
story reader с проверкой всех текущих веток основного содержимого.

Обычная граница раздела распознаётся по реальным родителям body/p/pPr/sectPr;
конечные свойства — последний body/sectPr. При отсутствии последних появляется
логическая конечная секция с anchor=None: отсутствующий XML узел не выдумывается.
Индекс секции нулевой, порядок исходный. Section хранит явные references и bindings;
каждая привязка содержит исходную definition_anchor и origin_section либо None для
пустого варианта. Предыдущие section/pPr свойства исключаются только после проверки
владельца, формы history marker и previousroot; source bytes не изменяются.

У header и footer по три независимых определения: default, first, even. Отсутствующее
определение наследуется из того же слота предыдущего раздела. Своя ссылка заменяет
этот слот, даже когда вариант пока отключён: first может понадобиться следующему
разделу. Отображаемые потенциальные варианты выбираются через titlePg в секции и
общий evenAndOddHeaders в единственной корректно связанной settings part. Нет ссылки
у первого раздела — пустой вариант, без подстановки другого вида колонтитула.

Stories перечисляет уникальные потенциальные части в порядке канонического имени.
Root anchor относится к реальному part/path(), но содержимое и правильность hdr/ftr
проверит следующий reader. Список не описывает страницы, не учитывает фактическую
длину секций или раскладку Word и не создаёт повторов на каждую страницу. Orphan parts
не становятся требованиями, однако этот каталог сам по себе ещё не доказывает
безопасность их исключения из полного анализа.

Ссылка разрешается только через relationship основного документа, с соответствующим
header/footer типом и MIME и внутренней целью. Внешние ссылки не загружаются. Settings
должна иметь единственную подходящую MIME part и main relationship; неоднозначность
не превращается в выключенный флаг. Ошибка контекста/ссылки/истории возвращает blocked
с пустыми sections/stories/histories. Лимиты/неверный input/hash — фиксированные ошибки.

SectionLimits ограничивает весь main+settings XML до semantic DOM: nodes/depth/chars,
namespaceURI, все sectPr/references/history markers, включая исключённые ветви.
Manifest считается потоково с ограничением размера. DTO не держат Element/DocxSource,
исходный текст, r:id, author/date; адреса/collections скрыты из repr. Импорт и вызов
pure API не обращаются к сети, окружению, файловой системе, БД или модели.

Сложные section revisions, секции внутри ячеек/неподдержанных wrappers и некоторые
другие history contexts остаются blocked. Это граница текущей реализации, не удаление
обязательного DOCX из продукта. Точные критерии и первичные источники:
[контракт](d03-17a2b4a1-contract.md), [результат](d03-17a2b4a1-result.md).
