# Лицензирование AIRA — технический проект

4 ноября 2026. Продуктовые границы — F03 в current-product-scope.md: срок в
серверной таблице от первой активации, одно устройство, онлайн-проверка при каждом
запуске (ответ Никиты3ноября). 4ноября возобновлена автономная разработка.

## Последовательные циклы

1. D04-01: pure правила срока/устройства, строгий протокол и привязка ответа к
   текущей попытке запуска/времени. Без HTTP/SQL/OS/disk side effects.
2. D04-02: отдельное серверное PostgreSQL-хранилище, атомарная активация/check,
   ограниченный HTTP API и ручная выдача через доверенного оператора.
3. D04-03: клиент HTTPS, определение устройства, сохранение идентичности активации,
   управление запуском/ошибками. Desktop wiring — в последующем цикле поставки.

Это три цикла из прежней оценки3–5, не новые функции. Каждый получает собственный
контракт/acceptance/red/full/result/локальный commit. Граница D04-02/03 уточняется
до freeze; библиотека сама по себе не означает защиты всего приложения.

## Данные и доверие

Сервер получает ключ при активации либо UUID лицензии при check, versioned digest
устройства и случайный256-bit nonce текущей попытки. Документы/результаты/имя
пользователя не отправляются. Ключ не сохраняется на клиенте и не логируется.
Сервер хранит HMAC-SHA256 ключа с явно переданным pepper, операционный pepper
только из ~/secrets.env. Тестовые случайные значения существуют только в памяти.

На диске клиента — публичный UUID лицензии и digest устройства, не разрешение
офлайн-запуска. Device-v1: domain-separated hash платформы и стабильного platform
UUID. Raw hardware UUID не отправляется и не сохраняется. Native readers и
стабильность ещё проверяются в D04-03. Это привязка штатного клиента, не аппаратная
аттестация и не защита от изменения его кода. Копия activation state на другой
машине не проходит check с заново вычисленным device digest.

Каждый запуск/retry генерирует новый nonce. Ответ принимается из текущего HTTPS
к заданному серверу с проверкой сертификата/имени узла. Редиректы, отключение TLS
verification и HTTP fallback запрещены. Nonce/operation/device и при check UUID
лицензии совпадают. Разрешение не загружается с диска и не сохраняется для нового
запуска. Для выбранного online-only режима отдельная подписанная офлайн-лицензия
не нужна: подлинность обеспечивает проверенный TLS, nonce связывает попытку.
Pure decoder не доказывает подлинность произвольных входных bytes.

Основания: [Python TLS](https://docs.python.org/3.12/library/ssl.html#ssl.create_default_context),
[HTTPX](https://www.python-httpx.org/advanced/ssl/),
[OWASP HTTPS](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html#https).
Транспорт/конечные тайм-ауты/admission проверяются отдельно от pure D04-01.

## Время, повторы и сохранность

duration_seconds — положительное целое без фиксированного тарифа; timestamps —
UTC epoch milliseconds. Первая активация под блокировкой строки фиксирует
device/начало/конец. Повтор тем же устройством сохраняет эти поля; другому отказ.
Check не активирует. now_ms>=expires_at_ms означает истечение. Частично заполненная
запись считается повреждённой, не новой. enabled=false запрещает следующий
запуск/активацию; мгновенный отзыв текущего сеанса не обещается. Продление, перенос,
аккаунты/платежи и админский веб-интерфейс не добавляются этим проектом.

Клиент рассчитывает остаток от серверного checked_at_ms на непрерывных часах,
включающих сон. Дедлайн отсчитывается от начала запроса: сетевой интервал списан
консервативно, ещё1ms снята за округление server clock. Ответ старше15s отвергается.
Это предел попытки, не длительность лицензии. В уже разрешённом запуске сеть
повторно не требуется; локальный дедлайн закрывает новые защищённые действия.
Каждый новый запуск опять требует сервер. Истечение/ошибка не удаляют документы;
сохранение уже введённого текста и выгрузка остаются доступны при будущем desktop
wiring. Это техническая защита сохранности F11/F12, не бесплатное продление доступа.

Потеря ответа после COMMIT разрешается повтором того же ключа/устройства; срок
остаётся первоначальным. Ответ новой попытки может иметь другой checked_at/nonce.
Бесконечная история nonce серверу не нужна; повтор не увеличивает entitlement.

## Поставка

БД лицензий отдельна от локальных документов/migrations; main V8 не мигрировать.
Импорт модулей/DTO не читает секреты/clock/файлы и не открывает сеть/БД. Серверный
домен/TLS/хостинг не считаются готовыми; ничего не публикуется. До клиентского и
desktop wiring прежнее development app не объявляется лицензированным.
