# Папка данных локальной установки

D05-04, 4 ноября 2026. `ara.desktop.data_home` не выполняет I/O при импорте.
`default_root()` явно возвращает стандартный путь, не создавая его: macOS —
Library/Application Support/AIRA текущего OS-пользователя, Windows — LocalAppData/AIRA
через Known Folder API. Переменные HOME/LOCALAPPDATA не определяют расположение.

`open_home(root: Path | None = None)` проверяет путь, создаёт только собственную
конечную папку и захватывает межпроцессное владение. Одновременно открыть эту
папку дважды нельзя. Существующие права не исправляются автоматически. Чужие
файлы, ссылки, неоднозначная структура или повреждённая identity требуют отдельного
восстановления; компонент не стирает их и не создаёт новую identity поверх данных.

Возвращаемый DataHome предоставляет:

- `identity()` — неизменяемые installation_id, user_id, project_id. Последние два
  детерминированно выводятся из installation_id; это локальная область документов,
  а не аккаунт в сети.
- `path(name)` — root, postgres, analysis, license или backups. Содержимое уже
  существующих дочерних папок этот компонент не читает и не изменяет.
- `view()` — phase, error_code, resources_pending без путей и native handles.
- `close()` — True только после подтверждённого освобождения своих ресурсов.
  Повторное закрытие закрытого объекта возвращает True. Незавершённое либо
  неподтверждённое закрытие возвращает False и не разрешает открыть второй экземпляр.

Объект нельзя создавать вручную, копировать, сериализовать или использовать после
fork в другом процессе. Открытые и неопределённо закрытые ресурсы удерживаются
реестром даже при потере ссылки вызывающим кодом. Закрытие сохраняет все данные.

В `identity.json` записывается только schema_version и UUID установки. Ключи
лицензии, пароли и device ID там отсутствуют. Первая публикация идёт через private
staging и атомарное переименование без замены final. После сбоя корректный staging
в доказанно пустой новой установке позволяет завершить публикацию с тем же UUID.
Опубликованная identity никогда не удаляется при rollback и не переписывается
при обычном запуске. Гарантия ограничена подтверждёнными файловыми операциями OS,
а не произвольной физической порчей диска.

Ошибки имеют закрытые коды: validation_error, invalid_handle, home_busy,
home_unavailable, home_recovery_required, unsupported_platform. Они не содержат
пути, содержимое файлов или исходные исключения OS. При recovery_required нельзя
автоматически удалять папку, lock file или identity; нужен отдельный сценарий
восстановления с сохранением имеющихся данных.

Порядок будущего desktop bootstrap: удерживать DataHome → запустить собственную
БД → открыть engines/supervisor → запустить HTTP. Завершение идёт в обратном
порядке; закрывать DataHome до подтверждённой остановки детей нельзя. Supervisor
использует свою блокировку внутри analysis, отличную от глобального владельца.
D05-04 сам не запускает PostgreSQL, модель или HTTP и не мигрирует рабочую БД.

Native macOS сценарии проверены на временных папках. Windows Known Folder,
создание private файлов, non-reparse admission и публикация проверены подстановками
native API; реальная Windows приёмка остаётся отдельным gate. Имеющийся общий
pytest fixture использует Unix PostgreSQL, поэтому перенос Windows smoke harness
нужен перед подтверждением native поведения. Реальная папка профиля не создавалась.
