# D01-01 — хранение локального черновика

28 октября 2026. Первый ограниченный цикл для текущего локального продукта, часть F05/F12 из [основного продуктового документа](current-product-scope.md). Сохранить и восстановить текущий черновик **существующего документа**. Это внутренняя основа будущего редактора; завершение цикла не означает готовность F05/F12 целиком.

## Границы

Использовать существующую PostgreSQL и DocumentRuntime. Черновик хранится отдельно от неизменяемых DocumentVersion. Только Python-сервис и миграция: нет HTTP, UI, таймера автосохранения, новых пустых документов, вкладок, записи черновика в сохранённую версию, анализа, скрытия замечаний, DOCX, лицензирования, Merge/preview/apply или истории черновиков. Старые контракты, миграции, модели и проверки сохраняются.

Markdown выбран внутренним текстовым представлением этого сервиса, совместимым с существующими документами. Это не выбор библиотеки редактора или окончательной desktop-архитектуры. Строка сохраняется дословно; пустая строка, пробелы, CRLF и незакрытые Markdown-конструкции допустимы. Не делить текст на блоки, не нормализовать его и не запускать анализ. Не переносить автоматически старую проверку непустоты или лимит миллиона символов на черновик: в этой задаче нет HTTP или ML. Приёмка проверяет также точное сохранение строки длиннее прежнего лимита версий.

## Публичный Python-контракт

Пакет `ara.drafts` экспортирует `DraftSnapshot`, `read_draft`, `save_draft`:

```python
read_draft(runtime: DocumentRuntime, *, document_id: UUID) -> DraftSnapshot | None
save_draft(
    runtime: DocumentRuntime,
    *,
    document_id: UUID,
    expected_revision: int,
    base_version_id: UUID,
    content_markdown: str,
) -> DraftSnapshot
```

`DraftSnapshot` — frozen Pydantic-модель с `model_dump`, без лишних полей. Ровно пять полей:

- document_id: UUID;
- base_version_id: UUID;
- revision: положительный int;
- content_markdown: точный str;
- updated_at: datetime с timezone, время PostgreSQL.

Возвращаемый объект отделён от сессии и состояния хранения. Caller владеет engine; сервис не dispose/close его и не хранит сессию между вызовами. Импорты не читают файлы, секреты, сеть или БД. Настройки и запуск приложения не меняются.

Аргументы UUID должны быть UUID-объектами, не строками. expected_revision — настоящий int, не bool/float/str, от 0 до 9223372036854775806 включительно (безопасный инкремент BIGINT). Текст — str без NUL и Unicode-суррогатов; не приводить чужие типы к строкам. Неверный аргумент → существующий `DocumentError(422, "validation_error", постоянное безопасное сообщение, False)` до доступа к БД.

## Чтение, база и область доступа

Для доступного документа без черновика read возвращает `None`, без INSERT или иного изменения. Для отсутствующего/чужого документа — обычный общий 404/not_found, совпадающий с `documents.storage._not_found()`. Сервис не создаёт документ, базовую версию или пустой черновик при чтении.

Каждый save передаёт **полный** content_markdown и явный base_version_id. Эта версия должна существовать и принадлежать данному документу; неизвестная или версия другого документа → тот же общий 404. Не требуется равенство базы с Document.current_version_id: появление новой сохранённой версии не запрещает сохранять незавершённый текст относительно прежней базы. Записать именно явно переданный base_version_id. При верной ожидаемой ревизии допускается явная смена базы на другую существующую версию того же документа; сервис не переносит изменения между версиями и не интерпретирует текст.

Черновик наследует доступ самого документа, как DocumentVersion. Project.owner_id должен совпадать с runtime.user_id, Document.project_id — с runtime.project_id. Отдельного owner_id у Draft нет. При передаче проекта новый владелец получает документ с его черновиком, старый теряет доступ. Перемещение документа между проектами требует соответствующего runtime проекта. Это сохранение существующей модели доступа, не добавление аккаунтов или ролей в текущий продукт.

Доступ проверяется до проверки базы и конфликта ревизии. Порядок блокировок совместим с append_version: Project FOR SHARE → Document FOR UPDATE для save / FOR SHARE для read. Блокировки сохраняются до commit/rollback. Они должны предотвращать смену владельца/проекта между проверкой доступа и операцией; проверять актуальное состояние после ожидания блокировки.

## Сохранение и конкуренция

Одна транзакция на операцию. Блокировка существующего Document сериализует даже две первые вставки, когда Draft ещё нет.

- Draft отсутствует и expected_revision=0 → INSERT revision=1.
- Draft есть и revision==expected_revision → UPDATE только Draft, revision увеличивается на 1.
- Любое другое сочетание → 409/draft_conflict/retryable=False, без изменений.

Одинаковый текст с актуальным expected_revision — новое успешное сохранение и следующий номер. Повтор со старым expected_revision, даже с тем же текстом, даёт конфликт. Идемпотентный replay не добавляется: при потерянном ответе caller сначала читает текущее состояние. Две конкурентные записи от одной ревизии, одинаковые или разные, дают один успех и один конфликт; поздняя запись не затирает новую.

updated_at задаётся временем БД `clock_timestamp()` после получения блокировок на **каждом** успешном save, включая UPDATE. Порядок определяет revision, не сравнение часов. Возвращать snapshot только после успешного commit. Ошибки INSERT/UPDATE/commit откатывают всю операцию, сохраняя предыдущий черновик и все исходные строки. Сервис никогда не изменяет Document, DocumentVersion, AnalysisRun, ContextRevision, AnalysisAttempt или ReviewRevision.

OperationalError → 503/storage_unavailable/retryable=True; другие ошибки хранения и commit → 500/storage_error/retryable=False. Сообщения постоянные, без SQL, DSN, текста исключений, содержимого черновика и чужих IDs. Существующие DocumentError не превращаются в 500. Чтение или запись повреждённой строки Draft не должны возвращать успешный некорректный snapshot.

## Модель и миграция

`ara.models.DocumentDraft`, таблица `document_drafts`, ровно пять полей:

- document_id UUID PRIMARY KEY NOT NULL, именованный FK → documents.id;
- base_version_id UUID NOT NULL;
- revision BIGINT NOT NULL, именованный CHECK revision > 0, без default;
- content_markdown TEXT NOT NULL, пустой текст допустим;
- updated_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp().

Именованный составной FK (document_id, base_version_id) → document_versions(document_id,id). Существующий UNIQUE у DocumentVersion уже подходит; старые таблицы/ограничения не менять. PK обеспечивает один текущий Draft на документ. Каскадного удаления нет. Дополнительные таблицы, история и индексы не требуются.

Добавить только `migrations/versions/0005_document_drafts.py`, revision=0005_document_drafts, down_revision=0004_review_revisions. Upgrade создаёт новую таблицу, сохраняя восемь прежних таблиц, их строки и ограничения; повторный upgrade ничего не меняет. Downgrade удаляет только document_drafts: при явном техническом откате черновики этой таблицы удаляются, старые данные сохраняются. В приёмке downgrade выполняется только на собственных одноразовых БД; ara_dev назад не откатывать.
