# D03-16B2B — транзакции полного черновика и legacy arbitration

31 октября 2026, после 572cc1f, Sol 6.1 High, F05/F11/F12. Реализовать working checkpoint read/put/discard на V9 и арбитрацию со старым /draft. Current/original DOCX и receipt ledger не изменяются этим циклом. Save prepare/commit/finalize остаются C; никаких новых endpoints.

Новый module ara.docx_documents.checkpoints:

- get_checkpoint(runtime,*,document_id:UUID)->CheckpointSnapshot.
- put_checkpoint(runtime,*,document_id:UUID,expected_checkpoint_revision:int,request_id:UUID,base_storage_revision:int,base_sha256:str,data:bytes,metadata:CheckpointMetadata)->CheckpointSnapshot.
- discard_checkpoint(runtime,*,document_id:UUID,expected_checkpoint_revision:int,request_id:UUID)->CheckpointSnapshot.

Новые frozen/slotted DTO в checkpoint_models.py: CheckpointRecord(document_id,checkpoint_revision,format_version,phase,base_storage_revision,base_sha256,working_data,working_sha256,metadata,last_request_id,last_request_sha256,updated_at), CheckpointSnapshot(document:StoredDocx,checkpoint:CheckpointRecord). Bytes/metadata/document скрыть из repr. Все stored fields строго проверяются; metadata — B2A typed record; unknown version/shape/hash/package/selection/updated_at -> storage_error без очистки. Snapshots detached. Pending fingerprint проверяется по полному контексту строки согласно d03-16-design.md; его присутствие не доказывает receipt. Этот pure helper разрешён здесь для read integrity и переиспользуется в C.

Каждый вызов — одна _session(runtime), project ownership lock → scoped document lock → checkpoint/legacy rows. get может создавать empty slot revision1 и потому берёт document FOR UPDATE. Other current/legacy writers уже используют этот lock. Проверять scope до stored conflicts/receipts. Returning document/record готовятся внутри transaction; DTO failure откатывает изменения. Commit/response uncertainty не означает доказанный rollback.

Input: exact UUID, строгие int expected 1…MAX_REVISION, base 1…MAX_REVISION, hex64 и defaults package/projection/history budgets B2A; frozen bypass перепроверять. Invalid request -> DocumentError 422 validation_error/прежний безопасный codec/package code, resource ->413. Не логировать bytes/SQL parameters. Внутри stored read invalid данные ->500 storage_error. `_session` сохраняет прежние 503 storage_unavailable semantics.

get: если нет legacy, под lock прочитать/создать empty row. Пустой slot не меняется повторным get. Nonempty возвращает проверенную working/pending copy, даже при base != current: это recoverable conflict, не причина удалить data. Обе версии видны в одном snapshot. Slot + legacy одновременно nonempty -> storage_error; legacy с отсутствующим/empty slot ->409 legacy_draft_present, ничего не создавать/не менять.

put: B2A encode_metadata phase working, derive data hash/size, detach metadata. Slot обязан уже существовать после get; отсутствие ->409 checkpoint_conflict. Canonical fingerprint namespace ara.docx.editor-checkpoint.v1\0 + UTF-8 sorted compact ensure_ascii JSON {version:1,action:"put",document_id,expected_checkpoint_revision,request_id,base_storage_revision,base_sha256,working_sha256,working_size_bytes,metadata}; UUID/revisions strings, size int. Если revision==expected+1 и last_request_id совпадает — matching fingerprint возвращает текущий snapshot без записи/смены timestamp; mismatch ->409 idempotency_conflict. Иначе exact expected revision, phase не pending, base revision/hash == current. Изменение current даже с теми же bytes ->409 docx_conflict. Запись working + revision+1 + request identity + updated_at атомарна. При MAX нельзя сделать новый переход:409 revision_exhausted; завершённый replay проверяется раньше. Старая retry после любого следующего перехода ->checkpoint_conflict, без восстановления старого bytes.

discard: тот же CAS/retry, fingerprint {version:1,action:"discard",document_id,expected_checkpoint_revision,request_id}; очищает base/working/metadata до empty и увеличивает revision даже для empty. Last request остаётся tombstone. Current/receipts не меняются. Pending ->409 pending_save_required без mutation; C добавит отдельную операцию discard_pending с предварительной классификацией receipt, не ослабляя working-only discard. Legacy conflict как get. Чужой slot никогда не очищать по старому expected.

Legacy recover(): под его прежним scope/document lock прочитать только phase/version/revision нового slot, не читать Word BYTEA и не парсить DOCX. Nonempty без legacy ->409 draft_mode_conflict; nonempty вместе с legacy ->500 storage_error до decode старого payload. Empty/absent сохраняют все прежние ответы. Только фактически успешный PUT старого draft при empty slot увеличивает checkpoint_revision и очищает last_request_id/hash; exact token/payload replay не увеличивает, DELETE не увеличивает (предыдущий PUT уже fence). Overflow отказывает и откатывает старый PUT. Тimestamp slot обновляется. Невалидные phase/version/revision считаются stored error.

## Пути и приёмка

Source: новые docx_documents/checkpoints.py, checkpoint_models.py, checkpoint_fingerprints.py; recovery.py только описанная guard/fence. Старые storage/exporters/DTO/API/models/migrations/tests/dependencies/runner/tasks/progress/AGENTS не менять. Freeze tests/acceptance/test_docx_checkpoints.py и этот контракт; дополнительно tests/docx_documents/test_checkpoint_storage_*.py. Результат docs/d03-16b2b-result.md, queue update.

Frozen acceptance: initial/repeated get; full bytes/metadata working roundtrip и reopen/new engine; dirty restore; snapshot isolation; put/discard exact replay/mismatch/superseded; empty tombstone ABA; two writers one winner; чужой current даже same bytes; scope/nonexistent before conflicts; legacy guard/actual PUT fence/replay/no Word parsing; validation/stored corruption/response rollback/MAX/retry. Дополнительные real transaction/ACK-loss/lock ordering/restart/pending-integrity cases. Только disposable PostgreSQL DB; baseline рабочих баз неизменен. Red→implementation→targeted→bash scripts/check.sh→result/local commit, затем C с отдельным контрактом на том же режиме, пока качество достаточно.

Errata после cfa142a: новый legacy interoperability test ожидал 200 при успешном DELETE старого /draft, хотя существующий контракт возвращает 204 No Content. Два assertions исправлены на точный прежний код 204; обязательность успешного удаления/fence/replay/guards и все остальные критерии сохраняются. Старые API/tests не изменяются ради нового примера; отдельный коммит фиксирует исправление новой приёмки.

Второе техническое errata того же нового test: старый error envelope имеет плоский code, а не error.code. Проверяется тот же точный HTTP 409 и draft_mode_conflict, исправлен только путь чтения существующего поля. Новый storage/API не подменяет старый envelope ради ошибочного теста.
