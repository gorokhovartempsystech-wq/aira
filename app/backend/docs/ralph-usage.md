# Ограниченные циклы Ralph

Ralph в этом проекте — ограниченный повтор задачи через локальный `codex exec`: исполнение → проверка → следующая попытка при необходимости. Runner не является готовностью продукта и не заменяет просмотр изменений человеком.

Текущий продукт определяет [current-product-scope.md](current-product-scope.md) от 28 октября 2026. Старые T01-01…T03-01 остаются завершённой технической историей; продолжение Merge/preview/apply не входит в новый объём.

Завершён цикл **D01-01 — сохранение и восстановление локального черновика существующего документа**, узкая часть F05/F12. [Контракт](d01-01-contract.md) задаёт Python API, миграцию, точный текст, контроль ревизии и изоляцию доступа; [результат](d01-01-result.md) фиксирует проверенное поведение и ограничения. UI, таймер автосохранения, новые документы и ML в этот цикл не входят. Зависимость от T03-01 в runner обозначает существующую исходную схему 0004, а не продуктовую необходимость Merge.

Завершён цикл **D01-02 — HTTP API чтения и сохранения черновика существующего документа**. [Контракт](d01-02-contract.md) ограничивает задачу двумя методами GET/PUT, строгой JSON-формой и безопасными ошибками; [результат](d01-02-result.md) фиксирует реализацию и ограничения. Создание пустого документа, UI и таймер остаются отдельной работой. Независимый `bash scripts/check.sh` runner 28 октября: **607 тестов и 24 подтеста проходят**.

Завершён **D02-01 — исходный пакет DOCX и экспорт без изменений**. [Контракт](d02-01-contract.md) задаёт чистый Python-модуль, неизменяемый каталог частей/связей и побайтовое сохранение оригинала; [результат](d02-01-result.md) фиксирует проверки и ограничения. Независимый gate runner: **711 тестов и 24 подтеста проходят**. Контрольный DOCX и его экспорт совпадают побайтово, рендеры LibreOffice — попиксельно. Текстовая проекция, редактирование, БД и интерфейс в этот цикл не входят.

- `AGENTS.md` — правила проекта и работы с секретами.
- `ralph/tasks.json` — ограниченные задачи и их фактические статусы, включая завершённые D01-01…D02-06.

- `scripts/ralph.py` — runner одной явно выбранной задачи.

Первоначальное продолжение — PostgreSQL и миграции → создание/чтение документа → версии и изоляция владельцев — уже выполнено. Каждый последующий цикл отдельно получает окружение, проверки и явно заданные `allowed_paths`; завершение одной задачи не запускает следующую.

## Запуск из корня проекта

Используется подготовленное окружение `.venv`. Сначала проверить план без вызова модели:

```bash
bash scripts/ralph.sh --task D02-06 --max-iterations 3 --dry-run
```

Команда завершённого цикла D02-06, максимум три попытки:

```bash
bash scripts/ralph.sh --task D02-06 --max-iterations 3 --agent-timeout 1800
```

D01-01, D01-02, D02-01, D02-02, D02-03, D02-04, D02-05 и D02-06 имеют статус completed: их повторный запуск не вызывает исполнителя. Следующий цикл не запускается автоматически; он требует отдельного контракта и независимой приёмки.

Отдельно повторить проверку приложения. Полный gate использует PostgreSQL; если она остановлена, сначала выполнить `bash scripts/postgres.sh start`:

```bash
bash scripts/check.sh
```

Обёртка `scripts/ralph.sh` выбирает проверенную локальную CLI 0.154.0: установленная ранее 0.149.1 отказалась работать с текущей моделью. См. [источник и проверку CLI](cli-runtime.md). Runner использует существующие модель, провайдера и авторизацию. Запуск выполняется штатной командой `codex exec --approve-for-me ...`: этот флаг задаёт `approval_policy=on-request`, `approvals_reviewer=auto_review` и `sandbox=workspace-write`. Выбор автоматической проверки соответствует явно указанному режиму разрешений основной сессии Codex. Dry-run показывает все три запрашиваемых значения.

В этой версии отдельный глобальный `--ask-for-approval on-request` не передаётся в `exec`, а одиночный `-c approval_policy=...` перекрывается внутренним значением `Never`. Штатный `--approve-for-me` включает предусмотренную в исходнике ветку автоматической проверки и убирает это внутреннее переопределение. Дополнительный `--sandbox` в той же команде конфликтует с флагом; `workspace-write` уже входит в выбранный режим. [Обоснование по исходникам](cli-runtime.md#почему-используется-approve-for-me).

Постоянные настройки, платёжная квота и режим авторизации не изменяются. Запросы разрешений проходят автоматическую проверку; её отказ или недоступность требуют отдельного решения. Ошибки авторизации, квоты и разрешений останавливают цикл. При сообщении об отклонении политики или reviewer управляемыми настройками runner блокирует задачу даже при нулевом коде выхода CLI. Он не повторяет запуск с другой политикой и не использует флаги обхода или отключение управляемых ограничений.

## Как определяется результат

Успех требует завершившегося без ошибки исполнителя, валидного структурированного ответа со всеми выполненными критериями и успешной независимой проверки runner. Выход за разрешённые пути среди видимых Git файлов блокирует задачу. Заявление «готово» само по себе не закрывает её.

`allowed_paths` проверяет изменения после работы агента; это не отдельная файловая песочница. Игнорируемые файлы не входят в этот снимок. Доступ дополнительно ограничивается штатным `workspace-write` sandbox и правилами проекта. Во время попытки другие исполнители не должны менять видимые Git файлы: runner не сможет отличить их изменения от изменений выбранной задачи.

Статусы задач: `pending`, `in_progress`, `completed`, `blocked`. Структурированный ответ исполнителя и результаты команд записываются runner; файлы отдельных запусков остаются в локальной исключённой из Git папке `.ralph/`. Перед добавлением журнала в коммит просматривают его содержание: он не должен содержать секреты и рабочие документы пользователя.

Повторный запуск completed-задачи не вызывает модель снова. После исчерпания попыток или блокера сначала смотрят журнал и изменения, устраняют причину, затем отдельно решают о следующем запуске. Runner не переключается на следующую задачу, не устанавливает зависимости, не делает commit/push и не разворачивает сервис.

## После каждого цикла

Проверить изменения в разрешённых путях, результат общей команды и запись о завершении. У D01-01 проверяются текущий черновик, точность восстановления, конкурирующие сохранения, изоляция и неизменность сохранённых версий. Следующая задача требует отдельного выбора по текущему объёму; runner не переходит к ней автоматически.

Рабочий архив и пять отчётов с исходными материалами исключены через `.gitignore`. Это не автоматическое разрешение публикации остальных файлов: локальный baseline и загрузка на GitHub — отдельные действия. Первый цикл работает локально.
