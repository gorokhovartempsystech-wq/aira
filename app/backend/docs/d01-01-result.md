## Проверенное поведение

Python API `ara.drafts.read_draft` и `save_draft` хранит один текущий черновик существующего документа отдельно от сохранённых версий. Текст восстанавливается через новый engine дословно, включая пустую строку, пробелы, CRLF, Unicode, незакрытую разметку и объём больше прежнего лимита версий. Чтение без черновика возвращает None и ничего не создаёт. Возвращаемый DraftSnapshot неизменяем и отделён от сессии.

Каждое успешное сохранение увеличивает ревизию. При двух записях от одной ревизии сохраняется одна, другая получает draft_conflict. Повтор со старой ревизией также конфликтует, даже при одинаковом тексте. Явная базовая версия должна принадлежать документу, но может быть старше его текущей сохранённой версии. Сервис не меняет документ, версии или результаты анализа.

Доступ наследуется от документа. Блокировки проекта и документа удерживаются до commit или rollback; смена владельца и перемещение документа учитываются после ожидания блокировки. Время каждого сохранения берётся из PostgreSQL после получения блокировок. Сбой записи или commit сохраняет прежние данные и возвращает безопасную ошибку. Импорты нового пакета не читают конфигурацию, файлы или сеть и не подключаются к БД.

## Ограничения

Это внутренний Python-сервис. HTTP API черновиков, редактор, таймер автосохранения, создание нового пустого документа, вкладки и перенос черновика в проверяемую версию не реализованы в этом цикле. F05/F12 целиком не закрыты. Реальный локальный ML, desktop-установщик, DOCX и лицензирование остаются отдельной работой; старый fixture-анализ не стал реальной моделью.

Использована существующая PostgreSQL без решения о её поставке в desktop-продукте. Старые технические модули сохранены; Merge, Confluence и обязательные аккаунты не возвращаются в продуктовый объём. Следующая задача требует отдельного контракта и приёмки. Код и история Git хранятся локально; remote не настроен.
