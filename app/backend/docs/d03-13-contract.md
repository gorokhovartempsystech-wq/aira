# D03-13 — сохранение paragraph commands через API

31 октября 2026. Отдельный backend-цикл F05/F11/F12 после ea98f84. Использовать неизменные pure API D03-11/D03-12, PostgreSQL и таблицу docx_edit_receipts V8. Frontend Ани и проверочный workspace не менять. Основание перехода/необходимого расширения API — прямая команда Никиты самостоятельно выполнить оставшиеся функции отдельными циклами.

## Один маршрут и строгий транспорт

POST /docx-documents/{document_id}/paragraph-commands, только при явном local DocumentRuntime. Default factory остаётся health-only. Обязательный единственный Idempotency-Key — canonical lowercase UUID. Query запрещён. JSON UTF-8, единственные content-type/content-encoding/content-length, только identity; размер ≤2 MiB по объявленному length и фактическому stream. Дубли JSON keys на любой глубине, NaN/Infinity, неправильный UTF-8, лишние/неверно типизированные поля, пустой/смешанный batch, noncanonical revision/UUID отклоняются до storage. Не логировать текст/ключи; безопасный прежний DraftErrorResponse/request_id/no-store, реальные ошибки 404/409/413/415/422/500/503.

Body: {expected_storage_revision: canonical decimal string 1..MAX_REVISION-1, kind: structure|format, commands: [1..1000 commands]}. Structure batch содержит только insert/delete; format batch только format. Все anchors относятся к одному исходному пакету, без цепочки пересчитываемых anchors внутри batch. Nested command.kind: insert {anchor,expected_text,texts:[1..1000 XML-safe strings],position:before|after=after}; delete {anchor,expected_text}; format {anchor,expected_text,style_id:null|string=null,list_kind:none|bullet|numbered=none,list_id:null|string=null}. Anchor по прежнему TextEditAnchor; expected_text и каждый новый текст ≤100000 code points, суммарно новый текст ≤1000000, суммарно новые абзацы ≤1000. Native DTO validation применяется до storage; batch semantics/definition checks — против сохранённого DOCX. Без coercion/trim/нормализации.

Ответ HTTP 200: прежние поля TextEditReceipt (revision строкой) + operation_id UUID. Изменённые anchors получить новым GET /view. В OpenAPI описать request/response, обязательный header, виды commands, все ошибки и реальные revision bounds. Добавляется ровно одна строка в точный список tests/documents/test_http_boundaries.py; все прежние строки/assertions обязательны. Это необходимое расширение разрешённой поверхности для нового маршрута, не удаление старых проверок и не изменение frozen D03-11/D03-12.

## Одна транзакция

Сначала прежний project ownership lock и scoped document write lock, затем _snapshot, затем durable receipt по (document_id,operation_id). Для нового ключа проверить expected revision, применить один соответствующий pure batch, провалидировать package прежними storage limits, сохранить current bytes/hash/revision+1/DB clock timestamp и receipt в одной транзакции. Original bytes/title/created_at не менять. Даже semantic no-op получает одну новую storage revision и receipt; повтор — без новой записи. Проверки/генерация/БД в worker thread, не event loop. Не читать секреты при import/setup; supplied engine не закрывать.

Fingerprint: SHA256(b"ara.docx.paragraph-commands.v1\\0" [с настоящим NUL] + UTF-8 canonical json model_dump, sort_keys=True, ensure_ascii=True, separators=(",",":")). Defaults участвуют, порядок keys/JSON whitespace не участвует, порядок commands участвует. Отдельный namespace защищает от смешения с прежним text-edit ledger. Существующий receipt валидировать как D03-04 (finite metadata/hash/revision, соответствие latest snapshot если receipt latest). Тот же ключ/тот же normalized body возвращает исходный receipt даже после новой записи, без применения и без перезаписи latest. Тот же ключ с другим body/другим видом операции — 409 idempotency_conflict. Scope проверять до replay. Ключ независим для разных документов.

Ошибки pure stale_source/text_mismatch — 409; остальные StructureError/FormattingError — 422, *_limit_exceeded — 413. Нижние DocxError/ProjectionError — 413 для лимитов, иначе 422. Corrupt stored package/receipt и неожиданные ошибки — прежние безопасные 500; недоступная БД/потерянный commit ACK — 503. Отклонённый batch не создаёт ни новой revision, ни receipt. Failure receipt insert откатывает package. Concurrent same key применяет однажды; разные ключи одной revision имеют одного победителя, другие 409 CAS. Старые span edits/binary saves/recovery сохраняют прежние контракты и тот же lock.
