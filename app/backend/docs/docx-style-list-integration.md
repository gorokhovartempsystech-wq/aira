# Style-list checks through the owned fixture desktop

D03-17A2b8B connects the [style-list reader](docx-visible-style-lists.md) through review4,
unchanged storage format1, fixture2 native checks, view4, persisted hides and an explicit
programmatic desktop mode. The model output remains visibly synthetic.

```python
from dataclasses import replace
from ara.desktop.composition import FixtureDesktop

config = replace(existing_config, analysis_mode="style_lists_fixture")
desktop = FixtureDesktop(config)
```

The existing [owned lifecycle](desktop-composition.md), online license at every startup,
Home/PostgreSQL ownership and drain rules still apply. Construction is inert. The fixed lazy
factory selects the new source profile and existing native review2 transport; no custom
algorithm registry, new route or SQL migration is introduced. Legacy/structured/outline modes
and the legacy default remain available unchanged. Native acceptance here is macOS; portable
Windows child-body tests are not native Windows composition proof.

Each new check in this mode uses `docx-analysis/final-visible-style-lists-v1` and
`docx-review/4`, including plain files and direct-only lists. Source capture rederives exact
bytes/snapshot/attempt/result. Previously accepted checks replay/retry with their original
one of four profiles even after the current document changes. A mode change never silently
upgrades stored evidence or transfers its hides to another profile.

Generated context keeps each item's numbering_source, actual style numPr location, applied
selector (or proved default), complete basedOn chain to the owner and abstract level binding.
Direct items explicitly carry empty/null style facts. Worker shape checks bound the chain,
part/owner relationships and total work; original XML reconstruction by the parent remains
semantic authority. Generated labels cannot be quoted as literal evidence. See the standalone
[review4](../contracts/docx-review-v4.json) and [view4](../contracts/docx-review-view-v4.json)
shapes; old versions remain closed and reject the extra style fields.

View4 retains all source list/note context under filtering/hide/show. Public output excludes
private finding provenance and hidden keys. Hiding every finding does not change the original
no-findings result. Same-source decisions survive a full close/restart/retry. Across edits,
the matcher accounts for every style-binding field and unchanged non-main parts, plus the
existing literal/neighbor/ancestor/counter proof. A distant ordinary main edit can preserve a
hide; changed style/numbering bytes, text or ambiguous correspondence makes it visible again.
This is deliberately conservative and does not discard the stored original hiding decision.

Synthetic native acceptance exercises import/check/hide/full Home+PG close/fresh online grant/
retry/show/exact DOCX export and subsequent distant/relevant edits. It covers four historical
profiles, stop without result, rehashed provenance corruption, malformed worker contexts,
aggregate chain budgets, source defaults/plain files and old exact-byte compatibility.

This integration adds no Word renderer or GUI and does not prove full DOCX coverage. The reader's
unproved numbering/Word semantics remain explicit gates. Real model assets and quality, Anya's
frontend, native Word/Windows acceptance, trusted launch packaging and signed releases remain
separate work. No document content is sent for licensing.
