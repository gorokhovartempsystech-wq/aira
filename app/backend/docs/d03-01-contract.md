# D03-01 — первый локальный экран документов

30 октября 2026. Одна задача после D02-08, часть F04/F11/F12 текущего объёма: пользователь видит список DOCX, выбирает файл, загружает его, открывает сведения и скачивает текущую сохранённую версию. В репозитории нет frontend/desktop-кода. Это локальный экран для проверки сценария в браузере, а не установщик или законченный редактор. Пользователь ранее выбрал прямую разработку в текущем чате; Ralph/tasks/progress не изменять.

## Доставка и границы

Добавить `ara.workspace.install_workspace` и два подключения в app.py только с явным DocumentRuntime. Три фиксированных GET: `/workspace`, `/workspace/assets/app.css`, `/workspace/assets/app.js`; UI/asset-маршруты не включать в OpenAPI продуктового API. Фабрика без runtime их не устанавливает. Существующие API, схема БД, зависимости и контракты сохраняются. Python-модули импортируются без I/O; создание app не читает assets и не подключается к БД. Assets читаются при запросе через importlib.resources из фиксированных путей; пользовательский путь не принимать. Без StaticFiles/mount на корень/произвольные каталоги. Добавить точный package-data для `ara.workspace/static/*.{html,css,js}`, без новой зависимости.

HTML/CSS/JS автономны, без CDN, шрифтов/скриптов извне и сборщика. Content-Type корректный UTF-8, Cache-Control no-store, X-Content-Type-Options nosniff, Referrer-Policy no-referrer, CSP ограничивает ресурсы и connect-src своим origin, запрещает inline script/style, object/base/frame embedding. Внешние ссылки и загрузки не открываются. Обработчики UI не выполняют SQL; данные поступают через существующий DOCX API. Продукт остаётся локальным настольным приложением; браузерный экран — средство разработки и проверки интерфейса.

## Поведение экрана

Русский интерфейс AIRA с явным обозначением предварительной версии. Слева список документов и кнопки обновления/следующей страницы, справа сведения выбранного документа и скачивание; отдельная форма загрузки DOCX с изменяемым названием. При старте не открывать последний документ автоматически. Использовать GET /docx-documents с limit=20 и offset; длинные названия переносятся, порядок API сохраняется, повторные IDs не дублируются. Количество показывать как загруженное, не как общее число документов.

Пользователь выбирает один `.docx`, название по умолчанию — имя без последнего расширения, затем явно подтверждает загрузку. До сети проверить расширение без учёта регистра, размер 1..33554432 и название по текущим правилам 1..200 символов, без trim/NUL/surrogates. Загрузить File как raw body с DOCX MIME через POST D02-08. Одному неподтверждённому импорту соответствуют неизменные UUID/file/title, повтор использует тот же ID и данные. При неоднозначной сетевой ошибке/тайм-ауте предложить повтор без нового ID; новый выбор файла начинает отдельную попытку. Двойное нажатие не создаёт параллельных запросов. Тело/названия/ID не сохранять в localStorage/sessionStorage и не отправлять на внешний origin. Файлы не разбирать в браузере и не показывать их содержимое как HTML.

Выбор документа запрашивает свежие сведения. Перед чтением другого документа прежние сведения/скачивание скрываются; ошибка не оставляет действия с прежним файлом под новым названием. Для простоты на время операции блокировать действия, способные изменить выбранный документ/список/импорт; защитить handler от повторного входа. Ограничить ожидание запросов через AbortController: чтение 15 секунд, импорт 60 секунд; это технические тайм-ауты UI, не тайм-аут анализа. Фоновое автосохранение/автообновление не добавлять.

Скачивание через GET /content проверяет HTTP-успех до создания Blob URL. Имя выгрузки — канонический UUID.docx; временный URL освобождается после начала скачивания. Ошибка показывается на экране, JSON-ошибка не скачивается как DOCX. Не отображать storage_revision через неточное JS Number и не использовать его для записи: редактирование в эту задачу не входит. Названия/сообщения сервера/метаданные — недоверенные строки, использовать textContent/DOM API, без innerHTML/eval. Ошибки показывать понятным русским текстом из фиксированного набора, без raw SQL/stack/body. Состояния загрузки/успеха/ошибки доступны через live regions; поля и действия имеют подписи и работают с клавиатуры. Адаптивная вёрстка для узкого окна без горизонтального переполнения.

## Разрешённые изменения и проверки

Реализация только `src/ara/workspace/**` и импорт/вызов в `src/ara/app.py`. Подготовка: этот контракт, независимый `tests/acceptance/test_workspace.py`, точный package-data в pyproject.toml. Отчёт и ссылка ralph-usage — снаружи реализации. Runner, старые тесты/сервисы/миграции и зависимости не менять. Пользовательский архив, output/ и .artifact-build/ не читать. Новые тесты и критерии заморозить до реализации.

Проверить asset-маршруты/заголовки/отсутствие DB/непрямой доступ к файлам, импорт без I/O и упаковку assets в wheel; полный bash scripts/check.sh. В реальном браузере проверить загрузку синтетического DOCX, список/сведения, обновление страницы, неверный DOCX, literal HTML в имени, скачивание с побайтовой сверкой, live-state ошибок и вид на узком окне. Для QA использовать собственную временную БД, удалить только её после остановки preview; основную БД не наполнять тестовыми документами. Сохранить screenshot и отчёт о фактических проверках. Не заявлять установленное desktop-приложение, просмотр Word, текстовый редактор, анализ или автосохранение. После одной задачи остановиться.
