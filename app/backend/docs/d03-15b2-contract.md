Это составные команды backend-controller; события DOM/IME, inline набор/typing format и durable recovery — последующие отдельные циклы. Не объявлять весь D03-15B/редактор готовым только по этому subcycle.

## Методы EditorSession

enter(*, expected_revision:int), join_previous(*,expected_revision:int), join_next(*,expected_revision:int) -> прежний EditorSnapshot. Expected revision проверяется первой. Требуется collapsed selection (одинаковые paragraph path/offset, affinity может различаться); выделенный диапазон → EditorError unsupported_intent, без удаления текста. Новое content-free сообщение/код unsupported_intent разрешается добавить в EditorError; прежние поля/коды/методы/контракты остаются.

Enter посреди/в начале непустого paragraph вызывает lossless split. В конце непустого прямого level-0 списка продолжает тот же ID/level, приоритет над next style. В конце непустого нелистового paragraph применяет явно заданный current-style w:next только к новому пустому правому paragraph. При отсутствии next/ссылке на себя — сохранить формат; при invalid/duplicate/missing/character next — unsupported_intent. Не угадывать Normal в импортированном файле. Прямой next проверяется на current style, а не наследуется из basedOn.

Если next отличается, новый пустой p получает только pStyle=next, без прямых spacing/ind/outline/rPr/numPr прежнего p. Старый левый paragraph не переоформляется. Если Enter завершает пустой прямой список, число p не меняется: текущий пустой p получает next либо проверенный default paragraph style, также с полным сбросом прямых overrides/пустых typing runs. Default может отсутствовать (ID=None, используется docDefaults); несколько defaults — отказ. Это явное стартовое правило AIRA для нового пустого содержимого, не потеря оформления существующих символов. Весь составной шаг — одна core revision/frame/undo позиция. Undo возвращает точный старый файл и курсор, redo — точный итог. Не публиковать промежуточный split.

Для решений по стилям требуется единственная корректно связанная styles part с тем же Word namespace. Существующий style ID проверяется как paragraph, basedOn references разрешаются не более чем по 128 уникальным style nodes; циклы/неоднозначность/неверные ссылки дают unsupported_intent. Inherited numPr через style пока не редактируется: положительный numId в effective style chain current/next/default → unsupported_intent там, где нужен style-policy. Ближайший numId=0 отключает наследуемый список; partial numPr без numId — отказ. Прямой nonempty list продолжает работать через неизменный D03-14 без разбора next. Для middle/start split style catalog не требуется. Empty обычный paragraph split сохраняет формат, после проверки отсутствия inherited list. Отсутствие styles part на style-policy ветках не скрывать произвольной подстановкой стиля.

Join_previous допустим только при offset=0, join_next — при offset=len(text). На краю документа no-op сохраняет весь snapshot/ID/history/selection. Через table/opaque не перескакивать → BoundaryError nonadjacent_paragraphs. Реальный join делегируется неизменному compatible join D03-14; несовместимые стили/прочие gates сохраняются. Курсор на стыке; один undo шаг.

Сборка Enter candidate через pure split и локальную замену **только пустого** p с прежними lexical/package/protection gates и output validation. Не сбрасывать pPr непустого paragraph. Package/projection/session budgets прежние, namespace/UTF16/Strict сохраняются. Текст/порядок остальных blocks/ZIP parts/ID нетронутых p прежние. Candidate и selection полностью готовятся до единственной публикации, включая ошибку response/лимита/стиля после split.

Основание next semantics: [Microsoft](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.nextparagraphstyle?view=openxml-3.0.1). Стандарт игнорирует неверную next-ссылку; консервативный отказ AIRA и сброс direct overrides нового пустого p — решения этого контракта. Они не выдаются за полную эмуляцию Word.
