## API

ara.docx_package.structure экспортирует frozen/slotted DTO InsertParagraph(anchor: SourceAnchor, expected_text: str, texts: tuple[str,...] = ("",), position: str = "after"), DeleteParagraph(anchor, expected_text), StructureLimits(max_commands=1000, max_new_paragraphs=1000, max_text_chars=1000000), StructureError, export_structure(data: bytes, commands: tuple[InsertParagraph|DeleteParagraph,...], *, limits: DocxLimits|None=None, projection_limits: ProjectionLimits|None=None, structure_limits: StructureLimits|None=None) -> bytes.

Настоящие классы/типы без coercion, frozen bypass перепроверяется при вызове; тексты не попадают в repr/errors. Anchor — source hash lowercase64, main part и настоящий tuple неотрицательных int без bool. Target — **paragraph anchor**, не text span. Только непосредственные абзацы main body, не ячейки и не вложенные обёртки. expected_text точно равен прежней полной проекции абзаца, без trim/Unicode normalization. Неверные формы — invalid_input, чужой source hash — stale_source, неверный адрес/часть — invalid_anchor, несовпадение текста — text_mismatch.

Insert вставляет один или несколько **новых** абзацев строго before/after целевого. texts — непустой tuple настоящих str. Новые абзацы используют default paragraph formatting документа, не копируют потенциально опасные свойства/ID/ссылки исходного абзаца и не добавляют styles/numbering/relationships. Unicode/пробелы сохраняются буквально; LF/TAB становятся w:br/w:tab, CR/CRLF/lone surrogates/запрещённый XML 1.0 отклоняются. Пустой текст оставляет редактируемый w:t. Для изолированного нового XML явно объявляется собственный WML prefix с тем же Transitional/Strict namespace, чтобы не зависеть от локальных xmlns исходного p.

Delete удаляет ровно исходный абзац вместе с его text/run/paragraph properties; нетронутые элементы не переносятся в соседей. В body должен остаться хотя бы один непосредственный абзац. Удаление последнего — unsupported_structure; очистка текста доступна прежним text-edit. Простые formatted runs, tabs/breaks допустимы. Абзацы с opaque, hyperlinks, неизвестными content children или sectPr не изменяются; inline protection/ревизии не обходятся.

## Сохранность и batch

Команды относятся к одному исходнику, проверяются атомарно. На один anchor разрешена одна команда; одинаковый anchor, два insert в одну byte position, пересечение/touch insert с удаляемым диапазоном — conflicting_commands. Соседние delete допустимы, если остаётся абзац. Порядок независимых команд не влияет на итоговые bytes. Все команды/новые абзацы/символы считаются до изменения, включительные положительные настоящие int лимиты; превышение structure_limit_exceeded. Нижние ошибки DocxError/ProjectionError не маскировать.

Любая фактическая правка проходит прежние settings/signatures gates: digital signatures, documentProtection, enabled/ambiguous trackRevisions/settings блокируют операцию. Глобальные диапазоны main body (bookmarks/comment/permission/revision ranges), tracked-change elements, fldChar/instrText консервативно дают unsupported_structure: не вставлять/не удалять текст внутри неизвестного диапазона. XML comments/PI **внутри целевого абзаца** также блокируют, внешние сохраняются. Другие opaque объекты вне target не теряются и не мешают безопасной операции при отсутствии указанных глобальных диапазонов. Это явные ограничения первого структурного API, не обещание полного Word-редактора.

Менять только byte ranges выбранных абзацев/вставок; не сериализовать весь main XML. Сохранить declaration/encoding/BOM, comments/PI/namespace declarations и весь XML за пределами выбранных ranges. UTF-8 и UTF-16 LE/BE поддерживаются, другие валидные кодировки могут давать unsupported_structure при фактической правке. Пустой commands после валидации возвращает точные исходные bytes, в том числе защищённого документа.

Сохранить состав/порядок/имена всех ZIP entries (включая directories), нетронутые части, archive/entry comments, timestamps, compress_type, create_system, internal/external attrs, неструктурные local/central extra. ZIP64 extra можно пересчитать. Использовать существующие parsing_end/chunks и safety helper settings из editing без изменения старых файлов; не терять legal ZIP signatures в archive comment. Повторно проверить package/projection и фактический порядок/текст paragraph blocks теми же лимитами до возврата. Новые anchors относятся к новому hash; старые должны отклоняться.

## Приёмка

Синтетические cases: insert before/after/many/empty, delete/last refusal, literal Unicode/LF/TAB/escaping, fresh anchors, multiple changes/conflicts/limits/invalid frozen DTO, Strict/UTF16/custom part/local namespaces/selfclosing p, immutable bytes outside edits и ZIP metadata, opaque/table preservation, signatures/protection/ranges/fields/comments, no-op, inert imports/operations и сохранение прежних возможностей. Rich fixture: вставка абзацев и удаление одного допустимого существующего, сравнение нетронутых частей/внешнего XML; render bundled LibreOffice по documents skill, просмотр всех страниц. Общий bash scripts/check.sh; основная БД неизменна. Без секретов/архива/output/.artifact-build. После проверенного результата — отчёт/локальный коммит и переход к отдельному D03-12 по прямому разрешению Никиты.

Техническая errata приёмки 31 октября: шесть случаев первоначально падали **до вызова нового API**. В четырёх XML-fixture использовалось неподдерживаемое Expat spelling декларации utf-16-le/be; теперь builder получает корректное utf-16le/be при тех же байтах LE/BE, как в прежней D02-03 приёмке. В двух field-cases старый projector намеренно делает всё body opaque, поэтому якорь известного первого fixture-p строится явно вместо получения отсутствующего paragraph DTO. Ни один assertion, тестовый сценарий, защита или критерий не удалён/ослаблен, старые тесты не менялись. Errata сохраняется отдельным коммитом; это исправление недостижимых входных данных новой приёмки в рамках разрешённых самостоятельных циклов, не адаптация ожидаемого поведения под реализацию.
