# D03-08 — вкладки открытых документов

30 октября 2026. Одна задача F11/F12 после D03-07; продолжение здесь на Sol 6.1 High. Один открытый документ — одна вкладка. При переключении сохранять текущую recovery copy и в памяти её текст, selection, history, pending key/payload, CAS base, view и ошибки. Закрытие вкладки не удаляет документ или подтверждённую копию; следующий явный open восстанавливает её через D03-05. Перечень вкладок после перезапуска не восстанавливать автоматически: это не автоматическое открытие последнего документа.

## Модель и состояние

Чистый tabs.js экспортирует MAX_OPEN_DOCUMENTS=12 и createTabs(): open(id,value), activate(id), close(id), get(id), has(id), activeId(), entries(). ID — непустая строка до 128 units, value — opaque non-null object. Map сохраняет порядок открытия и ссылки на состояние (включая history); entries возвращает новые строки/массив, а не внутренние key records. open существующего ID выбирает прежнее состояние, не заменяет его аргументом и не создаёт дубль. activate неизвестного ID — ошибка без мутации. close активной выбирает правого соседа либо левого, последней — null; закрытие другой/неизвестной не меняет active. Превышение 12 новых документов — явный отказ без eviction или потери старых состояний; повторное открытие существующей разрешено.

В UI один активный DOM editor, неактивные состояния удерживаются отдельно, DOM projection nodes можно парковать без HTML serialization. Перед уходом дождаться уже отправленного checkpoint и подтвердить последнее состояние (включая неизменный pending POST). При ошибке/конфликте/превышении лимита переключение или закрытие не завершать, текст остаётся в исходной вкладке; никакого удаления recovery copy при обычном переключении. Composition/busy/dialog не допускают смены состояния. Таймер неактивной вкладки остановлен; callback не пишет другой документ. При возврате создаётся новый active controller D03-06 с двухминутным сроком, прежние draft/history/anchor/revision/pending остаются. На экране явно указать: при переключении сохраняется черновик, запись в DOCX работает в выбранной вкладке. Фоновое пакетное сохранение в этой задаче не добавлять.

Повторный open уже активной вкладки — no-op, не сбрасывает dirty/history. При возврате в существующую вкладку не заменять её редактор свежим GET. Сохранённая CAS base не ребейзится. Добавить явное «Обновить документ»: прежний discard-dialog при dirty/pending, затем прежний scoped GET/view/recovery; это путь после конфликта или stale cached view. Ошибка открытия нового документа возвращает прежнюю вкладку, не оставляет текст чужого документа под новым заголовком. Новая metadata/read-error вкладка может показывать ошибку просмотра и download своего UUID; кнопка обновления доступна. Импорт нового файла при активной правке разрешён: сначала подтвердить/припарковать её, затем прежний stable-ID import, новая вкладка только после подтверждения; ошибка import сохраняет attempt и прежнюю вкладку. Лимит проверять до нового импорта.

## Закрытие и доступность

Список с role=tablist, tab buttons aria-selected/aria-controls/roving tabindex, один role=tabpanel. Стрелки/Home/End выбирают вкладку, Delete закрывает выбранную с теми же проверками, focus возвращается на актуальный tab. Отдельные подписанные кнопки закрытия, без nested buttons; title через textContent, длину визуально ограничить ellipsis/scroll без потери полного accessible name. Узкий экран не создаёт page overflow.

Закрытие dirty/pending требует dialog «Остаться / Закрыть вкладку», объясняющий сохранение recovery copy и отсутствие отката DOCX. Сначала подтвердить копию и дождаться in-flight PUT, затем убрать RAM state/таймер/history. При конфликтующей/неподтверждённой копии закрытие блокируется, пользователь может скопировать текст или использовать существующий явный discard активного редактора. Закрытие inactive вкладки не меняет active текст/history и не удаляет чужую копию. Последняя вкладка скрывает reader/скачивание. beforeunload проверяет dirty/pending **всех** открытых вкладок, а не только видимой. Скачивание адресует выбранный UUID и сохраняет прежний dirty guard. Статусы «черновик/требуется подтверждение» привязаны к нужной вкладке.
