# D03-09 — новый DOCX по базовому шаблону AIRA

30 октября 2026. Реализован [контракт D03-09](d03-09-contract.md), основа F04/F05/F11. По прямому ответу Никиты «Да, делаем базовый шаблон» [основной продуктовый документ](current-product-scope.md) дополнен решением: A4, обычный текст 11 пт, три уровня заголовков и два вида списков. D03-08 предварительно сохранён локальным коммитом **32e7bc5** с разрешения пользователя.

## Что реализовано

Чистый модуль `ara.docx_package.creation` создаёт новый DOCX в памяти. Frozen/slotted NewParagraph задаёт текст и стиль; CreationLimits ограничивает ресурсы; create_docx возвращает проверенные bytes. Пустой ввод даёт один пустой редактируемый абзац без примера или служебного текста. Импортированные файлы этот модуль не переписывает.

Шаблон версии 1: A4, поля 20 мм, Arial 11 пт, межстрочный интервал 1,15, чёрный текст. Title 22 пт, Heading1/2/3 — 16/13/11 пт с настоящими paragraph styles и outline levels. Заголовки удерживаются со следующим абзацем, оформление основано на интервалах, без декоративных линий/титульной страницы. Lists — настоящие Word numbering definitions; соседние numbered-абзацы продолжают последовательность, новый список после другого стиля начинается с 1. Маркеры не подмешиваются в пользовательский текст.

Unicode, пробелы и XML-литералы сохраняются буквально. LF/TAB записываются как w:br/w:tab; пустой текст остаётся редактируемым w:t. Неподдерживаемые XML-символы, lone surrogates и CR/CRLF отклоняются без нормализации; новый абзац задаётся отдельной записью. DTO и лимиты перепроверяются после обхода frozen. Repr и безопасные ошибки не выводят текст.

Семь частей OPC, только внутренние связи, без имён/дат пользователя, шаблонов по внешнему URL, макросов, комментариев, отслеживания изменений или AIRA-замечаний. Фиксированные ZIP timestamps и порядок частей дают одинаковые bytes для одинакового ввода на одном runtime. Перед возвратом выполняется прежняя проекция с нижними package/projection limits. Новый файл совместим с прежним механизмом диапазонных правок и session Undo/Redo; нетронутые части сохраняются.

## Визуальная проверка

Через новый API созданы два synthetic QA-файла в `.runtime/d03-09-qa` на bundled Python runtime. Оба повторно открылись через существующий project_docx и независимый python-docx; порядок/текст совпали, unprojected content отсутствует. Две генерации каждого файла дали одинаковые bytes. Python-docx и рендерер использовались только для QA, в зависимости приложения не добавлялись.

- `blank.docx`: **2776 bytes**, SHA256 `68fc69cddf2baafcfac74a7a5d530c13c20951e7293c32dd368fea1c14a6f682`, один пустой абзац.
- `template-preview.docx`: **4850 bytes**, SHA256 `d07e81be64ff6224a91141e8af88d7db82dabcab34be80c4528838788c907537`, 31 абзац.

Bundled LibreOffice через documents/render_docx.py: пустой документ — **одна страница**, пример — **две страницы**. Все три PNG просмотрены: читаемые заголовки и обычный текст, корректные маркеры и перезапуск нумерации, ровные отступы, разрыв строки и табуляция, без обрезаний/наложений или лишних пустых страниц. Контроль `generation-check.json`, PNG/PDF в `blank-render` и `template-render`, логи рендера. Содержательный пример — synthetic QA, не утверждённые требования продукта и не автоматически добавляемый учебный документ.

Microsoft Word на целевых Windows/macOS не запускался. Рендер LibreOffice и проверка XML не выдаются за полную проверку во всех версиях Word.

## Границы и окружение

Прямая разработка на Sol 6.1 High, без субагентов. API работает без файлов, сети, секретов, БД, процессов и логирования; инертность проверена отдельным процессом. Старые DOCX-модули, HTTP/storage/БД/редактор, dependencies, runner/tasks/progress, авторизация и квота не менялись. Чужие dirty-файлы сохранены, архив/output/.artifact-build не использовались.

Снимок `.runtime/d03-09-final-runtime.json` совпал с `d03-09-start-runtime.json`: основная V8/колонки/счётчики неизменны, ara_test пуста, временных ara_check_* осталось 0. PostgreSQL штатно остановлен с сохранением данных. В этой задаче нет HTTP/UI создания документа, сохранения его в БД или новых операций редактора. Списки в генераторе одноуровневые; inline rich text, таблицы/изображения и многоуровневые списки — дальнейшая работа. Следующая задача не запускалась.
