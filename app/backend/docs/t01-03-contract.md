# T01-03: создание и чтение документа

Уточнение спецификации перед Ralph. Добавляем три HTTP-маршрута, первую версию, ограниченное разбиение Markdown и явный локальный запуск. Следующие версии, GET /me, настоящий вход, ML, UI, интеграции и изменение миграций сюда не входят.

## Сборка приложения и пользователь

`ara.documents.runtime.DocumentRuntime(*, engine, user_id, project_id, mode)` — неизменяемый серверный контекст с SQLAlchemy Engine и UUID. Допустим только `mode='local'`; другое значение даёт безопасный `ConfigurationError`. Параметры обязательны, не брать их из HTTP. Конструирование runtime не открывает БД и не читает конфигурацию.

`ara.app.create_app(*, document_runtime=None)`: без runtime сохраняется прежний автономный `/health`; в этой ветке не импортируются DB-модули. С явным runtime добавляются три маршрута. Роутер импортируется только в этой ветке; фабрика не читает конфигурацию, не подключается к БД и не применяет миграции. Переданный engine принадлежит вызывающему коду, приложение не должно им управлять глобально. Каждая операция проверяет в БД `Project.id == runtime.project_id` и `Project.owner_id == runtime.user_id`.

Локальный API помечен заголовком `X-ARA-Auth-Mode: local-dev` и описанием OpenAPI. Это общий тестовый пользователь, не настоящая авторизация. Не добавлять выбор пользователя через заголовки, query или body.

`ara.local.create_local_app()` — отдельная явно вызываемая фабрика для ручного локального запуска. Она требует `ARA_ENVIRONMENT=local`, загружает существующие DatabaseSettings через load_settings(), создаёт engine и DocumentRuntime. В lifespan явно создаёт при необходимости синтетические User/Project с постоянными UUID `00000000-0000-4000-8000-000000000001` и `00000000-0000-4000-8000-000000000002`, проект `Local development`. Повторный запуск не дублирует их; если проект с этим ID принадлежит другому пользователю, остановиться, не менять владельца. При shutdown освобождает собственный engine. Миграции автоматически не запускаются. Импорт модуля инертен. Другие/отсутствующие значения ARA_ENVIRONMENT отклоняются до чтения настроек/БД. Команда разработки слушает только 127.0.0.1.

## HTTP-контракт

Все UUID и created_at сериализуются строками; created_at содержит timezone. Document summary: `id`, `title`, `current_version_id`, `created_at`. Для сохранённого документа current_version_id всегда задан.

| Маршрут | Поведение |
|---|---|
| POST /documents | Body содержит только title и content_markdown. 201 + Document summary. |
| GET /documents | 200, `{"items":[summary,...]}` только для своего server-owned проекта. Сортировка created_at DESC, id DESC. limit: 1..100, default 50; offset >=0, default 0. |
| GET /documents/{document_id}/versions/{version_id} | 200 с `id`, `document_id`, `parent_version_id`, `content_markdown`, `blocks`, `provenance`, `import_omissions`, `created_at`. Первая версия имеет parent_version_id=null. |

Вход: title — строка 1..200 символов, content_markdown — строка 1..1_000_000 символов. Пробельные-only значения, NUL, невалидный Unicode, нестроковые значения и любые лишние поля → 422. strip используется только для проверки непустоты: хранить обе исходные строки дословно. Ограничения длины — технические границы первого локального API.

Owner/user/project, version IDs, blocks и provenance назначает сервер. Переданные вместо них body-поля отклоняются; одноимённые заголовки/query не меняют доступ. Заголовок клиента X-Request-ID также не является идентификатором пользователя.

Ошибки — плоский JSON `code`, `message`, `retryable`, `request_id`. Сервер создаёт request_id; не возвращает SQL, DSN, traceback, входной документ или содержимое чужих записей. Неправильный запрос → 422 / validation_error / false. Неизвестная, недоступная или не соответствующая документу версия → одинаковые 404 / not_found / false. Несоответствующий пользователю проект runtime также не даёт доступа (404). OperationalError БД → 503 / storage_unavailable / true; другая ошибка сохранения → 500 / storage_error / false, с откатом. Сообщение 404 одинаково для отсутствия и недоступности; request_id закономерно различается.

## Сохранение

Одна транзакция: Document(current=NULL) → первая DocumentVersion → установка current_version_id → один commit. При ошибке любого шага в БД не остаётся ни документа, ни версии. До успешного commit не возвращать 201. Не менять ранее созданные версии, не использовать in-memory хранилище.

Версия сохраняет raw content_markdown, сгенерированные блоки, `provenance={"source":"manual"}`, `import_omissions=[]` для поддержанного примера. source_url=NULL: импорт пока отсутствует. Пользователь и проект должны существовать; обычный POST не создаёт владельцев или проекты.

## Ограниченное разбиение Markdown

`ara.documents.markdown.split_markdown(text)` → список блоков `{id, kind, text}`. Непустые уникальные непрозрачные ID, kind из действующего контракта. Для первого прохода поддержать ATX headings, абзацы, списки, pipe tables и fenced code (backticks/tilde). Сохранить строки дословно, включая CRLF, пустые строки и незавершающий newline; конкатенация block.text равна исходному тексту. Разделители допустимо присоединять к соседнему блоку.

Таблица и fenced code являются отдельными table/code, пустые строки внутри fence его не разрывают. Сгенерированные блоки сохраняются в версии и возвращаются с теми же ID при повторном чтении/пересоздании приложения. Неподдержанный/незавершённый структурный фрагмент можно сохранить kind=unsupported с указанием в import_omissions; не утверждать полную поддержку CommonMark. HTML не исполняется: API хранит и возвращает текст, не рендерит его. Никакого чтения URL или ML.

## Приёмка и разрешённые пути

Независимые тесты в tests/acceptance: реальная PostgreSQL, пересоздание engine/app, точное содержимое/блоки, недоверенные owner-поля, отсутствующие и чужие версии, безопасные ошибки, проверка атомарности через искусственный отказ записи версии в одноразовой тестовой БД. Существующие проверки T01-01/02 не ослабляются.

Разрешено: `src/ara/app.py`, `src/ara/documents/**`, `src/ara/local.py`, `tests/documents/**`. Запрещены изменения моделей/миграций, config/db, критериев, приёмки и runner. Команда проверки: `bash scripts/check.sh`. PostgreSQL уже запущен; обычное разрешение доступа к её сокету допустимо. Не переходить к T01-04.

## Подготовленный ручной запуск

После реализации: `bash scripts/postgres.sh start`, затем `bash scripts/dev.sh --documents`. Родительский launcher `scripts/serve_documents.py` явно выбирает локальную peer-БД ara_dev без пароля, задаёт ARA_ENVIRONMENT=local только дочернему процессу и слушает 127.0.0.1:8000 (порт можно задать ARA_PORT). Если уже указан нелокальный ARA_ENVIRONMENT, запуск отклоняется. Существующий ARA_DATABASE_URL эта специальная dev-команда не использует: она предназначена только для подготовленной ara_dev. PostgreSQL и миграции автоматически не запускаются. Без --documents команда по-прежнему запускает автономный health-only API.
