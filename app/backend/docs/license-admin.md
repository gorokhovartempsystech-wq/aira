# ADMIN01–ADMIN03 — закрытая панель лицензий

14 ноября 2026. Основание: Никита выбрал закрытую ссылку с отдельным входом,
доступную с любого компьютера. Продуктовое решение записано в current-product-scope.md.

## Границы

ADMIN01: отдельный серверный модуль `ara.license_admin`, без изменений публичного
API лицензий или установщиков. ADMIN02: вход, форма выдачи, список с постраничной
загрузкой, копирование и отключение. ADMIN03: отдельный loopback-сервис, HTTPS через
существующий Caddy, проверка, PR и инструкция оператору. Существующие секреты,
лицензии, привязки и сроки сохраняются. Код не продлевает и не переносит лицензии.

Путь `/license-admin/` не является секретом: доступ к данным и действиям требует
действующей серверной сессии. Публичная страница скачивания не получает ссылку
на панель. Администраторская учётная запись не является аккаунтом пользователя AIRA.

## Ключ и безопасный повтор

Браузер генерирует 128 случайных бит через Web Crypto и UUID операции. Ключ имеет
прежний формат AIRA-xxxxxxxx-xxxxxxxx-xxxxxxxx-xxxxxxxx. Только HTTPS передаёт его
серверу; в PostgreSQL остаётся прежний HMAC отпечаток. Полного ключа нет в ответах
API, логах, URL, localStorage или журнале. После подтверждённой выдачи интерфейс
однократно показывает ключ из памяти страницы, даёт скопировать и очищает поле
при закрытии окна. Перезагрузка страницы не позволяет восстановить полный ключ.

При потере ответа браузер хранит в памяти тот же UUID/ключ/параметры и повторяет
их. Транзакция создаёт одну лицензию, заметку и событие; повтор не меняет активацию,
срок или отключение. Отличающиеся параметры дают конфликт. Закрытие страницы
теряет не скопированный ключ: такой ключ можно отключить и выдать новый.

Срок задаётся целым числом дней (технический предел формы 1–36500). Начало срока —
первая активация, а не выдача. Отключение влияет на следующую серверную проверку,
не закрывает уже открытое приложение и не удаляет документы.

## Доступ и хранение

- Пароль проверяется scrypt N=32768, r=8, p=1 со случайной солью. SHA/HMAC cookie
  — случайный 256-bit токен; в БД хранится только его digest, срок сессии 4 часа.
- Cookie Secure, HttpOnly, SameSite=Strict, префикс __Host; выхода достаточно для
  отзыва сессии. Смена hash пароля или session key обесценивает старые сессии.
- Все API требуют same-origin заголовок; POST дополнительно проверяет Origin
  и отдельный CSRF, производный от токена. CORS не открывается. CSP и frame-ancestors
  запрещают сторонние скрипты и встраивание; ответы no-store.
- JSON максимум 4096 bytes, ожидание тела 5 секунд, не более четырёх операций
  одновременно. Login: 10 попыток на адрес и 100 глобально за окно 15 минут;
  счётчики сохраняются в PostgreSQL и переживают перезапуск.
- В отдельной SQL-схеме `aira_license_admin`: sessions, notes, audit, attempts.
  Публичные таблицы v1 не меняются. Выдача/отключение и аудит атомарны.
- Операторские настройки читаются только при явном `python -m ara.license_admin`:
  `AIRA_LICENSE_ADMIN_ORIGIN`, `AIRA_LICENSE_ADMIN_USERNAME`,
  `AIRA_LICENSE_ADMIN_PASSWORD_HASH`, `AIRA_LICENSE_ADMIN_SESSION_KEY`.
  Источник — ~/secrets.env. Пароль первого оператора хранится только в локальном
  ~/secrets.env как AIRA_LICENSE_ADMIN_PASSWORD; серверу передаётся его hash.

## Приёмка

Проверяются: отсутствие доступа без сессии; неверный пароль и лимиты; выход,
истечение и смена пароля; HTTPS/Origin/CSRF; лимиты и повторные поля JSON;
идемпотентная/конкурирующая выдача, rollback при сбое аудита; отсутствие открытых
секретов в данных; прежний срок первой активации и отказ отключённой лицензии;
список/пагинация; безопасное отображение заметок; вход/выдача/копирование/отключение
в браузере. Общая проверка — `bash scripts/check.sh`.
