## Реализовано

- POST /documents принимает title и content_markdown, возвращает 201 с идентификаторами документа и первой версии. Создание документа, версии и установка current_version_id завершаются одной транзакцией.
- GET /documents возвращает документы серверного проекта с ограниченной пагинацией и устойчивой сортировкой.
- GET /documents/{document_id}/versions/{version_id} возвращает точный Markdown, сохранённые блоки с постоянными ID, происхождение и сведения о неподдержанном фрагменте. Проверяются одновременно пользователь, проект, документ и версия.
- Ограниченный splitter выделяет заголовки, абзацы, списки, pipe-таблицы и fenced code; сохраняет CRLF, пустые строки и отсутствие завершающего newline. Незакрытый fence сохраняется как unsupported с отметкой в import_omissions.
- Ошибки валидации, отсутствия/недоступности и БД имеют безопасный плоский контракт без SQL, DSN или текста документа. Идентификаторы владельца из body не принимаются; заголовки и query не изменяют серверный контекст.
- Явная локальная фабрика создаёт синтетического пользователя и проект при startup, повторно использует их при следующем запуске, не меняет чужого владельца и освобождает свой engine. Режим local-dev указан в ответах и OpenAPI. Health-only фабрика остаётся независимой от конфигурации и библиотек БД.

Независимые проверки используют собственные одноразовые базы настоящей PostgreSQL и подтверждают:

- повторное чтение после пересоздания приложения и engine с теми же текстом, блоками и ID;
- одинаковый 404 для неизвестной/чужой версии и несовпадающей пары document/version, включая два документа одного проекта;
- отсутствие доступа к другому проекту того же пользователя и к проекту другого пользователя, устойчивость к подмене body/headers/query;
- полный rollback при искусственном PostgreSQL-trigger отказе вставки версии и обновления current_version_id;
- безопасные 422 и 503, инертность импортов, локальный режим и отсутствие автоматических миграций.

Read-only ревью слоя API не выявило замечаний. По ревью тестов добавлены две проверки: несовпадение document/version внутри одного проекта и фактическое сохранение table/code/heading через API. Затем вся общая проверка повторно прошла.

Ручной запуск `ARA_PORT=8013 bash scripts/dev.sh --documents` успешно открыл сервер на 127.0.0.1. HTTP GET /health, /documents и /openapi.json вернули 200 и заголовок local-dev. Список документов был пустым; ручная проверка не создавала документов в ara_dev. Сервер штатно остановлен с успешным shutdown.

PostgreSQL штатно остановлен, статус stopped; данные сохранены. Перед следующим запуском API или тестов выполнить `bash scripts/postgres.sh start`.
