# D02-06 — результат хранения и восстановления DOCX

29 октября 2026. Реализован [контракт D02-06](d02-06-contract.md), часть F05/F11/F12 [текущего объёма](current-product-scope.md). **Независимый `bash scripts/check.sh`: 1230 тестов и 24 подтеста проходят**, Ruff и форматирование проходят. Исходный DOCX и его текущий черновик сохраняются в PostgreSQL без преобразования в Markdown. Это сервисный слой; HTTP, интерфейс и таймер автосохранения ещё не подключены.

## Поведение

`ara.docx_documents` предоставляет `import_docx`, `get_docx`, `list_docx` и `save_docx`. Импорт проверяет пакет и его текстовую проекцию с фиксированными ограничениями. Сохраняются точные bytes оригинала и текущего файла, их SHA-256, название, ревизия хранения и даты. Полученные DTO неизменяемы и отделены от ORM-сессии. После завершения операции вызывающий код продолжает владеть переданным engine.

ID документа служит ключом повтора импорта. Повтор с тем же названием и исходником возвращает последний черновик, сохраняя сделанные правки. Другой исходник или название для занятого доступного ID дают конфликт. Чужой проект или документ остаются недоступны с общей ошибкой 404. Параллельные первые импорты создают одну запись.

Сохранение требует текущую ревизию хранения: устаревший запрос получает конфликт и не затирает свежую версию. Даже сохранение тех же bytes с актуальной ревизией увеличивает её один раз. Оригинал, название и дата создания не меняются. Ревизия хранения отделена от ревизии `DocxSession`: заново открытая сессия начинается с нуля, без истории отмен и без несохранённых изменений. Подтверждение `mark_saved` остаётся обязанностью вызывающего кода после успешной записи.

Владение проектом проверяется под блокировкой; затем блокируется строка документа. Чтение, повтор импорта и сохранение проверяют целостность сохранённых файлов, хешей и метаданных. Повреждённые данные дают безопасную ошибку хранения, без автоматического исправления. Список использует ограниченную пагинацию и стабильный порядок, читает только метаданные и размер файла, не загружая DOCX.

Ответ подготавливается до commit. Ошибка до commit откатывает транзакцию. При потере подтверждения уже выполненного commit запись может сохраниться: состояние нужно перечитать, а не автоматически компенсировать. Импорт модулей не читает секреты и не выполняет I/O; ошибки не раскрывают содержимое документов или детали SQL.

Миграция `0006_docx_documents` добавляет одну таблицу с ограничениями целостности и один индекс. Существующие модели, кроме добавления нового класса, старые миграции, сервисы, DOCX-модули и ML-контракты не изменены.
