# D03-05 — восстановление незавершённой правки

30 октября 2026. Одна задача F05/F12 после D03-04. По запросу «Давай дальше тогда разрабатывать» продолжаем прямо здесь на Sol 6.1 High. Незавершённый span и ключ неподтверждённой операции сохраняются отдельно от DOCX в локальном PostgreSQL и возвращаются после явного открытия документа. Последний документ при старте не открывать. Автоматический экспорт/применение текста раз в две минуты остаётся отдельной задачей.

## Хранилище и HTTP

Миграция 0008_docx_edit_drafts после 0007 добавляет только docx_edit_drafts: document_id UUID PK FK docx_documents.id без cascade, token UUID NOT NULL, payload JSONB NOT NULL с именованной проверкой jsonb_typeof(payload)='object', updated_at TIMESTAMPTZ NOT NULL clock_timestamp(). Новая ORM DocxEditDraft. Содержимое payload — ровно edit (прежний TextEditRequest со строковой ревизией) и operation_id (canonical UUID string или null), оба обязательны. При чтении валидировать payload; повреждение — безопасный 500, не выдавать за пустой черновик. Копия не меняет original/current/revision DOCX, receipts анализа/редактирования и старые таблицы.

Только явный DocumentRuntime; GET/PUT/DELETE `/docx-documents/{document_id}/draft`, без query. UUID пути прежний HttpUUID. GET 200 `{document_id,draft:null|{token,edit,operation_id,updated_at}}`. PUT JSON ровно expected_token (canonical UUID string или null), token (новый canonical UUID string, не равный expected_token), edit, operation_id. Ответ — тот же envelope с подтверждённой копией. DELETE JSON ровно expected_token canonical UUID string; 204 после commit. Все успешные ответы no-store.

Проверять Project owner и scope документа раньше чтения копии. PUT/DELETE блокируют тот же doc row FOR UPDATE, включая случай отсутствующей копии. GET FOR SHARE. Первое создание требует expected_token=null. Обновление требует текущий token; другой token — 409 draft_conflict, `Document draft has changed`. Повтор PUT с тем же текущим token и payload возвращает прежний snapshot без изменения updated_at, даже если ожидаемый token уже старый. Это повтор последней записи копии, не долговечный журнал всех попыток. Тот же token с другими данными — конфликт. DELETE сравнивает expected_token, отсутствующая копия возвращает 204; устаревший DELETE не удаляет чужое новое содержимое. Не восстанавливать удалённую копию при позднем PUT с ненулевым expected_token. Все изменения одной транзакцией, snapshot до commit, безопасные ошибки shared _session, потерю ACK обрабатывать повтором того же запроса. Сохранение копии разрешено на старой ревизии DOCX: она нужна для восстановления текста, а apply сохраняет прежний CAS.

PUT/DELETE: строгий UTF8 JSON, запрет extra/duplicate keys/NaN/Infinity/coercion, прежние ограничения TextEditRequest. Content-Type application/json с необязательным charset=utf-8, Content-Encoding identity; дубли media/encoding/length и length+transfer — 422. Bounded stream **2 MiB**, ранний/фактический перебор 413 draft_request_too_large, `Document draft request exceeds a technical limit`; неверный MIME/encoding 415 unsupported_media_type; обрыв/несовпадение длины 422 validation_error. Неограниченный auto-body не использовать. Decode/model/DB/response preparation в threadpool. Без I/O/secrets/network при импорте/создании factory. OpenAPI документирует модели и 404/409/413/415/422/500/503. Старые endpoints не менять.

## Интерфейс

Каждый ввод асинхронно сохраняет страховочную копию (это не применение правки в DOCX). Запросы одной копии сериализовать и объединять накопившийся ввод до последнего текста; поля можно менять во время записи. Держать подтверждённый token и неизменный неподтверждённый PUT, повторять его перед следующим snapshot. Показывать подтверждение/ошибку сохранения именно черновика, не выдавать его за сохранение DOCX. Весь введённый текст остаётся в памяти при ошибке; переполнение не обрезать. Два окна используют CAS: проигравшее сохраняет свой текст и сообщает о конфликте, не перезаписывает чужую копию.

Перед POST text-edit сначала надёжно записать копию с точным operation_id/payload D03-04. Если checkpoint не подтверждён, POST не отправлять. После 200 удалить только свою копию по token; ошибка удаления не отменяет сохранённую правку и явно обозначается. При повторном ручном открытии документа GET draft восстанавливает текст и исходную строковую ревизию/anchor/expected text. operation_id восстанавливается вместе с **тем же** POST payload, режим readOnly/повтор D03-04; само открытие ничего не применяет. Если DOCX изменился, старый текст доступен для копирования/ручного решения, никакого auto-rebase. GET draft failure не трактовать как отсутствие: новый текст не должен тихо перезаписать неизвестную копию.

Подтверждённая отмена/переключение удаляет свою копию по CAS, ждёт уже отправленный PUT, чтобы поздний ответ не воскресил её. При конфликте копии разрешить закрыть собственный локальный текст после dialog, сохранив другую копию; при недоступном хранилище оставить текст и сообщение. Не обещать откат DOCX при закрытии неподтверждённой операции. beforeunload и dirty download guard сохраняются. Browser storage, внешние origin, автофикс, история, новые зависимости не добавляются.
