## 2. Public API и безопасные metadata

`driver.start_fixture_attempt(slot:SlotLease, identity:AttemptIdentity, budget:Budget, *, request:bytes, execution_spec:bytes, mode='success') -> WindowsAttempt`.

До admission: exact issued live E1 slot, exact C1A identity (UUID/run/attempt/worker, fence1), copied validated Budget и immutable bytes request1..8MiB/spec1..4KiB, closed E3 mode enum. Валидация и encode одного C1C run frame с SHA выполняются до создания процессов. Native clock читается явно при вызове, не при import. Требуется `budget.last_ns <= now < L <= D`, `D-now <= 300s`, `L-now <= 15s`; guard уже применён C1A, второй guard не вычитать. Invalid input даёт fixed `WindowsRuntimeError('validation_error')`, stale budget/clock/platform — соответствующую безопасную ошибку, без launch.

Factory резервирует единственную E4 запись, получает E3 holder **до OS setup**, создаёт полностью связанный attempt/actor state и выдаёт handle после попытки старта трёх workers. Она не ждёт `holder.start`, initial permit, armed или анализа. Единственный I/O до background startup — проверка slot/clock; validation/encode не включаются в обещание 50ms renew. После регистрации holder не теряется: обычная ошибка Thread.start фиксируется в handle и инициирует Stop/H; выдаётся управляемый failed attempt, а не голое исключение с потерянным cleanup. До admission ошибка не создаёт registry entry. Неизвестный результат Thread.start не повторять и не объявлять поток отсутствующим без доказательства; сохранить attempt и запретить новый.

`WindowsAttempt` factory-only, PID-bound, issued capability, safe repr, no copy/pickle/forged construction. Все public методы могут вызываться разными caller threads; они не исполняют E2 I/O/process polling. Повторный вызов start на том же объекте не предусмотрен, повтор factory при занятом registry — `runtime_busy` без новых threads/holder/процессов.

| Метод | Контракт |
|---|---|
| `view() -> AttemptView` | Frozen/slotted detached metadata без payload, native paths, PID/HANDLE и exception strings. Не делает SQL/native polling/clock reads и не является authority. |
| `candidate() -> bytes \| None` | Одна и та же immutable reply reference только после композиции §6 и свежей проверки local D/L/Stop/fault. Не запускает inference и не подтверждает B1/SQL. Clock failure вызывает H и возвращает None. |
| `renew(lease_ns:int) -> bool` | Только trusted caller после принятого SQL heartbeat ACK в будущем C1F. True означает receipt §4, не G ACK и не SQL success. False не разрешает caller считать lease продлённой. |
| `stop(reason='user') -> None` | Closed C1C reason enum, monotone/coalesced R; `protocol` также H. Invalid reason — validation_error без mutation. Никаких join/poll/wait/decode или ожидания write; signal holder вне metadata mutex. |
| `close(timeout=5.0) -> bool` | Explicit bounded shutdown/coordination по §7. Exact int/float, finite, 0..30, bool запрещён. Invalid timeout без mutation. True — собственные resources/threads завершены; caller slot и SQL не затрагиваются. |

AttemptView: `phase` (starting/running/stopping/closed/blocked), `stage` (None/loading_model/analyzing), `stop_requested`, `error_code`, `exit_kind` (None/clean/stopped/crashed), `exit_code` (signed32|None), `cleanup_confirmed`, `candidate_ready`, `permit_ready`, `resources_closed`, `fixture=True`. Последние четыре флага bool. `permit_ready` — initial full write был принят локально; история не отменяется поздним Stop, live authority не означает. `candidate_ready` — последнее наблюдение, метод candidate перепроверяет время. `resources_closed` — E3 finish_close=True + собственная I/O quiescence; без M/SQL proof. `cleanup_confirmed` определён отдельно в §6.

Fixed view errors: None/clock/lease/deadline/protocol/process/transport/shutdown_timeout. Clock/transport/protocol/process faults sticky; ordinary user/storage/shutdown Stop не обязан создавать H. Первый error сохраняется; H latch отдельно и никогда не сбрасывается. При одновременном deadline/lease expiry приоритет deadline. `shutdown_timeout` — отсутствие завершения к caller timeout, не доказательство process error; допускается заменить этим полем None, но не скрывать ранее обнаруженный fault. Public exception enum E1 не расширять.

## 3. Три владельца, bounded coordination и время

| Владелец | Единственные операции/ресурсы |
|---|---|
| Launch worker | E3 start/poll_process/finish_close и failed-setup reap. Хранит immutable последние process observations в state; только он вызывает process/Job native operations. |
| Control worker | control writer, его begin/poll/cancel/close/event wait. Initial permit и не более одного admitted renew command. |
| Data pump | request writer, armed/events/status readers, их begin/poll/cancel/close/events. Decoder/token state, один run frame и одна provisional reply. |
| Caller | metadata, renew mailbox/receipt, Stop latch + E3 request_stop, bounded joins. Ни process.poll, ни чужой I/O poll/close. |

Три workers создаются не более одного раза. Factory сначала стартует launch worker, затем control и pump, но все ждут отдельный **startup admission gate**: native setup разрешается только после нормального возврата всех трёх Thread.start. Ошибка закрывает gate навсегда и уведомляет уже начатые workers; поздно оживший thread также не начинает setup. Если launch worker действительно работает, он закрывает ещё не запущенный holder через свой finish_close; если его start имеет неизвестный исход и cleanup owner отсутствует, record остаётся blocked/closeFalse, без замещающего thread или caller polling. Never-started threads не join; неизвестный start не считать never-started по одному исключению. Это позволяет безопасно отказать даже при частичном запуске workers.

После admission control/pump ждут handoff или окончательный startup failure через Condition/Event и bounded wakeups. E3 channels публикуются одной неизменяемой записью **только после успешного start**; launch worker после публикации не использует эти endpoints. E2 connect setup уже завершён, I/O owner ещё не назначен. Каждый новый владелец делает первую submission сам. До публикации/при failed setup всеми созданными E3 resources занимается launch worker. Нельзя передать endpoint после его первой submission или передать failed-connect operation pump.

У каждого handoff ровно один outcome: published или failed, плюс отдельный published-before-Stop факт. Stop не отменяет обязанность принять/закрыть опубликованные endpoints на назначенных owners. При Thread.start failure до handoff launch worker оставляет каналы у себя и закрывает их после actual process proof; новые worker threads для cleanup не создаёт. Если native setup/create ещё не вернулся, оставшиеся workers могут ждать его исхода, но их число и очередь не растут.

Shared state под коротким metadata mutex: R/H/closing latches; один latest stage; immutable process snapshot; три done/quiescent bits; один current command/receipt cell; одна reply reference. Не хранить историю renew, stage events, frames или closures. Stop — OR-latch, не сообщения в queue. Mutex не охватывает clock/native IO, encode/decode, waits/joins, пользовательские callbacks/SQL. Native Stop signalling выполняется после записи latch и отпускания mutex; сигнал не держит permit receipt lock. E3 собственная краткая сериализация SetEvent/event close остаётся как есть. Это отсутствие ожидания анализа, а не hard real-time гарантия при остановке ОС/native API.

Signal отправляется при первом R и при повышении до H; повторный одинаковый Stop не создаёт work item. Failure holder.request_stop фиксируется как H/transport, сохраняет local Stop и будит существующих owners для cleanup; public stop не выдаёт raw native exception и не ждёт повторной успешной доставки. Независимые control EOF/последнее L и launch polling остаются страховкой, не превращаются в доказательство, что остановка уже произошла.

Один strong E4 registry record на процесс до успешного explicit close; потеря ссылки caller не делает attempt безопасно забытым. Нет ThreadPoolExecutor/unbounded Queue/Timer на каждый heartbeat/stop/close. Pending E2 registry cap64 остаётся дополнительной защитой. Unknown create/cancel/close не допускает следующий attempt. Workers, ещё владеющие pending, остаются живыми на своих loops; повтор close не создаёт reaper thread. Background normal completion может закрыть resources и закончить workers, но registry снимается только после проверенного close.

Один E4 WindowsClock допускает concurrent readings через его собственный mutex; E3 использует свой уже проверенный clock. При переупорядочивании публикации samples разных threads нельзя объявлять backward clock только потому, что более старый sample позже вошёл в metadata lock. Native backward/failure sticky внутри WindowsClock; actor проверяет свою последовательность. Общая observed-time watermark обновляется max, сроковые решения не используют значение меньше watermark. Перед новым write, обработкой данных, receipt и candidate — новое чтение clock вне metadata lock, затем короткая проверка state. Не переносить новый L из неподтверждённого receipt в общий live budget.

D неизменен, current accepted L monotone, ни wait/cleanup, ни renew не создаёт новых300s. Sleep-inclusive clock — authority; timed waits только будят. Каждая idle/native wait итерация <=100ms, control admission/receipt wait ограничен более коротким cutoff §4. После wake clock/Stop проверяются первыми. Latched Event исключается из wait set либо заменяется timed Condition wait: нельзя spin на permanently signalled Stop/completed operation. Не ждать чужой event или закрывать event, по которому другой поток ещё ждёт. Scheduling/native-call stall не превращать в обещание real-time50ms; независимый G сохраняет enforcement последнего принятого разрешения.

## 4. Initial permit и renew: receipt вместо queue ACK

Control owner первым отправляет permit seq0 с исходными D/L. Для него cutoff=`min(dispatch_time+50ms, initial L, D)`; время setup не возобновляет L. Initial receipt устанавливается самим control owner после полного completion и свежего clock/Stop check до cutoff. Он не расширяет L. Pump может читать startup channels, но request отправляет лишь после initial receipt **и** armed+EOF. Initial timeout/short/error — H; до initial receipt публичный renew возвращает False без admission. Это не очередь heartbeat во время запуска.

Renew scalar: exact int signed63, current L <= new L <= D; now < new L <= now+15s, old L ещё жив. Equal L допустим как у G, но не увеличивает budget. Invalid scalar/bounds — validation_error без отправки или Stop. Expiry по свежему clock сначала фиксирует ordinary Stop(lease/deadline), возвращает False, не оживляет старое L. Clock failure — H/False. При stopped/closing/terminal, неготовом initial permit или занятом command cell — False без native write, без нового fault и без очереди. Invalid scalar type проверяется даже для закрытого attempt; временные bounds проверяются лишь при live admission.

Один admitted command содержит immutable token, new L, old accepted L, фиксированный D, admitted-time и cutoff=`min(admitted-time+50ms, old L, D)`. Другие renew не ждут, пока он освободится. Mailbox/condition notification **не является ACK**. Все попытки проверять receipt относятся к этому token; переиспользовать stale receipt в следующем command запрещено.

1. Control worker получает command, проверяет cutoff/Stop/current generation, кодирует вне mutex один permit и резервирует seq/caps до native submission. После повторного clock/Stop check выполняет ровно одну begin_write всего frame (<=4KiB body +4byte header). Нет split/retry control frame: positive short completion также H. Для больших request/result partial writes обрабатываются иначе (§5).
2. Immediate full completion и pending→full completion идут через один путь. Owner проверяет результат, читает clock, публикует **provisional receipt** только если до cutoff/old L/D, нет R/H/closing и command по-прежнему current. Pending write не освобождает command cell.
3. Caller renew ждёт Condition только до того же cutoff, затем с новым clock под mutex принимает receipt при тех же условиях. **Этот переход — локальная точка подтверждения renew:** обновить accepted L на new L, отметить command accepted и вернуть True. До него текущим остаётся old L, даже если G уже получил bytes. Clear command делает owner после принятого/отклонённого outcome; новый caller может кратко получить False/busy, очереди нет.
4. Если receipt ещё pending при наблюдении cutoff, caller **или любой работающий actor** отклоняет его и ставит H/transport, Stop и сигнал hard-abort; accepted L не меняется. Старый L/D expiry, наступивший до admission, остаётся ordinary expiry; истёкший admitted write/receipt — delivery failure/H. Нельзя вернуть True только по историческому successful write, если caller проснулся поздно. Если caller не возобновился вовсе, control owner сам инвалидирует receipt по cutoff. Ordinary Stop атомарно завершает ещё pending command как cancelled вместе с R latch: если эта отмена выиграла раньше наблюдения timeout, возврат False без искусственного H лишь за cancellation. Позднее пробуждение не превращает cancelled command в timed-out. Если timeout/fault уже зафиксирован, Stop его не стирает. Actor, одновременно обнаруживший expired pending receipt и old L, сначала отклоняет receipt как delivery timeout, затем применяет budget expiry.
5. Late full completion после Stop/timeout учитывается как доставленные bytes, но не возрождает receipt/L/candidate. Уже принятый receipt может предшествовать конкурентному Stop: True описывает свой линейный момент, Stop сразу отзывает дальнейшую работу. Защитить durable публикацию обязан C1A/B, а не boolean renew.

Accepted receipt завершает delivery timer: owner сначала различает accepted/rejected/pending outcome, затем применяет cutoff только к pending. Пробуждение owner после50ms не отменяет своевременное caller acceptance и не создаёт ложный H; дальнейшая expiry проверяет уже новый accepted L. Аналогично initial receipt после принятия больше не имеет активного50ms timer. Этот порядок проверяется отдельным barrier test.

Delivery reservation ограничивает512frames/1MiB body в соответствии с C1C; seq начинается0, резервируется ровно один номер при допуске native submission. Считать полные frame reservations консервативно даже при partial/unknown delivery; отдельно можно хранить scalar delivered bytes/full completions без payload. Caps проверять **до** begin_write. Full completion после Stop всё равно учитывается, но следующего permit не будет. Неудача до submission после reservation также terminal/H, поэтому дырка seq никогда не отправляется следующим frame. Busy/rejected-before-admission renew не расходует seq. Не обходить caps на repeated equal-L renew.

Stop использует R/H event и закрытие control своим owner; **новый stop frame E4 не отправляет**. Это разрешённый C1E out-of-band путь, не изменение C1C: G уже понимает event/EOF и stop frame от других допустимых senders. Таким образом Stop не стоит за pending permit и не вписывается в середину его prefix. Owner отменяет pending, ждёт terminal completion, затем закрывает writer. Caller не вызывает чужой poll/close, не сбрасывает event. CancelIoEx success/ERROR_NOT_FOUND не ACK, normal completion после cancel допустим только как cleanup. При partial/unknown native error H, независимо от количества bytes.

Natural finish control допускается без R только после valid status+EOF, G exit0/count0 и полного data terminal proof. Затем закрыть writer, сохранить последний L для candidate checks; больше не продлевать завершённый attempt. Early control EOF нельзя использовать как «пора заканчивать», пока G ещё должен прислать доказательство cleanup.

## 5. Pump: request, результат и EOF

Pump владеет четырьмя E2 endpoints. Armed проверяется frozen E3 TokenReader: exact token+EOF, никакого GO/request по одному prefix/token без EOF. После initial receipt и armed+EOF — ещё clock/Stop check, затем ровно один C1C run frame seq0. Каждая write submission <=64KiB, positive partial completion сдвигает offset, нет повторной отправки уже записанного prefix. После полного completion закрыть request writer; `request_complete=True` лишь после successful close (EOF нашему M). FlushFileBuffers не использовать. Early broken pipe, zero progress, incomplete send без принятого Stop — transport/H.

Одновременно читать events/status, по одному pending на endpoint; это не sequential write-entire-request/read-entire-response. Per turn <=64KiB на lane и <=256KiB суммарно, сначала clock/latches/latest process observation; bounded wait set<=32 handles. Armed reader после EOF больше не ждёт; operation event извлекается из wait set перед terminal poll/close. Process polling принадлежит launch worker, pump читает только immutable snapshot. Нет readall/communicate, dynamic workers, callbacks под mutex или передачи native handles UI.

Events через frozen C1C decoder: exact binding/seq/spec SHA/ready→loading_model→analyzing→result, caps/hash/base64 и обязательный EOF. Valid error frame — `process`, без candidate; не превращать error+exit0 в success. Status через отдельный strict decoder: один closed+EOF. Partial/trailing/duplicate/wrong binding/caps/sequence — H/protocol; malformed decoder не оживлять. Не делать candidate в callback на result/closed до остальных EOF/proofs.

Во время обычной остановки отсутствие/допустимый incomplete prefix отменённого armed/request/events не создаёт H само по себе; incomplete result отбрасывается. Уже обнаруженный malformed/fault не стирается. Status по возможности дочитывается строго для cleanup evidence: cancelled/partial status не становится closed. Late extra bytes на нормальном пути всегда fault. После Stop результат никогда не кандидат, даже если последующие EOF/exit оказались чистыми.

Tail window начинается по первому valid closed frame либо первому observed G exit, что раньше; monotone cutoff=`start+2s`, overflow→H. Не продлевать при следующих chunks/status/polls. Для **успеха** требуется уложиться также в live D/L. После ordinary Stop/expiry допускается дочитать cleanup/status до этого же2s cutoff без выдачи candidate/нового budget. Если closed/exit ещё нет, работают обычные D/L, R/H и E3 kill escalation; наличие provisional result не запускает новый бесконечный tail timer.

По истечении drain без необходимых EOF — fault/no candidate, отмена своих pending и очистка. Drain2s ограничивает получение пригодного evidence, **не разрешает освободить незавершённый native OVERLAPPED**. Pending cancellation/reap может удержать ресурсы дольше; тогда blocked/closeFalse. G смерть/known nonzero немедленно запрещает success, но оставшийся tail можно дочитать в существующем окне для безопасной диагностики без payload.

Память: один immutable run frame<=12MiB+header; ссылка на исходные request/spec отпускается после encode; frame после completion/cancel больше не удерживается state. На lane только один chunk/pending<=64KiB, один bounded C1C decoder frame, один latest stage. Result message/base64 не хранить вместе с reply дольше decoding; одна decoded reply<=4MiB, provisional и candidate — тот же reference. Bounded transient codec copies неизбежны, не обещать4MiB RSS. Ни request, ни result/diagnostics в логи/view/errors/queue/file. Повтор candidate не копирует reply и не вызывает decode снова.

## 6. Три независимых вида доказательства

`cleanup_confirmed=True` только при valid closed(clean/stopped/crashed, actual signed32 code, cleanup=True)+status EOF, actual G signalled/exit0, outer Job empty и known creation. Hard process/query fault или missing/untrusted status не компенсируются пустым Job. Это доверие к независимому G о M и отдельный retained G proof, **не SQL ACK**. Отдельный data protocol fault может сосуществовать с доказанным физическим завершением, но не с candidate. `exit_kind/code` — только decoded status после его EOF; G exit хранится отдельно во внутреннем snapshot, не подменяет M code.

Transport candidate требует одновременно:

1. Initial receipt, armed exact+EOF и полный run write+successful request close.
2. Valid ready/stages/result с exact spec digest и events EOF, reply1..4MiB; no error/tail.
3. Valid closed(**clean,0,True**) и status EOF.
4. E3 observation creation=created, process_exited=True, G exit_code=0, job_empty=True, hard_fault=False; holder resources_closed само по себе ничего из этого не заменяет.
5. Все обязательные channels достигли terminal EOF до tail cutoff; R/H/fault/closing нет, **последний accepted** L и D ещё живы. Непринятый permit receipt не даёт дополнительных миллисекунд.

После сборки evidence можно закрывать собственные endpoints/resources; закрытие с ошибкой вызывает H и отзывает выдачу. Candidate не обязан ждать вызова caller.close, но не выдаётся при известном pending fault/cleanup error. `candidate()` проверяет state/clock каждый раз; повтор — те же bytes. `view.candidate_ready` не обход проверки. Поздний Stop/expiry/fault отзывает будущие выдачи; уже возвращённые bytes нельзя «забрать» у C1F, поэтому C1A/B должны самостоятельно принять child_closed/permit и проверить SQL fences. E4 не вызывает control arbiter/publisher и не ставит run=completed.

`resources_closed=True`, `cleanup_confirmed=True`, `candidate()!=None`, `close()==True` — разные факты. Например, failed G create без M может полностью закрыть свои ресурсы и вернуть closeTrue, но cleanup_confirmed=False/нет status/нет candidate. G crash при count0 также не создаёт M proof. Stopped/nonzero M может иметь cleanup_confirmed=True, но result запрещён. Unknown create всегда closeFalse независимо от free slot/count0.

## 7. Завершение workers и close

Launch worker вызывает `poll_process` регулярно (bounded wake<=100ms) после возврата start и публикует observation. Из pump/control H/R передаётся через thread-safe holder.request_stop. Launch owner не применяет initial L как текущую lease: E4 проверяет accepted L, а G — свой received permit; E3 start уже ограничил исходный bootstrap. E3 ordinary Stop→outer escalation после5s и H→terminate остаются неизменны. Пока start/native create не вернулся, caller не освобождает holder/Job/буферы и не делает foreign termination.

При natural terminal/Stop/fault control/pump каждый закрывает только свои endpoints, отменяет/reap pending на исходном owner и публикует quiescent. Quiescent требует no pending и успешного close всех собственных endpoints; «loop вышел», cancel requested или истёк timeout недостаточны. На pending сохраняется исходный worker, bounded waits и retention; ошибку CloseHandle не повторять по старому integer. Sticky close failure остаётся blocked, даже если worker уже может выйти без active pending.

Launch owner начинает finish_close только когда handoff failed (всё его) либо оба чужих owners подтвердили quiescence. E3 finish_close сам перепроверяет process/job/endpoint состояния; False не заменять True по metadata. Failed-setup orphan pending reap делает launch owner. При успехе publish resources_closed, закончить launch loop. При unknown in-flight create/uncertain pending retained owner остаётся; никакого emergency abandonment как successful close. Все workers имеют собственные done acknowledgements; public close дополнительно проверяет фактическое завершение Thread, не только флаг.

`close(timeout)` ставит один closing latch и запрещает новые renew/candidate. Если до этого уже есть полная natural terminal композиция §6 и нет ошибки, Stop не добавляется только ради закрытия handles. Иначе запрашивается ordinary shutdown Stop (уже H остаётся H). Pending unaccepted renew инвалидируется; successful historical receipt не удаляется. Одно общее caller wait-deadline на все joins, а не по timeout каждому thread. `time.monotonic` допустим только для этого локального wait budget, никогда для D/L/permit/candidate; приостановленная ОС/зависший native вызов не обещают realtime-return. timeout0 — poll plus инициирование shutdown, без ожидания.

True только после successful E3 finish_close, quiescence каждого owner и фактического конца всех запущенных workers; registry снят, payload/decoder state discarded. Caller slot не освобождается, owner не закрывается. Repeated closeTrue безопасен/no native repeat. False по timeout сохраняет strong record/handles/pending/owners, закрытие продолжается теми же workers; retry только снова ждёт. Timeout сам по себе не подтверждает отмену и не запускает ещё один kill/worker; process escalation остаётся за E3. При неизвестном Thread.start required proof тоже отсутствует.

Phase starting — до завершения request; running — request завершён, transport ещё не terminal; stopping — latched Stop/fault/close с известным продолжающимся cleanup. Closed — resources закрыты и workers завершены, без нерешённой unknown cleanup ветки; возможно с error и без candidate (в том числе known failed/no-create, где M не было). Blocked — unknown creation/missing M proof после созданного terminal G, sticky close error либо незавершение к close timeout. Blocked из-за timeout может перейти в closed после настоящего proof; payload после Stop/fault не восстанавливается. При missing M proof blocked может сохраниться даже после closeTrue: собственные ресурсы закрыты, но доказательство об M не появилось. Metadata snapshot может отставать, не участвует в разрешении публикации.

После потери S автоматический Windows restart по-прежнему **не готов**: C1F обязан иметь durable crash fence до create и собственный physical+SQL+I/O recovery gate. E4 не добавляет файл/DDL и не выводит recovery из empty Job, free slot, истечения lease или terminal SQL. После E4 запрещено подключать этот fixture driver к production scheduler до C1F. Реальный B1 adapter/weights — C2, reply E3 `b'fixture-response'` остаётся явной заглушкой.

## 8. Acceptance и порядок реализации

До source: новая acceptance, review её fixtures/collection, freeze local commit, настоящий red отсутствующего E4 driver. Старые tests неизменны. Portable acceptance должна управлять **реальными тремя Python threads** и детерминированными barriers/fake endpoints/clock: вызов из неверного owner обязан падать, а не быть разрешён заглушкой. Не доказывать concurrency тестом, последовательно вызывающим всё из одного thread. Timeout tests через управляемые события, не случайные короткие sleeps.

Обязательная portable matrix:

- Inert imports/без SQL, сети и секретов; exact hostile values/forged/copy/stale/foreign PID, payload-free repr/view/errors, limits до launch, detached identity/budget, second factory busy, strong retention после GC.
- Start paused before/inside create, Stop до handoff и после handoff, initial write до/после expiry, Thread.start failures на каждой позиции; no second worker/launch/owner reset, failed setup reap original owner. Зависший launch не мешает Stop latch и renew refusal/closeFalse.
- Initial full immediate/pending, short/zero/aborted/error/late completion; blocked request pump не удерживает control. Renew caller/owner/timeout barriers: receipt queued, bytes complete, receipt published, caller accept, Stop на каждой границе. No ACK по queue, no L update до acceptance, late caller и abandoned command, concurrent renew busy, no renew above pending, fixed D, equal-L/caps/seq и delivery после Stop. Backward clock vs reordered cross-thread samples различаются.
- Expiry/Stop при decode/большом request/result, no waits/native/codec под metadata mutex. Проверить watchdog/command deadline без caller activity; permanently signalled events не вызывают spin; registry/queue/thread count bounded при100 повторных Stop/renew/closeFalse.
- Каждый отсутствующий composite fact отдельно запрещает candidate: initial/armedEOF/requestEOF/ready/spec/result/eventsEOF/statusEOF/M code/G wait/G code/job empty/currentL/noStop. Тот же immutable reply reference на repeated candidate. Transport success не вызывает publisher/SQL/slot release; view/closed resources не выдаются за proof.
- Состязания tail/status/G exit: result+hang, error+exit0, missing/duplicate/trailing/partial/malformed frame, wrong binding/hash/sequence, flood/caps, both ordering EOF vs process observation.2s drain не продлевается bytes/повторным poll, но cancellation retention может длиться дольше. Ordinary cancelled prefix без ложного H; ранее выявленный H не исчезает.
- Owner-only cancellation/reap/wait-set lifetime: pending после close timeout, ERROR_NOT_FOUND, completion-after-cancel, failed CloseHandle/query; no reuse/double-close. finish_close ждёт чужую quiescence, а True не требует выдуманного M status при known failed create. Unknown всё ещё False. Общий timeout трёх joins, repeated close и all workers actually finished, source slot остаётся caller-owned.

Native suite Windows отдельно: success exchange/requestEOF/result identity/actual cleanup, все closed E3 fixture modes, Stop до GO/при backpressure/GIL-hang/result-hang, renew при blocked pump, malformed/tail wrappers, G death после доказанного M startup, slot held до caller release probe, wait/code259/signed NTSTATUS. Дополнить deferred E3 native gates: actual inheritance allowlist и reduced event rights/pipe READ_ATTRIBUTES, active-process-limit rejection descendant, incompatible enclosing Job без fallback,100 sequential attempts без роста process HANDLE/thread count. Test harness использует только свои retained capabilities; не OpenProcess по PID. Need snapshots до/после и controlled cleanup каждого native failure.

Физический suspend/resume и pre-return death stress остаются отдельными обязательными environment gates. Последний только disposable Windows VM по E3 §7, без лишнего Job HANDLE и без safety Job, меняющего last-close semantics; неизвестный outcome очищается внешней процедурой VM, не поиск/kill по имени. На Mac — явные skip/pending, не pass. Отсутствие native среды не отменяет portable tests, но весь Windows runtime принят не будет.

Targeted E1–E4/own, полный `bash scripts/check.sh`, read-only main V8 start/final, source/test hashes до/после gate, result и local commit. Не менять принятую модель ошибок или тестовые expectations задним числом ради зелёного прогона. Продолжить E4 на **Sol6.1 High**; после completed implementation следующий C1F требует отдельного архитектурного контракта на Astra6 High (durable recovery/SQL lifecycle), не молчаливого production wiring. Самостоятельный остаток после этого design — **27–42 цикла**, E4 implementation ещё не вычтен.
