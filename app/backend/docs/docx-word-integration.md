# Ordinary Word checks in the owned desktop

The explicit `word_fixture` analysis mode uses `WordSnapshot` and the fixed
`docx-analysis/final-visible-word-package-v1` source policy. It is an opt-in fixture mode:
its result says that real inference did not run. Existing desktop modes/defaults remain.
No model package, native Windows composition or final GUI is supplied by this integration.

`ara.docx_analysis.word_review` exposes `prepare_word_review` and `validate_word_reply`.
Request/result `docx-review/5` and presentation `docx-review-view/5` retain the complete
style-list and note context, with literal evidence independently mapped against original
XML. The fifth exact wire/profile pair uses the existing fixture2 context validator and
native review2 transport. Generated markers contribute to work limits but cannot be quoted
as literal evidence. Unsupported content refuses without enqueuing or adaptive fallback.

Storage format1 rederives the fixed original source policy. Historical retry preserves the
source bytes, revision and meaning of all five accepted profiles; selecting a newer desktop
mode does not upgrade saved results. Nested HTTP metadata enumerates all previous versions
and version5; the new standalone schemas retain closed shapes and all previous bounds.

The new fixed source uses the existing persisted preferences and full-context presentation.
A hide can survive a proven distant text edit. A changed literal, ambiguous correspondence,
profile change or changed non-main source part cannot inherit it. Auxiliary theme/font/style
changes are therefore conservative barriers, even when a human sees no text change. Private
model provenance and hide keys do not appear in the public view.

Acceptance exercises six independent synthetic ordinary-template packages, original-byte
export, manual text edits with untouched auxiliary parts, and owned macOS Home/PostgreSQL/
license/HTTP check-hide-close-reopen-retry-show. A reopened desktop obtains a fresh online
license grant. Tests use a synthetic license transport and a plainly marked fixture model.
This is not public TLS deployment, native Word visual parity, complete DOCX support, release
packaging or validation of a real local model. Source boundaries are documented in
[the reader guide](docx-visible-word.md); final verification is in the cycle result.
