## Native preflight и передача C1D на Astra6 High

После законченного C1C выполнены только synthetic native probes, без model/DB/пользовательских файлов. Ignored `.runtime/d03-17c1d-probe.py`/`d03-17c1d-native-probe.json`:5/5 поздних регистраций kqueue NOTE_EXIT для unreaped child вернули событие; os.posix_spawn setsid=True работает, хотя отдельная Python константа POSIX_SPAWN_SETSID не экспортируется. Унаследованный flock удерживает slot после закрытия reference родителя и освобождается после естественного выхода child. Символ mach_continuous_time доступен; преобразование timebase/suspend пока не реализовано и не проверено.

Первый probe получил `PermissionError(EPERM)` при killpg после наблюдения завершения child; попытка завершилась ошибкой, не считается teardown gate. Сигнал не повторялся через другой syscall/утилиту, обходов approvals/sandbox нет. Безопасный повтор проверял только естественный exit и stdin EOF; все эти synthetic children завершились. Это **не automatic approval rejection** и не доказательство запрета остановки живого child.

В [первичном исходнике Apple XNU killpg1](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sig.c#L1612-L1624) обход группы исключает zombies, а отсутствие подходящих процессов может давать EPERM. Это правдоподобное объяснение наблюдения, **не** доказательство причины на установленной версии ядра. Нельзя blanket-ignore EPERM как cleanup success или автоматически объявить его permission blocker. Нужны разные доказательства для живого child и подтверждённого unreaped exit; сохранённый PID не authority.

Перед C1D implementation рекомендован **Astra6 High для точного native lifecycle/startup контракта**. Уточнить: signal/NOTE_EXIT/wait linearization с PID pin и указанными errno, fail-closed proof cleanup, startup barrier до engine import (C1C child ready — не guardian-armed ACK), точные FD ownership/EOF/leak правила, безопасный threads-only launcher и неизвестный guardian exit. Возможные дополнительные bootstrap сообщения/pipe не добавлять молча в frozen C1C protocol; отдельная версия/контракт при необходимости. По этим вопросам общий C1 design задаёт намерение, но ещё не содержит точной проверяемой схемы. После законченного native проекта вернуться на Sol6.1 High для C1D implementation. C1D source/acceptance не начаты; новый продуктовый ответ не требуется. Остановка автономной работы — на границе завершённых C1A/B/C для согласованной смены режима.
