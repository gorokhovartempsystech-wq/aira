## Что работает

При явном локальном DocumentRuntime доступны два метода:

- `GET /documents/{document_id}/draft`: текущий черновик или JSON null, если у доступного документа черновика ещё нет. Чтение ничего не создаёт.
- `PUT /documents/{document_id}/draft`: полный текст, base_version_id и expected_revision. Успех возвращает сохранённый снимок с document_id, base_version_id, revision, content_markdown и updated_at.

Пустой, незавершённый, Unicode-текст, CRLF и текст длиннее миллиона символов сохраняются точно. Ошибка формы запроса возвращает безопасный 422 до обращения к хранилищу. Поддерживаются UUID-строки, допустимые Python UUID; сервис получает UUID-объекты. Проверено точное прохождение больших JSON integer вплоть до успешного сохранения ревизии 9223372036854775807.

Маршруты напрямую вызывают существующие read_draft/save_draft. Доступ задаётся runtime сервера; клиент не может подменить его полями, заголовками или query-параметрами. Старый номер ревизии даёт 409, две конкурентные записи — один успех и один конфликт. Сбой хранения или commit возвращает безопасный 500/503 и не оставляет частичной записи. Ошибки имеют серверный request_id и local-dev заголовок.

OpenAPI описывает реальные запросы, nullable GET и error-envelope, включая 422 без отражения исходного input. FastAPI округляет большие числовые границы при построении схемы; локальная обёртка OpenAPI восстанавливает границы двух полей ревизии из Pydantic-моделей. Она не меняет чужие схемы, общие настройки FastAPI или проверку входных данных.

## Ограничения и продолжение

Существующий документ и его базовая версия по-прежнему обязательны. Создание нового пустого документа, редактор, таймер автосохранения, вкладки и сохранение версии перед анализом в D01-02 не входят. Реальная локальная модель, установщик, лицензия и DOCX остаются отдельной работой.

HTTP-режим local-dev использует синтетический локальный контекст и не является реализацией авторизации или активации продукта. Приложение без runtime сохраняет только health из продуктовых маршрутов. Код находится в локальном Git; публикация и GitHub remote не выполнялись. Следующая задача — отдельно определить создание пустого документа до первой сохранённой версии, затем подключать редактор.
