# D03-05 — восстановление незавершённой правки

30 октября 2026. Реализован [контракт D03-05](d03-05-contract.md), часть F05/F12 [текущего объёма](current-product-scope.md). После закрытия окна при явном открытии документа восстанавливаются подтверждённая копия текста и ключ неподтверждённой операции. Восстановление само не применяет текст в DOCX. Автоматическое применение правки раз в две минуты, вкладки и desktop-поставка остаются отдельными задачами.

## Реализация

Новая таблица docx_edit_drafts хранит одну копию на DOCX, UUID её состояния, edit payload и время. GET/PUT/DELETE `/docx-documents/{document_id}/draft` доступны только с прежним явным локальным runtime. Ownership/project/document проверяются до доступа к копии. PUT/DELETE блокируют общий с DOCX writers документ, но читают только его ID, без загрузки и разбора Word bytes.

PUT требует ожидаемый UUID текущей копии и новый UUID. Повтор последнего PUT с тем же UUID и payload возвращает прежний snapshot без повторной записи. Изменение данных под прежним UUID и устаревшая запись получают 409. DELETE сравнивает UUID; повтор удаления отсутствующей копии безопасен, чужая более свежая копия не удаляется. Поздний PUT с ненулевым устаревшим expected_token не воскрешает удалённый черновик. Запись/удаление транзакционны; ответ появляется после commit.

JSON строгий, UTF8, не более 2 MiB bounded stream, без duplicate/extra keys и NaN/Infinity. Прежний edit schema сохраняет строковую BIGINT-ревизию. Проверяются MIME/encoding/длины/дубли headers/обрыв. Decode, validation, DB и подготовка ответа идут в threadpool. Непредставимые в PostgreSQL JSONB NUL и одиночные UTF16-суррогаты отклоняются 422 до БД; исправленный текст можно отправить снова. Повреждённая сохранённая копия — 500, а не пустой результат. Ответы no-store, безопасные ошибки без текста/SQL. OpenAPI описывает все три метода.

В UI ввод создаёт отдельную страховочную копию: запросы сериализуются, накопившийся ввод объединяется до последнего текста. Неподтверждённый PUT повторяется с тем же UUID перед следующей копией. Пользователь видит подтверждение именно копии, а не изменения DOCX. Перед POST text-edit сначала сохраняется checkpoint с точным operation_id/payload D03-04; при сбое checkpoint POST не отправляется.

При открытии возвращаются исходные anchor/expected text/revision и введённый текст. Для неподтверждённого POST восстанавливаются readOnly и кнопка повтора с тем же ключом. Устаревшая копия не переносится автоматически на свежую ревизию. Ошибка GET не трактуется как отсутствие: правки блокируются до повторного открытия. Известный конфликт копий оставляет введённый текст; закрытие своей локальной правки сохраняет копию другого окна. Удаление своей копии ждёт отправленный PUT и использует CAS, чтобы поздняя запись её не воскресила. Подтверждённый POST остаётся успешным при сбое последующего удаления копии, с явным сообщением.

## Браузер

Собственная disposable БД, synthetic rich-source.docx. Ввод `Kitchen heating` получил подтверждение копии; после закрытия вкладки новое окно при ручном открытии восстановило текст с надписью «Восстановлен черновик». Исходный DOCX оставался прежним. Screenshot `.runtime/d03-05-qa/recovered.jpg`.

QA middleware заменил ответ успешного POST после реальной записи на 503. Перед закрытием в БД были ревизия 2, один receipt и копия с совпадающим operation_id. Новое окно восстановило именно неподтверждённую попытку; повтор подтвердил её без изменения ревизии/hash/размера/timestamp/receipt и удалил копию. Снимки `pending.json`, `retried.json`, `after-cancel.json` в `.runtime/d03-05-qa/`.

Отдельно потерян ACK самого PUT копии: текст остался в поле, следующий ввод повторил старый PUT и затем сохранил новое содержимое. В двух окнах восстановлена общая копия; первое записало новый текст, второе получило конфликт с сохранённым textarea. Подтверждённое закрытие второго окна не удалило копию первого. Затем первое удалило свою копию; последующее открытие не восстановило её, документ и единственный receipt не изменились.

При искусственной ошибке GET draft все 34 текстовых фрагмента стали недоступны для редактирования, сохранилось объяснение ошибки. После восстановления сервиса повторное открытие вернуло доступ. Скачанный DOCX — **48129 bytes**, SHA256 `6d199e32c709ce40d081c89f75c0b734b22813ec0d561e074045b9f839173f90`, 19 нетронутых частей совпали с исходником. Файл побайтово идентичен визуально проверенному экспорту D03-03, новый форматирующий движок не вводился. Контроль `export-check.json`. Microsoft Word не проверялся.

Native beforeunload в IAB не позволил подтвердить обычную перезагрузку инструментом; восстановление проверено настоящим закрытием вкладки и созданием новой. Установленное desktop-приложение и перезапуск ОС не проверялись. Тестовый сервер остановлен, созданная им база удалена, агентские вкладки закрыты.

## Оставшиеся границы

Восстанавливается подтверждённая сервером копия; ввод, запись которого ещё не завершилась или завершилась ошибкой, остаётся только в памяти окна. Поэтому интерфейс явно показывает сохранение и ошибку. Конфликтующий текст второго окна тоже удерживается в памяти для копирования и ручного решения. Одна копия на документ; истории копий нет. Новые абзацы/структурные изменения, undo/redo UI, таймер применения в DOCX, вкладки, реальная модель и установщики ещё не реализованы.

Чужие dirty-файлы сохранены, рабочий архив/output/.artifact-build не использовались, секреты не читались. Следующая задача не запускалась.
