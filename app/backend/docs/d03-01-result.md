30 октября 2026. Реализован [контракт D03-01](d03-01-contract.md), часть F04/F11/F12 [текущего объёма](current-product-scope.md). **Полный `bash scripts/check.sh`: 1316 тестов и 24 подтеста проходят**, Ruff и форматирование проходят. Это первый локальный экран документов, доступный через браузер для разработки; установщик и редактор текста ещё не реализованы.

## Что работает

На `/workspace` открывается русский интерфейс AIRA: список сохранённых DOCX, обновление и следующая страница, форма выбора файла и названия, сведения выбранного документа и скачивание текущей сохранённой версии. При старте документ не выбирается автоматически. Предварительная версия явно обозначена.

Экран использует существующие DOCX API D02-07/08. Файл отправляется бинарным телом, без разбора Word в браузере. До загрузки проверяются расширение, размер и название. На время операции действия блокируются; повторное нажатие не начинает вторую операцию. При неоднозначной ошибке сохраняются UUID, File и название попытки; повтор загрузки использует их же. Новый выбор файла начинает новую попытку. После подтверждённого импорта ошибка обновления списка не превращает сохранение в якобы неуспешное.

Перед открытием другого документа прежние сведения скрываются; ошибка не оставляет скачивание старого документа под новым названием. Скачивание проверяет успешность HTTP перед созданием Blob URL. Названия выводятся через textContent, не как HTML. JSON-поле storage_revision не используется в вычислениях JS и не показывается через неточное Number. Файлы и метаданные не пишутся в localStorage/sessionStorage; внешних CDN и запросов нет. Ожидание ограничено AbortController: чтение 15 секунд, импорт 60 секунд; это технические тайм-ауты клиента.

Добавлен `ara.workspace` с фиксированными маршрутами HTML/CSS/JS. Assets читаются при запросе через importlib.resources, без произвольного пользовательского пути. Заголовки задают UTF-8, no-store, nosniff, no-referrer и ограничительную CSP. UI/asset-маршруты отделены от OpenAPI продуктового API через include_in_schema=False. В фабрике без runtime экран отсутствует. Создание app и импорт workspace не читают файлы и не обращаются к БД.

## Фактическая проверка в браузере

Preview запускался только на `127.0.0.1:8793` с собственной одноразовой PostgreSQL и синтетическими файлами. Проверены:

- Выбор rich-source.docx через файловый диалог, подстановка названия, явное подтверждение, появление в списке и открытие сведений. После обновления страницы список восстановился, документ не открылся автоматически.
- Скачивание через кнопку: файл в Downloads совпал с контрольным rich-source.docx побайтово — **48126 bytes**, SHA-256 `73009626640400679d2b1a2031c565a964308073aa287067cf39088836176fcd`.
- Название `<img onerror=alert(1)> Учебные требования` отображалось буквально; DOM не содержал img. Недоверенная строка не стала разметкой.
- Неверный synthetic DOCX показал понятную русскую ошибку и действие повторной загрузки; ранее выбранный корректный документ не повредился.
- QA-middleware только в preview один раз заменил подтверждение уже выполненного импорта на 503. Экран показал ошибку; повтор завершился успешно. Снимки до/после подтвердили одну запись с теми же ID, ревизией 1 и обоими хешами. Это контролируемая имитация потерянного подтверждения, не реальный сетевой обрыв. Снимки `.runtime/d03-01-before-retry.json`, `.runtime/d03-01-after-retry.json`.
- Для пагинации через существующий API добавлены ещё 22 синтетических документа: первая страница 20, следующая — всего 23 уникальных записи, кнопка следующей страницы скрылась.

- На ширине 390 и 1280 пикселей горизонтального переполнения нет. Временный viewport сброшен. На просмотренных этапах console error/warn отсутствовали.

Для обычного локального запуска используется существующий `ara.local:create_local_app`; после запуска открыть `/workspace` на его localhost-порту. Требуются ранее настроенная ARA_DATABASE_URL и мигрированная PostgreSQL; секреты по-прежнему загружаются только из ~/secrets.env при явном запуске. QA-preview завершён и не является постоянно работающим приложением.
