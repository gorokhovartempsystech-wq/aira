# D03-16E3B — explicit recovery discard

31 октября 2026, Sol 6.1 High; F05/F11/F12, D/C3B/E3A. Только явное удаление durable копии, без UI/SQL deadlines/нового storage protocol. Прямое разрешение продолжать циклами действует.

Два новых POST paths от `/docx-documents/{document_id}/editor-recovery`:

- `/prepare-discard`: strict JSON expected_checkpoint_revision (canonical decimal string), request_id (canonical UUID). Passive project→document FOR SHARE→legacy/CP validation, не init/write/read receipt/commit/finalize. Только непустая exact CP working/pending. Возвращает client-retained plan; повтор до изменения CP детерминирован. Никакой RAM cache планов/подписи/секрета. Это описание выбранного состояния для повтора, не дополнительная авторизация.
- `/discard`: body — exact plan. Working `{kind:"working",document_id,expected_checkpoint_revision,request_id}`; pending `{kind:"pending",document_id,request_id,handle}`. path/body document_id обязаны совпасть, включая handle. Handle — полная immutable SaveHandle: document_id/prepared_checkpoint_revision/base_storage_revision/base_sha256/working_sha256/working_size_bytes/metadata с selection/origin/pending. UUID/counters/anchors strict E1 types; origin/pending counters строки, size int1..32MiB. SaveHandle пересчитывает identity fingerprint, валидация before durable dispatch. Unknown fields/bool/подмена handle422. Metadata не содержит package/text.

Working исполняется существующим discard_checkpoint, pending — discard_pending C3B. Сохранять их CAS/idempotency/полную proof проверку; никаких SQL bypass/повторов с новым ключом/дополнительной очистки. Один и тот же сохранённый plan повторим после loss/restart уже с empty tombstone; поздний старый plan не удаляет новую CP. Prepare не выдаёт plan для empty; вручную сконструированный working plan следует прежнему B2 empty-CAS поведению (без потери данных). Смена request_id после неизвестного исхода не является client retry protocol.

Reply kind=discarded/document_id/checkpoint_revision/current summary/save_confirmation/current_matches_receipt. confirmation=not_checked для working, confirmed или unconfirmed для pending по результату C3B; unconfirmed не доказывает rollback. Current/original/receipts не удаляются/не откатываются, в том числе если pending уже committed/outdated. Corrupt receipt безопасно блокирует pending discard; prepare остаётся возможным без receipt lookup.
