# T01-04: история версий и локальная идентичность готовы

17 сентября 2026 года T01-04 завершена за одну итерацию Ralph. **144 теста и 24 подтеста проходят**, Ruff и форматирование проходят. Этим закрыта T01 общего бэклога в локальном техническом режиме.

## Поведение

`ara.documents.storage.append_version` создаёт следующую версию через Python API. Вызывающий передаёт серверный runtime, document_id, ожидаемую текущую версию и Markdown. Функция проверяет доступ, блокирует строку документа, сравнивает базу, создаёт новую версию с родительской связью и обновляет current_version_id в одной транзакции. Возвращает независимую копию снимка после успешного commit; чужой engine не закрывает.

Прежние версии и метаданные документа сохраняются. Текст, блоки и сведения о неподдержанных фрагментах формируются тем же путём, что для первой версии. Если база устарела, функция возвращает безопасный 409/version_conflict без записи. Два одновременных вызова с одной базой дают ровно один успех и один конфликт.

GET /me возвращает user_id, project_id, environment=local и auth_mode=local-dev из проверенного серверного контекста. Заголовки/query пользователя не меняют ответ. При явно нелокальном ARA_ENVIRONMENT даже приложение с внедрённым локальным runtime отклоняет запуск. Явная локальная фабрика по-прежнему требует ARA_ENVIRONMENT=local, а launcher слушает только 127.0.0.1. Автономный health-only путь сохраняется.

## Доказательства

Контракт и приёмка до реализации: локальный коммит `b175c54`. Исходный общий прогон: **15 failed, 125 passed, 24 subtests passed**. Падения указывали на отсутствующие append_version, /me, дополнительный pilot guard и ожидаемое расширение OpenAPI.

Ralph: `.ralph/runs/T01-04-20260917T153841Z-d89d0d23`, одна попытка, `criteria_and_checks_passed`, agent/check exit 0. Независимая приёмка находилась вне разрешённых исполнителю файлов. Сокет PostgreSQL использовался через штатные разрешения.

Проверено на настоящей PostgreSQL в собственных одноразовых базах:

- цепочка трёх версий, точные HTTP-снимки всех версий после пересоздания app/engine, неизменность истории при изменении возвращённого Python-объекта;
- недоступность документов других проектов/владельцев и одинаковые 404 до проверки базовой версии;
- stale/repeat conflict и одинаковый 409 для существующего чужого ID версии;
- полный откат при отказе вставки версии, обновления current и ошибке commit;
- два конкурентных writer, защита от смены владельца проекта в ходе операции и повторная проверка доступа после смены владельца;
- строгая валидация прямого Python-входа, безопасные ошибки, /me, pilot guard, инертные импорты и loopback launcher.

Read-only ревью storage/schemas и отдельное ревью app/API замечаний не выявили. После цикла усилена независимая приёмка видов Markdown-блоков, unsupported/import_omissions и конфликта с чужим expected_version_id. Итоговый полный прогон повторно прошёл: 144 теста и 24 подтеста, два прежних предупреждения deprecation от TestClient.

Ручной HTTP-запуск на 127.0.0.1:8013 подтвердил /me, /health, /documents и OpenAPI. Запрос /me с подменёнными user_id и auth-mode всё равно вернул предусмотренную синтетическую идентичность и local-dev. Запись документов в ara_dev не выполнялась. Сервер штатно остановлен.

После проверки временных баз ara_check_* — 0. В ara_dev ревизия 0001_initial_documents, один синтетический пользователь и проект, документов/версий — 0; ara_test пустая. PostgreSQL штатно остановлен, status=stopped, данные сохранены. Перед следующим API или тестами выполнить `bash scripts/postgres.sh start`.

## Границы

Следующие версии пока создаются через слой хранения, отдельного HTTP endpoint записи новой версии нет. Merge/apply и идемпотентность по ключу операции относятся к T03. Гарантия сохранения истории относится к прикладному пути; прямой SQL владельца БД не ограничен отдельными immutable-триггерами или ролями. Локальный пользователь не является настоящей авторизацией.

T02 — следующий этап: типизированные модели и проверки ML-контракта, сохраняемое задание и worker с явно обозначенным fixture-адаптером. Это ещё не реальный ML-анализ. GitHub remote не создавался; работа остаётся локальной.
