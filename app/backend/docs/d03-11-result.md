# D03-11 — backend добавления и удаления абзацев

31 октября 2026. Реализован [контракт D03-11](d03-11-contract.md), F05/F11. Первый цикл по прямой команде Никиты самостоятельно продолжать разработку по отдельным этапам. Рекомендуемый и использованный режим — Sol 6.1 High. Основной frontend Ани и текущий workspace не менялись.

## Результат

Новый чистый API ara.docx_package.structure добавляет один или несколько абзацев до/после существующего body paragraph и удаляет выбранные абзацы. Frozen/slotted команды содержат точный paragraph anchor исходника и expected_text; после изменения нужны свежие anchors. Операции атомарны, независимый порядок команд не влияет на bytes. Пересекающиеся/неоднозначные команды и удаление последнего body-абзаца отклоняются.

Новые абзацы используют собственный локальный WML namespace и default paragraph formatting документа; свойства/ID/ссылки старого p не клонируются. LF/TAB становятся native Word controls, Unicode/пробелы/escaping сохраняются. Меняются только выбранные lexical byte ranges, остальной main XML не сериализуется. ZIP metadata/части, comments/PI вне target, стили, таблицы, изображения и внешние связи остаются прежними. Поддержаны UTF-8, UTF-16 LE/BE, Strict WML, нестандартный main part и локальные xmlns.

Прежние settings/signature gates применяются без изменения старого source. Protection, tracking, complex field/range markers, target annotations/opaque/hyperlinks/sectPr дают безопасный unsupported_structure. Вложенные cell paragraphs пока не адресуются. Это явная граница первого структурного API, не полная поддержка редактирования Word. Пустой batch возвращает точный исходник. Операции не обращаются к файлам/сети/БД/секретам и не логируют текст.
