## Что нужно учесть при подключении frontend

Сверено с PR #19, commit
[`ad02b9e475ad0dbad53fc9d3f2a12c019ad4564c`](https://github.com/gorokhovartempsystech-wq/aira/tree/ad02b9e475ad0dbad53fc9d3f2a12c019ad4564c/app/frontend).
Эта проверка относится к указанному commit; ветка может измениться позднее.

1. Обновить поставляемые backend **и** `/client` вместе. Исправление отказа находится
   в `analysis-session.mjs`, разрешённые новые действия — в `protocol.mjs`.
   После подтверждённого отказа `canStop=false`, `canCheck=true`,
   `canRetryAdmission=false`. Ошибка остаётся видимой. Новый check сохраняет документ
   и получает новый request ID; не следует повторно использовать отклонённый запрос.
2. В `docx-assets.mjs` остаётся старый общий список BLOCKERS, а `review.mjs`
   (`runCheck`, строка 119 в указанном commit) прекращает запуск до вызова backend.
   Обновление backend само по себе не снимет этот запрет. Blanket-запрет по наличию
   `softHyphen/noBreakHyphen/ptab/pBdr/numPr` теперь неверен; `sym` и `oMath`
   поддерживаются только в закрытом подмножестве. Рекомендуемый вариант интеграции:
   предварительный разбор UI показывает предупреждение, а окончательный допуск
   решает backend. Не удалять элементы из DOCX ради успешного запуска.
3. Подключить `insert_table` и `insert_image` к очереди редактирования интерфейса:
   дождаться отправки набранного текста, зафиксировать текущий курсор, отправить
   команду, перечитать проекцию и assets, восстановить курсор из ответа.
   Не менять одновременно исходный ZIP на стороне браузера.
4. Таблица: `{action:'insert_table', value:{rows:2, columns:3}}`.
   Изображение: `{action:'insert_image', value:{data_base64:encodedBytes}}`.
   До 4 MiB / 20 млн пикселей; только PNG/JPEG. Не заполнять `alt_text` именем файла:
   непустое описание сохраняется, но текущий анализатор его явно отклоняет.
5. В `docx-review/5` и `docx-review-view/5` у исходных slices добавлены
   `nonbreaking_hyphen` и `symbol`. Если frontend использует закрытый enum,
   его нужно обновить вместе с backend. Виды из прежних версий не удалены.
   Координаты остаются в Unicode code points и привязаны к неизменяемому источнику.

Кнопки и DOM-поведение в PR #19 этим backend-патчем не изменялись; прохождение API
не заменяет приёмку интерфейса после подключения.

## Фактически проверенный сквозной сценарий

На macOS, локальный PostgreSQL и настоящий пакет `models-0.2m`:

- создание DOCX; ввод текста; вставка таблицы и текста в её ячейку;
- вставка PNG; undo/redo; сохранение перед проверкой;
- анализ, ручная правка и повторный анализ (`fixture=false`);
- экспорт обоих вариантов, повторный импорт с точным совпадением байтов;
- явный отказ на alt text без run/state, после которого API экспортирует и закрывает документ;
- настоящий анализ `tests/fixtures/docx/word-blockers.docx` из ветки frontend;
- перезапуск supervisor/app и повторное получение того же DOCX и результата.

Финальный повтор этого сценария: **1 passed за 15,76 с**, с `table_editor=True, field_editor=True`, как в оболочке frontend. Время собственно двух
запусков анализа в этом маленьком примере — 1,512 и 1,257 с. Это не оценка скорости
на больших документах и не доказательство полноты замечаний модели.

Оба экспортированных документа отрисованы встроенным LibreOffice в PDF/PNG;
каждый содержит одну страницу. На обеих страницах визуально проверены текст,
таблица и изображение: без обрезания и наложений. Эта проверка выявила отдельную
несовместимость префиксных OPC metadata; исправление `04b411b` проверено повторно.
Microsoft Word для Windows/macOS таким рендером не подменяется.

Локальные журналы и синтетические файлы: `.runtime/d03-20-final/` (не публикуются
вместе с весами/временными БД). `live-report.json` содержит результаты реального
сценария, `render-*/page-1.png` — визуальную приёмку, `source-hashes.json` — состав
входов общего прогона.

## Ограничения

- Оригинального проблемного файла Word для Mac у команды сейчас нет (ответ Никиты
  9 ноября); его конкретный сбой не воспроизведён и не объявляется исправленным.
- Это не поддержка произвольного OOXML: неизвестные шрифтовые символы, сложные
  формулы и старые VML-надписи могут отклоняться. Известная галочка не означает
  поддержку всей таблицы Wingdings. Простое oMath не вычисляется.
- Изображения сохраняются и отображаются; OCR нет. Непустой alt text пока блокирует
  анализ — таков прежний явный контракт, а не повод незаметно удалить описание.
- Вставка объектов в ячейку, расширенное выделение и защищённые структуры
  отклоняются без изменения документа. Размеры/оформление таблиц ограничены
  базовым вариантом, расширенный редактор Microsoft Word не реализуется.
- Native Windows и пользовательский интерфейс после подключения требуют своей
  приёмки. Windows lease-drain PR #20 не подменён этим набором изменений.
- Изменения качества ML, публичный сервер лицензий и выпуск установщиков не входят
  в эти циклы. Сценарий с локальной моделью проверяет интеграцию, а не точность ML.
