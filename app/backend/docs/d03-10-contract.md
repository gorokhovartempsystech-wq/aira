# D03-10 — создание нового документа в приложении

30 октября 2026. Одна задача F04/F05/F11/F12 после D03-09: пользователь задаёт название, создаёт пустой DOCX по согласованному шаблону AIRA, вводит первый фрагмент, сохраняет и скачивает файл. Структурный редактор, учебный пример, анализ, лицензия и установщик остаются отдельными задачами. Шаблон D03-09, прежние storage/recovery/CAS и импорт не меняются.

## HTTP

Добавляется ровно один продуктовый маршрут `POST /docx-documents/{document_id}/create?title=...`, только при явном local DocumentRuntime. UUID клиента — стабильный ключ создания. title — единственный query parameter, ровно один, по прежнему valid_title (1–200 Unicode code points, не whitespace-only, без NUL/lone surrogates). Query string — ASCII URI с корректными percent escapes и UTF-8: некорректные escapes/UTF-8 отклоняются, а не превращаются в replacement characters. Название сохраняется буквально как metadata и не подставляется в содержимое пустого документа. Ни user/project IDs, ни paragraph/text/template payload от клиента не принимаются.

Тело отсутствует. Не читать его целиком: пройти request.stream без накопления, первый непустой chunk даёт 422 до генерации/БД. ClientDisconnect также 422. Content-Type отсутствует или пустой; непустой — 415. Content-Encoding отсутствует/identity, другое — 415. Дубли content-type/content-encoding/content-length, любой Transfer-Encoding, неверный Content-Length (не ASCII digits, больше 19 digits или не равен 0) дают 422. Все недопустимые запросы не вызывают генератор/storage. Результат ошибок — прежний безопасный envelope code/message/retryable/request_id с local-dev header, без входных данных/исключений.

В worker thread вызываются неизменные create_docx() D03-09 и import_docx(runtime, document_id, title, data). Результат — прежний DocxMetadata, HTTP 200 для первого запроса и повтора, Cache-Control no-store. Генератор и storage не выполняются на event loop. Новый endpoint в OpenAPI без requestBody и с прежними точными полями/bigint bounds/ошибками 404/409/415/422/500/503. Default factory остаётся health-only.

Одинаковые UUID/title/пустой исходник возвращают последний сохранённый current DOCX, а не сбрасывают его к шаблону. Параллельные повторы создают одну строку; потеря ACK допускает безопасный повтор. Другое название/другой исходник на том же UUID — 409 creation_conflict; foreign/peer IDs остаются 404. Новый origin-флаг не добавляется: ранее импортированный побайтово такой же blank с тем же UUID/title эквивалентен повтору. Если в будущей версии изменятся bytes шаблона, старый replay может консервативно получить 409; не подменять исходник. Ошибки генерации DocxError/ProjectionError/CreationError — безопасный 500 creation_error; прежние storage 500/503 сохраняются.

## Интерфейс

Отдельная форма «Новый документ»: label «Название нового документа», поле, «Создать документ». Ограничения title совпадают с сервером, без trim/сокращения; maxlength допускает 200 supplementary characters (400 UTF16 units). Перед отправкой создаётся отдельный RAM attempt {id,title}; двойной submit/busy не создаёт новый UUID/запрос. Pending attempt блокирует изменение своего названия, показывает «Повторить создание». Повтор использует тот же UUID/title, включая потерянный ACK или неверный receipt. Импорт имеет отдельный attempt и сохраняет прежнее поведение.

Перед POST проверяется лимит 12 вкладок, composition/dialog/busy, затем подтверждается и паркуется активный draft по D03-08. Неуспех парковки не отправляет create и удерживает текст. Ошибка запроса восстанавливает прежнюю вкладку и сохраняет attempt. Подтверждённый ответ с UUID, отличным от attempt, не считается успехом. После подтверждения attempt очищается независимо от ошибки последующего списка/view; повторное создание не предлагается для уже подтверждённой операции.

Документ открывается одной вкладкой своего UUID. Уже открытая вкладка того же UUID сохраняет своё RAM-состояние, не заменяется свежим view. Blank при успешном просмотре автоматически открывает пустой фрагмент для ввода, только если нет восстановленного draft/recovery guard. Повтор после успевшей записи возвращает актуальный текст. Ошибка списка/view ясно отделяется от состоявшегося создания; скачивание своего UUID доступно. Оформление reader остаётся прежним упрощённым представлением, структура/стили Word находятся в скачиваемом DOCX.

Неудачную попытку можно завершить явной кнопкой «Завершить попытку» через диалог «Остаться / Завершить попытку». Сообщение: документ мог уже создаться и останется в списке; завершение снимает только локальный retry-key, ничего не удаляет в БД и не меняет открытый текст. До подтверждения сброса ключ не меняется. Beforeunload учитывает attempt создания. Никаких browser storage, автоматически открываемых последних документов, обязательных аккаунтов или фиктивного анализа.
