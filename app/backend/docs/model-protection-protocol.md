# Защищённая поставка модели AIRA — MP01–MP04

13 ноября 2026. Основание: запрос Никиты защитить локальную модель и согласие
однократно повторить активацию после обновления. Существующие публичные данные
активации не дают права получить ключ защищённой модели.

## Граница защиты

В установщике лежат AES-256-GCM контейнеры `.onnx.aira`, токенизаторы и публичный
манифест. Ключ релиза отсутствует в установщике, Git, feed, argv, environment и
профиле приложения. ONNX Runtime получает аутентифицированные bytes в памяти.
Открытых временных ONNX нет. Веса остаются локальными, документы серверу не нужны.

Это препятствие извлечению готовых весов из установщика, а не DRM с аппаратной
аттестацией. Контролирующий процесс пользователь может извлечь ключ/веса из памяти
или изменить Python-код. Нет гарантии обнуления памяти, отсутствия swap/crash dumps.
Ранее выпущенные открытые веса и правила Python этой защитой не закрываются.

## Вход и повторный запуск

1. Прежний HTTPS `/license/v1/activate` или `/license/v1/check` подтверждает срок
   и устройство. Этот API не выдаёт ключ модели и не меняет свой контракт.
2. Клиент читает закрытый Ed25519-ключ устройства из macOS Keychain или Windows
   Credential Manager. Linux/file/config-selected fallback запрещён.
3. Если ключа нет или сервер не знает его, нужна однократная активация исходным
   лицензионным ключом. Клиент создаёт и сохраняет новый ключ в штатном хранилище.
4. Клиент получает challenge для зарегистрированного релиза и подписывает его.
5. Сервер атомарно повторяет проверку срока/отзыва/устройства, проверяет подпись
   и одноразовость, затем возвращает ключ конкретного релиза по HTTPS.
6. Только после этого клиент становится active и сохраняет публичную идентичность.
   Следующий запуск повторяет онлайн-проверку и proof, не просит лицензионный ключ.

Ключ релиза хранится в памяти до закрытия/отказа/истечения permit. Дополнительной
сети на каждый анализ нет. Отзыв проверяется при следующем запуске/явной проверке;
текущий подтверждённый сеанс ограничен сроком permit. Сбой лицензирования не удаляет
документы и не запрещает экспорт уже внесённых изменений.

## HTTP-контракт `aira-model-access/1`

Только POST по HTTPS, JSON до 8192 bytes, без повторных JSON-полей, ответ
`Cache-Control: no-store`. Клиент проверяет сертификат, запрещает redirects,
прокси из environment, сжатые/слишком большие/кэшируемые ответы. Сервер ограничивает
одновременные обработчики четырьмя. Uvicorn доступен только на loopback за HTTPS.

`/license/model/v1/challenge` принимает строго:

| Поле | Значение |
|---|---|
| schema_version | `aira-model-access/1` |
| operation | `enroll` или `unlock` |
| license_id | UUID лицензии |
| license_key | ключ для enroll; null для unlock |
| device_id | `dv1-` и 64 hex текущего digest |
| public_key | 32 bytes Ed25519, lowercase hex |
| client_nonce | случайные 32 bytes, lowercase hex |
| release_id | ASCII ID, до 96 символов |
| manifest_sha256 | 64 lowercase hex; разрешён серверным реестром |

Ответ: `{schema_version, token}`. Токен — канонический JSON в base64url и HMAC-SHA256
с разделением домена. Он содержит контекст запроса без license_key, случайный nonce,
серверные issued/expires (60 секунд) и revision регистрации устройства. MAC-секрет
не передаётся клиенту. Клиент проверяет весь контекст до подписания.

`/license/model/v1/complete` принимает строго `{schema_version, token, signature}`.
Подпись Ed25519: `b"aira-model-proof/1\0" + token.encode()`. MAC и подпись проверяются
до SQL. Под блокировкой строки лицензии сервер проверяет актуальные enabled, expiry,
устройство и revision; атомарная вставка nonce допускает только одно завершение.
Повторная регистрация увеличивает revision и обесценивает старые pending proofs.

Успех: `{schema_version, license_id, device_id, client_nonce, release_id,
manifest_sha256, checked_at_ms, expires_at_ms, key}`. Ключ — 32 bytes lowercase hex.
Клиент проверяет точное совпадение контекста, срока и ограничение общего времени.
Ошибка содержит только фиксированный code. `enrollment_required` предлагает
повторную активацию; остальные отказы не открывают модель и не отражают входные данные.

## SQL и секреты

Публичные таблицы v1 не меняются. Явный `python -m ara.model_protection init`
проверяет их и создаёт отдельную схему `aira_model_access`: `devices`
(license_id, device_id, public_key, revision), `used_challenges` (nonce, expires_ms).
Истёкшие nonce очищаются при завершении новых proofs. В таблицах нет ключа модели.

Операторский `~/secrets.env` сервера содержит прежние настройки лицензирования
и `AIRA_MODEL_RELEASES_JSON`: список до 16 объектов с release_id, manifest_sha256,
key. На машине упаковки отдельный `AIRA_MODEL_RELEASE_KEY`. Значения не выводятся.
Импорт модулей не читает секреты, не подключается к сети/SQL/Keychain.

## Приватный worker

Режим `protected_model` использует прежний приватный request pipe. Перед неизменным
run frame передаётся фиксированный преамбулой 32-byte ключ. Это не публичный JSON
контракт и не дополнительный наследуемый канал. Decoder выдаёт ключ только после
полного корректного frame и EOF; прежние guardian, gate, deadline, stop, ownership
и cleanup остаются обязательными. Legacy-режим отвергает переданный ключ.

## Поставка и эксплуатация

Mac 0.2.7 build 7: Apple Silicon, macOS 14+. Минимум соответствует поставляемым
бинарным зависимостям; appcast также указывает 14.0. Developer ID/notarization
отсутствуют, поэтому предупреждение Gatekeeper остаётся. Windows builder требует
защищённый пакет и запрещает plaintext ONNX/NoModel в релизном установщике.

Сервер разворачивается в новом каталоге и venv, исходный unit/code сохраняются.
Добавляются только два точных маршрута Caddy. При неудачном переключении возвращаются
старый unit и proxy. SQL v1 остаётся совместимым. Закрытые ключи оператора не нужны
Windows runner: он получает только зашифрованный публичный пакет модели.

Приёмка: подмена/обрезка контейнера, неверный ключ, повтор/гонка proof, смена release,
отзыв/истечение между challenge и complete, миграция старой активации, автоматический
повторный вход, отказ сети/хранилища, целостность приватного канала, настоящий анализ
и сохранность DOCX. Native UI-проверка Windows остаётся отдельным шагом перед пилотом.
