# D03-16E3C — scoped SQL deadlines и handoff

31 октября 2026, Sol 6.1 High; F05/F06/F11/F12 и последний раздел locks в D design. Последний HTTP-подцикл D03-16. Прямое разрешение продолжать автономно действует. Не реализует анализ/лицензию/frontend.

На explicit HTTP installation создать отдельный OptionEngine через execution_options с прежним pool/dialect, скопировать DocumentRuntime. Только этот wrapper получает instance begin listener: SET LOCAL lock_timeout='5s', SET LOCAL statement_timeout='15s' на каждую транзакцию. Никаких listeners на global Engine/class/parent/pool checkout, постоянных SET, новой БД, migration, secrets или I/O при construction/import/OpenAPI. Не создавать/закрывать/dispose caller engine. Registry D копирует scoped runtime, E3A/B переиспользуют его. Старые API и прямой EditorRegistry(runtime) сохраняют прежнее поведение.

Это технические ограничения **одного SQL statement/ожидания lock**, не общий request/transaction/CPU/import/model timeout. Connect/pool checkout зависят от явного caller engine; HTTP body/worker/send admission E2 и budgets D/E остаются. Продуктовые autosave2min и analysis5min не меняются. Никаких client wire settings/фоновых timer/cancellation rollback promises.

PostgreSQL lock/query timeout в прежней `_session` boundary даёт sanitized503 storage_unavailable/retryable=true. Ошибка durable dispatch сохраняет stable active SaveAttempt/identity/working bytes; повтор/реconciliation после освобождения SQL lock завершает ровно один save, без повторного edit/потери history. Новые requests503 editor_busy пока worker занят; gate/actor locks освобождаются после выхода worker, как E2. SET LOCAL сбрасывается при commit/rollback и не протекает в прежние routes/другой scope wrapper даже через общий QueuePool connection. Не вызывать database cancel или менять B/C protocol.
