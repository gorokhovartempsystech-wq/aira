# D03-06 — автосохранение выбранного фрагмента DOCX

30 октября 2026. Реализован [контракт D03-06](d03-06-contract.md), часть F05/F11 [текущего объёма](current-product-scope.md). Текущая ручная правка одного текстового span автоматически записывается в DOCX через две минуты. Новых продуктовых backend routes, миграций, зависимостей и операций над Word нет.

## Поведение

Один контроллер таймера принадлежит одному открытому черновику. Первый dirty-ввод задаёт срок 120000 ms; последующий ввод не отодвигает его, запись берёт последнее значение. Без изменений нет записи. Во время save следующий callback не запускается. Busy/dialog откладывают проверку до следующего интервала. Закрытие/смена редактора останавливает контроллер, старый callback не работает с новым документом. Ошибки не оставляют running и не создают unhandled rejection.

Автосохранение использует прежнюю последовательность D03-04/05: стабильный ключ/payload → подтверждённая копия → POST text-edit → receipt → CAS DELETE копии. При проблеме с копией POST не отправляется. При конфликте или неподтверждённом ответе текст остаётся, timer приостанавливается; pending повторяется вручную с тем же ключом. Исправление текста после исправимой ошибки разрешает новый срок; конфликт документа требует переоткрытия. Восстановленная неподтверждённая попытка не запускается таймером.

Обычный успешный auto-save сохраняет открытое поле, фокус и курсор. Редактор получает новую чистую базу именно из receipt операции: точную строковую revision, expected text и source SHA. Part/path остаются прежними, потому что single-span export не меняет структуру. Receipt проверяется, включая expected+1 через BigInt и hex64 SHA; JS Number для ревизии не используется. После обновления основы можно продолжить ввод и явно либо автоматически сохранить следующую правку.

Структурный view обновляется без очистки editor. View принимается только с тем же hash/revision, что receipt; ошибка или более свежий view не подменяют CAS base. Пользователь видит подтверждение записи и предупреждение о просмотре, timer приостанавливается до переоткрытия. При проблеме удаления копии подтверждённый результат DOCX остаётся успешным; панель закрывается с предупреждением, чтобы следующая правка не записалась с неопределённым token. Ручной save сохраняет прежнее закрытие панели.

На время запроса ввод readOnly, поле доступно для выделения/копирования, кнопки блокируются общим busy guard. Это первый ограниченный вариант: параллельного набора во время записи нет. На экране указан интервал. Browser storage, внешних запросов, ML или автофикса нет: сохраняется введённый пользователем текст. Окно должно работать; в закрытом приложении таймер не исполняется.

Общий `bash scripts/check.sh`: **1458 passed, 24 subtests**, 63 предупреждения, **162,53 секунды**, exit 0. Ruff/format проходят. Проверены точный deadline/latest input, непрерывный ввод без debounce postponement, unchanged, busy, отсутствие перекрытия saves, stop/старый callback, ошибка/возобновление, pause и второй dirty-цикл. Node взят из уже установленного bundled runtime рядом с Python; пакеты не устанавливались, отсутствие runtime не превращается в skip. Логи `.runtime/d03-06-red.log`, `d03-06-targeted.log`, `d03-06-full-check.log`.

app.js теперь ES module с одним прежним script tag, autosave.js доступен только по одному фиксированному asset-route с no-store/nosniff/self CSP и вне OpenAPI. Default factory не обслуживает его. Старые inert import/asset checks проходят; файлы входят в прежний package-data wildcard.

## Границы

Остаётся редактор одного существующего span. Новые абзацы/структурные правки, Undo/Redo документа, вкладки, анализ, лицензия и установщики отдельны. Страховочная копия D03-05 сохраняется при вводе независимо от таймера; это не выдаётся за изменение DOCX. Ввод с неподтверждённой/ошибочной копией остаётся в памяти до подтверждения хранения.

Прямая разработка на выбранном Sol 6.1 High. Runner/tasks/progress, backend/БД, авторизация и квота не менялись. Чужие dirty-файлы сохранены; рабочий архив/output/.artifact-build не использовались, секреты не читались. После одной задачи следующая не запускалась.
