# D03-17B2 — результат проектирования хранения проверки

1 ноября 2026. Архитектурный цикл по команде Никиты продолжить разработку после переключения на Astra. Исходный HEAD `4999b57`, B1 завершён. Подготовлены [дизайн](d03-17b2-design.md), [точный целевой DDL](d03-17b2-schema.sql) и [контракт первого implementation цикла B2A](d03-17b2a-contract.md). Обновлены ссылки D03-17 и development-queue. Продуктовый scope неизменен; поведение приложения/миграции/модели/tests ещё не менялись.

Выбраны четыре отдельные таблицы, exact BYTEA для DOCX и wire, immutable source/revision/profile/model binding, scoped FK и атомарные взаимные связи run↔attempt/result. SQL не позволит committed success без результата или несвязанный attempt. Одна attempt/run; пользовательский Retry — новый run, транспортный replay — прежний. Зафиксированы время300s, lease15s, heartbeat≤5s, fence/state matrix, lock order, repeat/cancel/unknown commit и safe downgrade с отказом при любых сохранённых analysis rows. Предыдущий результат не удаляется при неуспехе следующего запуска.

B2A реализует только schema/ORM/migration. B2B отдельно проверит canonical storage/reconstruction через существующий B1 без inference; далее B3A start/read/replay и B3B worker lifecycle. Функция сохранения результатов пользователю после одного B2A не считается готовой. B1 pinned adapter не совместим автоматически с новым team engine, содержащим partial/pairwise; C2 должен выбрать явную версию адаптера.

Техническое обоснование BYTEA/NULL/FK/locking сверено с первичной документацией PostgreSQL18, ссылки в дизайне. Продуктовых вопросов не появилось. Для следующего freeze подготовлен узкий V9 pin пяти migration-fixture вызовов в двух файлах; все прежние assertions остаются, общий default head не меняется. В этом design-cycle tests не редактировались. Новая independent acceptance B2A/freeze/red ещё впереди.

Проверка проекта SQL: `.runtime/d03-17b2-probe.py` создал собственную `ara_check_<uuid>`, применил существующую V9 и целевой DDL, проверил **30 сценариев**, exit0; затем удалил только созданную базу. Проверены допустимые states, terminal до/после claim, deferred commit отказ без result/attempt и при неверной связи/digest, active uniqueness, NULL/lease/deadline/fence/hash/size-shape/time checks, cross-document attempt и SET CONSTRAINTS gate. Все данные синтетические; это design probe, **не** замена полной независимой приёмки будущей миграции/сервиса. Отчёт `.runtime/d03-17b2-ddl-probe.json`, лог `.runtime/d03-17b2-ddl-probe.log`.

Полный `bash scripts/check.sh`: **2704 tests + 24 subtests passed**, **74 warnings**, **291,07 секунды**, exit0. Ruff check/format прошли; `.runtime/d03-17b2-full-check.log`. Тесты действующей реализации сохранены без изменений. Read-only сравнение `.runtime/d03-17b2-runtime.json` с последним B1 baseline полностью совпало: ara_dev V8, schema/counts прежние, ara_test пуста, временных ara_check БД0. Пользовательские документы/архив/секреты не читались, source не менялся, ML/Word не запускались.

Документы дизайна фиксируются отдельным локальным commit. Чужие dirty README/старые планы/новые материалы сохранены и не включены. Runner/tasks/progress не менялись. PostgreSQL оставлен запущенным. Push/PR по отложенной публикации не выполнен; подготовленный ранее пакет основан на verified code `4999b57` и не должен называться уже загруженным.

**Следующий режим — Sol 6.1 High, задача D03-17B2A.** Начать с independent acceptance/freeze/red и узкой migration compatibility preparation, затем реализовать V10 на одноразовой БД. После законченного gate продолжать B2B/B3 по отдельным циклам без новых подтверждений, если не требуется архитектурное решение. Основную БД автоматически не мигрировать.

Уточнённый самостоятельный остаток **30–45 implementation/verification циклов** без ожидания работы Ани/Артёма: DOCX13–19, проверка/результаты8–11, лицензия3–5, поставка4–6, финальная проверка2–4. По сравнению с промежуточным28–43 две большие строки B2/B3 разделены на четыре ограниченные задачи; новые продуктовые функции не добавлены. Завершённый design здесь повторно не считается. Диапазон — ориентир, не потолок; native Word/сложный DOCX и интеграция целевых платформ остаются рисками, frontend/реальная модель не объявляются готовыми.
