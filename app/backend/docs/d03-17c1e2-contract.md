# D03-17C1E2 — private pipes, events и pending IO

2 ноября 2026, Sol6.1 High. Следующий ограниченный цикл [C1E](d03-17c1e-design.md), после available E1 gate; Windows native gate остаётся отдельно pending. F06–F08/F12. Только native IPC primitives, без процессов/Job/guardian/model/SQL/HTTP/scheduler. C1C wire и готовые E1/macOS modules неизменны.

Разрешены новые `windows/{_io_abi,_events,_pending,_pipes}.py`, новая frozen `tests/acceptance/test_docx_analysis_windows_io.py`, own `tests/docx_documents/test_analysis_windows_io_*.py`. Этот contract до freeze, result/status docs после gates. Не менять E1/старые source/tests/DDL/runner/dependencies/check script/root exports. Stdlib ctypes; Native IO расширяет binding композиционно, не дописывает E1 Native. Freeze/red до source, targeted/own/full gate и read-only DB snapshots. Native skips не являются Windows pass.

## Event

`_events.create_event()->NativeEvent` — explicit I/O, manual-reset unnamed non-inheritable initial nonsignalled. Issued process-local uncopiable объект, private `_io_abi.IO` factory; safe constant repr. `.set()->None`, `.is_set()->bool` (WaitForSingleObject с timeout0), `.close()->None` idempotent. Native errors sanitized WindowsRuntimeError runtime_unavailable. `.handle()->int` borrowed trusted wait/launcher capability, non-inheritable; forged/closed/foreign process→invalid_handle. Нет ResetEvent публичного API и named global event. Temporary inheritable duplicate делается отдельным owned HANDLE, original flags не меняются. Close допускается только после прекращения собственных waits; caller loop несёт это обязательство, не закрывать handle из Stop-потока. Signal разрешён из другого thread, close защищён коротким object mutex, но mutex сам не превращает foreign wait в safe close.

## Pending operation

`_pending` — private lifetime engine. У каждого endpoint максимум одна pending operation; strong process-local registry максимум64 записей, reservation **до** native submission, cap→runtime_busy без native call. Новый process origin проверяется до mutex. Import не создаёт OS objects/threads. Полная операция содержит неизменяемую запись buffer≤64KiB, свой OVERLAPPED и свой manual-reset event. Connect использует zero payload и тот же lifecycle. OVERLAPPED с Windows x64 layout: ULONG_PTR Internal/InternalHigh, DWORD Offset/OffsetHigh union-compatible storage, HANDLE hEvent; size32, hEvent offset24.

`PendingIO.poll()->IOResult|None`: GetOverlappedResult(handle,overlapped,bytes,FALSE), никогда bWaitTRUE. Incomplete996→None. Terminal success/aborted995/broken-pipe109/failure снимает registry reservation и pending endpoint ровно один раз; release event/buffer только после terminal status. Immutable IOResult: kind read/write/connect, count:int, data:bytes repr=False, eof:bool, aborted:bool. Read broken-pipe→eof; write broken-pipe→safe error. Zero successful read/write reject как отсутствие progress; connect bytes undefined/игнорируются. Partial read/write valid, count<=submitted size; caller отвечает за оставшиеся bytes. Cancelled completion не successful data. Repeated poll после terminal возвращает тот же result/error, не новый native call. При terminal error тоже освобождаются собственные ресурсы, но native error text не раскрывается.

`PendingIO.cancel()->None`: CancelIoEx(handle,exact OVERLAPPED), ERROR_NOT_FOUND1168 допустим, **не** terminal proof. Cancel fault sanitized, record живёт до actual completion; повтор cancel coalesced, no infinite retries. Даже после cancel normal completion возможно и проверяется, local Stop выше запрещает publication. Потеря пользовательской ссылки не освобождает native buffer: strong registry удерживает pending record/endpoint. No finalizer thread/implicit cancellation on GC. Нельзя выдавать success очистки по одному CancelIoEx. Poll owner loop обязателен; при permanently missing completion bounded record остаётся, новый attempt не допускается поверх старого slot.

Native submission возвращает TRUE→проверить completion; FALSE+ERROR_IO_PENDING997→pending; FALSE+другая ошибка→terminal с правильной очисткой. Для connect ERROR_PIPE_CONNECTED535 — уже соединённый endpoint, не pending kernel request; manual event signal и synthetic connect completion допустимы. При synchronous failure без зарегистрированного kernel request можно сразу освободить record. Не считать произвольное исключение после submission доказательством отсутствия pending IO: retain/cancel/probe при неопределённом исходе. Один exact native call на submission, no retry чужого handle.

`PendingIO.event_handle()->int` — borrowed event HANDLE только пока операция pending. После terminal completion invalid_handle. Wait set строит тот же I/O owner thread; другой поток может cancel, но не poll/close/release event из активного wait set.

Endpoint/pending poll/begin/close принадлежат одному I/O thread с первой submission, без ожиданий под metadata mutex. Cancel допускается из другого thread. Setup connect owner освобождается только после подтверждённого completion перед возвратом pair. Future S data pump и G loop сами закрывают свои IO endpoints в finally; S.stop только signal/cancel, не close event из активного wait set. Если close вызван не owning thread при активном I/O lifecycle — invalid_handle, не native close. Не использовать CloseHandle для отмены pending IO.

## Pipe pair

`_pipes.create_pipe_pair(*, deadline_ns:int, clock, synchronous_writer=False)->PipePair` — explicit trusted factory. Deadline exact int0..signed63, `clock.now_ns()` explicit sleep-counting WindowsClock-compatible private test port; setup cutoff=min(deadline,now+2s), без reanchor при poll. Invalid scalar/boolean config→validation_error до native calls. Native IO factory platform check до DLL load. Pair issued process-local, reader/writer endpoints; safe repr без pipe name/bytes/handle. `.close()->bool`: best effort обе стороны; True только все closed, False при pending cancellation, safe error при native failure; не терять references нужных pending records.

Создать случайный UUID128 name `\\.\pipe\aira-<hex>`; один CreateNamedPipeW inbound server, FIRST_PIPE_INSTANCE|OVERLAPPED, maxInstances1, byte stream/PIPE_WAIT/REJECT_REMOTE_CLIENTS, buffers64KiB, explicit canonical protected current SID/SYSTEM/Administrators DACL. Setup не создаёт app directories и не читает environment/secrets. First ConnectNamedPipe overlapped; затем собственный CreateFileW client write с OVERLAPPED, либо synchronous flag для M diagnostics. Peer PID у обоих ends до handoff равен GetCurrentProcessId; collision/foreign peer→error без retry/reconnect name. Names не являются authenticator против same-user attacker; его security sandbox не заявляется. Pair существует только до закрытия его HANDLE, не постоянный server.

Setup loop completion waits<=100ms и повторный clock перед каждым действием; old cutoff equality→abort. Pending Connect cancellation сохраняет record до terminal completion; factory error не теряет его. При исключении закрыть только созданные и quiescent handles, pending оставить strongly retained с cancel requested. Нет WaitNamedPipe(INFINITE), FlushFileBuffers, sockets, shell или блокирующего anonymous CreatePipe.

`reader.begin_read(size=65536)->PendingIO`, `writer.begin_write(data:bytes)->PendingIO`: direction-specific, exact size1..65536/bytes1..65536; invalid input без IO/mutation. Только overlapped endpoints; synchronous writer не имеет Python blocking write метода, только borrowed handle для trusted child/fixture. Один outstanding per endpoint→runtime_busy. Owned stable bytes/buffer не выдаются наружу до completion. User-facing ошибки/DTO не содержат diagnostic bytes.

`endpoint.handle()->int`: borrowed, только live issued capability. `.close()->bool`: без pending invalidate/CloseHandle один раз→True; с pending cancel+nonblocking poll; incomplete→False с сохранением record, completion→close. Terminal poll error: закрыть quiescent endpoint и сообщить safe error, не false success. Close не ждёт и не делает fork/extra threads. Повтор после fully closed→True. Parent не принимает произвольный integer как endpoint capability; trusted inherited adoption для будущего child будет отдельным E3 contract, не публичный продуктовый API E2.

Control pipe не имеет отдельной atomic-write магии: E4 использует тот же overlapped primitive для frames≤4KiB+header с bounded50ms completion, Stop event независим. Большие bytes chunks ограничены, не требуют нового protocol или изменения frozen C1C. Kernel buffers запрошены64KiB, actual capacity не предполагается точной и не используется как permission на unbounded queue.

## Приёмка

Portable: inert fresh imports/без secret/env load; ABI exact sizes/signatures; event flags/rights/process-local/forged/stale/reused handle; partial/zero/count overflow/EOF/error/aborted completion; immediate и pending submission, connect535; cancel1168, normal-after-cancel, failed cancel, missing completion; buffer/event strong lifetime через weakref/GC до terminal, registry64cap с отказом65-го до native call, endpoint busy; repeated poll/close не double-close. Direction/scalar/buffer limits, owner-thread check и concurrent cancel без CloseHandle активного event; setup UUID/DACL/flags/explicit endpoints/foreign PID/timeout/backwards clock/no reconnect/failure cleanup. Fakes фиксируют реальные native-call аргументы и outcomes, не только mirrors состояния.

Native Windows: real pair/read/write partial chunks+EOF, pending read cancellation с actual completion, full-pipe pending write+Stop event responsiveness, buffered payload delivery без trailing loss, synchronous diagnostic writer fixture, active pending GC retention, repeated100 pairs/no HANDLE growth. Все данные синтетические; timeout fixture bounded; no model/Job. На Mac native cases skipped с явным gate pending, full existing regression всё равно обязательна. После E2 на Sol подготовить E3 exact contract/freeze/red и продолжить, если нет архитектурного конфликта.
