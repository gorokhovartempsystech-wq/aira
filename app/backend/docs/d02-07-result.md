# D02-07 — чтение и скачивание DOCX через HTTP

30 октября 2026. Реализован [контракт D02-07](d02-07-contract.md), часть F11/F12 [текущего объёма](current-product-scope.md). Добавлены три GET-маршрута локального API: список `/docx-documents`, сведения `/docx-documents/{document_id}` и текущий файл `/docx-documents/{document_id}/content`. Установка выполняется только при явном `DocumentRuntime`; фабрика без runtime сохраняет прежнее поведение.

Список и сведения содержат семь полей метаданных без bytes, оригинала и внутренних идентификаторов владельца/проекта. Скачивание возвращает точные bytes текущего DOCX. Безопасное имя файла строится из UUID; MIME, длина, SHA-256 в ETag и ревизия хранения соответствуют одному прочитанному snapshot. Успешные ответы имеют `Cache-Control: no-store`. Range и условное скачивание пока не поддерживаются: ответ содержит полный файл.

Действуют прежние ограничения доступа и безопасные ошибки local-dev API. Query-параметры проверяются до обращения к сервису: ASCII-цифры, пределы значений и длины, запрет неизвестных и повторных ключей. Метаданные/файл проверяются существующим `get_docx`, список использует metadata-only `list_docx`. Новые HTTP-обработчики работают в штатном threadpool. Сервис, БД, зависимости и прежние маршруты не изменялись; `app.py` получил только импорт и вызов установки. OpenAPI сохраняет точные целочисленные границы BIGINT и описывает бинарный DOCX.

Проверены скачивание синтетического rich-source.docx без изменения bytes, чтение после service-save и нового app/engine, MIME/имя/хеш/длина/ревизия, отсутствие DML, порядок/пагинация, изоляция проектов, повреждение файла и безопасная ошибка хранения. Три дополнительных собственных случая проверяют последнюю ревизию BIGINT, один snapshot на скачивание, запрет query до чтения и отсутствие заголовков скачивания в ошибочном ответе. Визуальный рендер не повторялся: цикл не меняет DOCX. Microsoft Word этим не проверен.

Все прежние адреса присутствовали, но строгая проверка запрещала дополнительные.

В старом тесте добавлены ровно три строки ожидаемого набора; все прежние адреса, остальные утверждения и строгое равенство сохранены. Отдельная проверка текста подтвердила точность изменения и совпадение независимой приёмки D02-07 с подготовительным коммитом `0d59840`.

## Автоматический запуск и отличие от ручной реализации

Ralph был запущен в отдельной копии из подготовительного коммита, со своей PostgreSQL. Пользователь выбрал экономичную модель; локальная обёртка CLI добавила только штатные параметры `--model gpt-6.1-sol -c model_reasoning_effort='"high"'`. Runner, его prompt, схема результата и preset разрешений сохранены. Авторизация, провайдер, квота и постоянные настройки не менялись; секреты не читались.

Запуск `.ralph/runs/D02-07-20261030T082550Z-05bab027` остановился до работы исполнителя: CLI вернул HTTP 400 `model_not_found`, «The 'gpt-6.1-sol' model is not supported when using Codex with a ChatGPT account». Runner записал **blocked / agent_process_failed**, agent exit 1, check exit null. Это несовместимость выбранного идентификатора с отдельным CLI, а не отказ автоматической проверки разрешений. Внутренняя реализация и независимый gate runner не состоялись.

Разработка затем выполнена непосредственно в основном чате на текущем Sol с той же замороженной приёмкой и общим gate. Точные runner-produced tasks/progress и каталог логов перенесены без ручного изменения статуса. **D02-07 остаётся blocked в runner**, даже при прошедших прямых проверках; автоматическое завершение не заявляется. Для будущего запуска Ralph нужно отдельно определить поддерживаемый CLI идентификатор модели. Следующий цикл не запускался.

## Ограничения

Это read-only технический API. HTTP-импорт и сохранение, интерфейс и файловые диалоги, таймер автосохранения, анализ, активация лицензии и полная совместимость DOCX остаются дальнейшими задачами. Local-dev контекст не является пользовательской авторизацией. Рабочий архив и параллельные артефакты не использовались.

После первого прогона основная схема V6 и счётчики строк совпали со снимком начала задачи; содержимое строк не читалось. Временных `ara_check_*` баз не осталось, основная `ara_test` пуста. Изолированные `ara_dev`/`ara_test` также пусты. Оба PostgreSQL штатно остановлены с сохранением данных. Снимки: `.runtime/d02-07-start-runtime.json`, `.runtime/d02-07-final-runtime.json`, `.runtime/d02-07-isolated/.runtime/d02-07-final-runtime.json`. После финального зелёного прогона повторная проверка подтвердила ту же схему, счётчики строк и отсутствие временных БД; основная PostgreSQL вновь штатно остановлена.
