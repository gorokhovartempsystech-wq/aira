Прочитан официальный локальный dictionary `/Applications/Microsoft Word.app/Contents/Resources/Word.sdef`: open/read only/add to recent files, text range/text retrieval mode/include hidden text/include field codes. Probe inputs полностью синтетические: direct gap и plain `AIRA CONTROL`, каждый в собственном UUID-named DOCX. Первый вызов обнаружил особенность automation open: document result не был доступен последующему коду (`-2753`); проба исправлена на адресацию по уникальному имени своего файла. Ни одна попытка не дала пригодного observed text. Причина самого Word/UI timeout не установлена; это не доказательство отсутствия Word, доступа к файлам или конкретного модального окна.

SHA тестовых источников до/после совпали. Закрытие только собственных тестовых документов выполнено отдельно; результат записан в ignored observations. Возврат к b2a2c после восстановления измеримого native gate. Отдельный B1 не снимает DOCX coverage blockers и не заменяет реальную модель.

Приёмка native reader не пройдена из-за конкретного automation blocker; это результат исследования, не завершённая реализация c. Продуктовый scope сохраняется. ## Повторная проверка по просьбе Никиты

Никита попросил проверить ещё раз и сообщил, что лицензии Microsoft у него нет. При повторе Word открыл контрольный DOCX, но setter `include hidden text` вернул **-10006**. Причина setter error не установлена: возможны ограничения read-only/automation/активации, конкретная связь с лицензией не доказана. [Microsoft](https://learn.microsoft.com/en-us/microsoft-365-apps/mac/overview-of-activation-for-office-for-mac) описывает reduced functionality как чтение/печать без создания/редактирования; из этой общей справки нельзя вывести причину конкретного AppleScript error.

Вместо setter выполнено read-only наблюдение font.hidden по каждому физическому character range. Для direct gap Word вернул **`abcd\r`**, hidden mask **`00111111000`**: два видимых символа, шесть hidden, два видимых и retained mark. Это согласуется с AIRA b2 на данном синтетическом случае. Source SHA до/после совпал: `0ddb980b72b6ae6529dd18c981c2fd9fb58c024eb0553123c2d099ff56b38b86`. `.runtime/d03-17a2b2a2c0-font-probe.applescript` / `-font-observation.json`. Режим отображения/Final не переустанавливался; ordinary range.content и font.hidden не доказывают visual paragraph layout/specVanish/revision context.

Подготовлен bounded batch с plain/direct/character/default/toggle/paragraph-mark cases, но самый первый **новый plain source** опять получил AppleEvent **-1712**, после чего batch остановлен. Остальные cases не запускались; не считать план из21 cases выполненным corpus. `.runtime/d03-17a2b2a2c0-batch.py` / `-native-results.json`. Таким образом, отдельный successful read воспроизвёл direct hidden gap, но повторяемый измеритель ещё не получен. Прежний conservative boundary guard остаётся обязательным. Повторная cleanup адресует только свои UUID-named test files, без закрытия приложения/чужих документов: общий retry не дал подтверждения; отдельный заключительный cleanup последнего файла прошёл (`-last-cleanup.json`, cleanup_confirmed=true). Предыдущие свои файлы были закрыты в успешном/error-handler probe.

Никакого обхода лицензирования/активации/ограничений Office не выполнялось. Приложение AIRA не требует установки Word для штатной работы: Word нужен здесь для native QA; чтение/сохранение DOCX выполняют собственные модули. Independent D03-17B1 продолжать на Sol. Source/tests после regression gate не менялись; это дополнение наблюдений текущего evidence-cycle, не новая реализация c и не уменьшение оценки оставшейся работы.
