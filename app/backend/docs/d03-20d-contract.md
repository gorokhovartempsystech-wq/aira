# D03-20D — вставка новой таблицы

9 ноября 2026. F05/F11/F12, запрос команды о недостающей команде создания
таблиц, продолжение автономной разработки, разрешённой Никитой.

Добавить `insert_table` в существующую командную шину редактора. Значение:
`{rows, columns}` — целые положительные размеры, технические пределы 100 строк,
32 столбца и 1024 ячейки. Пустая таблица вставляется в свёрнутую позицию курсора
основного текста; абзац разделяется с сохранением обеих половин и оформления.
После таблицы остаётся абзац для продолжения текста. Вся операция — один шаг
undo/redo и один номер команды. Ячейки редактируются уже существующим
TableEditorSession. Вложенные таблицы и сложные неподдержанные позиции не
включаются автоматически.

Пути: новый модуль `docx_package/editor/_objects.py`, методы `_session.py`,
командные DTO/декодирование/схема в `docx_editor`, список действий JS protocol,
новые acceptance-тесты и документация. Новых HTTP endpoints, SQL и зависимостей
не требуется. Прежние тесты и runner не меняются.

Проверить разделение Unicode-текста, XML/пакетную сохранность остальных частей,
геометрию таблицы, ввод в ячейки, точный undo/redo, отказ без изменения истории,
устаревшую ревизию, HTTP replay/CAS, сохранение и повторное открытие.

Макет таблицы: равные столбцы, тонкая видимая сетка, ширина не больше
доступной ширины раздела/колонки и 6 дюймов. Внешние XML-части, изображения,
стили и исходные байты пакета вне изменяемого главного XML сохраняются.
На неподдержанной границе отказ происходит до публикации изменения.

## Целевые результаты

До реализации 10 новых проверок были красными. Команда, HTTP replay,
сохранение/восстановление и прежний клиентский протокол: **88 passed**.
После дополнительной проверки повреждённого native DTO: **13 passed**
в чистом наборе вставки (HTTP уже проверен выше). Общий gate — на финальной
последовательности. Кнопка frontend остаётся задачей интеграции Ани.
