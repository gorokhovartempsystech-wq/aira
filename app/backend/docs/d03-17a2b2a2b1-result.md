Существенная граница результата: query ещё не является распознанным XML run. Этот batch не доказывает отсутствие table/numbering/revision/hidden-boundary context и не даёт допуска к ML. Полный main reader должен сам построить queries из тех же saved bytes, связать direct properties со source anchors, учесть excluded gaps/boundaries и доказать completeness. Новая policy не переинтерпретирует старые snapshots/results/hide decisions.

Конкретный дополнительный case для b2/Word corpus: неявный default character со свойством false при docDefaults=true. В b1 это намеренно фиксированная algebra/neutral-default convention контракта, а не подтверждённое поведение Word. Повторно прочитано [описание rStyle Microsoft](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.runstyle?view=openxml-3.0.1), в котором при отсутствии ссылки character style не применяется. Мой вывод для handoff: нельзя подменить проверку взаимодействия default flags/document defaults выводом о «нейтральности» false относительно любого D; нужен явный admission guard либо native evidence в новом main profile. Frozen b1 не переписывать ради такого изменения: при необходимости другой capability/profile по новому контракту. Это ещё одна причина архитектурного review перед подключением к полной проверке.
