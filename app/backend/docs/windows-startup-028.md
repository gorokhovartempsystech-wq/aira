# W08 — замечания Ани к Windows и странице скачивания

14 ноября 2026. Источник — сообщения и скриншоты Ани в командном Telegram:
непонятная кнопка со стрелкой; объяснение устанавливаемых компонентов; пропущенный
выбор папки; SmartScreen; долгое ожидание и зависание на «Загружаем модель…».

## Изменения

- Кнопка закрытия на лендинге — «Хорошо», без стрелки. Требования объясняют модель,
  Python, PostgreSQL, обновления и WebView2. Отдельная страница в установщике
  показывает состав пакета до установки. Файлы не загружаются тайно дополнительно.
- Inno Setup DisableDirPage=no: выбор папки виден и при обновлении. Пользовательские
  данные по-прежнему отдельно, выбор папки программы не переносит их.
- Исправлен воспроизводимый путь: Uvicorn при ошибке lifespan выходит SystemExit,
  который раньше мог завершить boot-thread мимо except Exception, оставив спиннер.
  Причина ошибки захватывается до SystemExit; recovery_required сохраняется для
  существующего безопасного подтверждения восстановления.
- Старт показывает действительные этапы: хранилище, целостность модели, сервер,
  интерфейс. Проверка файлов не называется загрузкой ONNX-сессий. Есть прошедшее
  время и безопасные отметки этапов в журнале.
- Проверка целостности читает все bytes и сверяет прежний SHA256. Checkpoint между
  блоками позволяет сообщить о превышении времени, не пропуская проверку файлов.
- Локальный DB connect_timeout=5s, lock_timeout=5s, statement_timeout=30s; контроль
  подготовки сервера 120s и ожидание готовности Uvicorn 90s. PG initdb/pg_ctl имеют
  собственные пределы 120s / 90s. Это сроки прекращения ожидания с ошибкой, а не
  обещание успешного запуска за это время на любой машине. Заблокированный системный
  read может задержать выполнение checkpoint до возврата ОС.

## Проверка

Новые тесты: остановившийся сервер/SystemExit; сохранение причины recovery_required
в настоящем Uvicorn lifespan; ограниченное ожидание живого сервера; готовый сервер;
deadline проверки пакета; совпадение identity с checkpoint/без него; обнаружение
подмены и прерывание проверки. Windows CI устанавливает EXE и дважды запускает его
на одном профиле, сохраняя прежние обязательные проверки native bridge и экрана активации.
Самопроверка запрашивает обычное закрытие с prepareToClose/close_result вместо
преждевременного destroy, чтобы не освобождать semaphore pywebview одновременно
с подтверждением закрытия. Ненулевой exit code остаётся ошибкой проверки; stderr
нативного процесса и номер попытки выводятся только для синтетического CI-профиля.

Получены старые журналы Ани от 7–8 ноября, версия 0.2.0. Они показывают две
последовательные проблемы: initdb с кириллицей в пути (затем успешно обойдён через
короткие имена Windows); сбой cleanup при закрытии, после которого следующий старт
блокировался recovery_required и завершался SystemExit: 3. Последний путь покрыт
регрессией настоящего Uvicorn. Свежих журналов от 14 ноября пока нет: нельзя
отождествлять текущий сбой со старым только по сходству экрана. Не следует удалять
базу или снимать произвольную блокировку: подтверждаемое восстановление прежнего
завершённого запуска сохраняет прежние условия безопасности.
Пользовательские журналы и файлы домашнего задания в Git и тесты не копировались.

Первый нативный прогон обнаружил конфликт URL options с ограниченной конфигурацией
supervisor. URL оставлен допустимым; тайм-ауты редактора передаются только его
движку через connect_args, а supervisor сохраняет собственные более строгие лимиты.
Добавлена отдельная регрессия совместимости реального URL с supervisor.

## SmartScreen

У пилотного EXE нет Authenticode-подписи издателя. Подпись обновлений Ed25519
подтверждает целостность для updater, но не заменяет сертификат Windows.
Репутация SmartScreen — отдельный механизм, новая сборка может вызвать предупреждение.
Защита Windows не отключается. Основание: документация Microsoft
https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation

Windows патч — 0.2.8; Mac остаётся 0.2.7, поскольку его установщик этим исправлением
не меняется. Публикация Windows разрешена только после успешной установки и запуска
готового EXE; существующий опубликованный 0.2.7 не перезаписывается.
