# D03-09 — генерация нового DOCX по базовому шаблону AIRA

30 октября 2026. Одна задача F04/F05/F11 после D03-08. Никита согласовал базовый шаблон: A4, обычный текст 11 пт, три уровня заголовков, маркированные и нумерованные списки. D03-09 создаёт чистую основу DOCX в памяти; HTTP/кнопка создания, сохранение в PostgreSQL и структурные операции редактора будут отдельными задачами. Импортированные документы этот генератор не переписывает.

## API и границы ввода

Новый модуль `ara.docx_package.creation` экспортирует `NewParagraph(text: str = "", style: str = "body")`, `CreationLimits(max_paragraphs: int = 1000, max_text_chars: int = 1000000)`, `CreationError` и `create_docx(paragraphs: tuple[NewParagraph, ...] = (), *, creation_limits: CreationLimits | None = None, limits: DocxLimits | None = None, projection_limits: ProjectionLimits | None = None) -> bytes`.

DTO frozen/slotted; repr NewParagraph не показывает текст. В вызове перепроверяются настоящие типы, включая поля изменённых обходом frozen объектов. paragraphs — настоящий tuple, элементы — NewParagraph, text/style — настоящие str. Подклассы/генераторы/mappings/bytes не принимаются. Допустимые style: body, title, heading1, heading2, heading3, bullet, numbered. Неверные данные дают CreationError invalid_input. CreationLimits — положительные настоящие int с включительными границами. Пустой tuple создаёт один пустой body-абзац, который считается в лимите. Сумма text_chars считается в Unicode code points до XML escaping и включает все абзацы. Превышение — generation_limit_exceeded. Нижние DocxLimits/ProjectionLimits проверяются существующими API, их ошибки и ограничения не маскируются.

Текст сохраняется буквально без trim, Unicode normalization, Markdown/HTML parsing или автозаголовка из имени файла. Разрешён XML 1.0 Unicode, включая supplementary characters. LF создаёт настоящий w:br, TAB — w:tab, последовательные/краевые LF/TAB и пробелы сохраняются в проекции. CR (включая CRLF), NUL, запрещённые control/noncharacters XML 1.0 и lone surrogates отклоняются, а не нормализуются. Новый абзац задаётся отдельным NewParagraph; символ LF — разрыв строки внутри абзаца. Пустой text сохраняет пустой редактируемый w:t. Никаких данных пользователя, примера, фиктивного анализа или обязательного текста в пустом документе.

## Шаблон версии 1

Transitional WordprocessingML; A4 11906×16838 twips, все четыре поля 1134 twips (20 мм). Arial для ascii/hAnsi/eastAsia/cs, normal 22 half-points (11 пт), чёрный цвет, язык ru-RU. Межстрочный интервал 276/240 (1,15), после обычного абзаца 120 twips (6 пт), widowControl. Никаких декоративных линий, титульной страницы, колонтитулов, полей, комментариев, ревизий или скрытого пользовательского текста.

Настоящие paragraph styles: Normal; Title 44 half-points (22 пт); Heading1/2/3 — 32/26/22 half-points (16/13/11 пт), bold/black с outlineLvl 0/1/2. У title/headings keepNext и keepLines, следующий стиль Normal; у headings интервалы before 240/180/120, after 120/100/80 twips; title after 240. Заголовки не имитируются текстом. Heading style_id остаётся доступным прежней проекции. ListBullet/ListNumber основаны на Normal, после 60 twips.

Списки пока одноуровневые: настоящий numPr ilvl=0, маркер bullet «•» либо decimal «%1.». Indent left=360/hanging=360 twips, tab stop num=360. Соседние numbered абзацы составляют одну последовательность; любой другой style прерывает её, следующая начинается с 1 через отдельный numId и startOverride. Bullet использует отдельную numbering definition. Маркеры не включаются в текст w:t. Многоуровневые списки/таблицы/изображения и inline rich text не входят в API этой задачи; их сохранение в импортированных DOCX остаётся прежним.

Пакет содержит только семь частей: [Content_Types].xml, _rels/.rels, word/document.xml, word/_rels/document.xml.rels, word/styles.xml, word/numbering.xml, word/settings.xml. Все связи внутренние, без template reference, макросов, внешних шрифтов/URL, core properties с именами/датами. Settings — только compatibility mode 15. ZIP — фиксированный порядок, timestamp 1980-01-01, UTF-8 XML, без случайных IDs и текущего времени. Одинаковый ввод даёт одинаковые bytes на одном runtime. Перед возвратом результат обязательно проходит прежний project_docx с переданными нижними лимитами; blank/document text и numbering/style anchors пригодны для прежнего session/editing. Новых служебных AIRA-замечаний нет.
