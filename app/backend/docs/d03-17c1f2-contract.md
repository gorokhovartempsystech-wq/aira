## Схема и полномочия

Одна logged table, slot_key1, positive bigint revision, closed phase/NULL shapes по DDL. Нет payload/timestamp/PID/paths/FK/cascade и auto increment. Seed unprovisioned revision1 без installation/owner/binding. Missing row не восстанавливается автоматически. Новая migration не делает существующую установку clean. Downgrade: ACCESS EXCLUSIVE table lock, строго одна допустимая unprovisioned row, затем DROP; иначе fixed RuntimeError('Cannot downgrade a provisioned analysis supervisor'), полный rollback. Не очищать clean/armed/drained ради downgrade.

Trusted low-level services доступны прямым import новых модулей, не HTTP/client command. OS owner/root provisioning/own I/O quiescence подтверждает caller S/installer по C1F; helper не принимает bool force/rebooted/cleanup. record_drained — запись уже полученного proof, не его источник. F3 обязан вызвать его только после physical proof либо точно отсутствовавшего OS call и завершения собственных jobs. clear_drained вызывается лишь после slot release/probe под owner. Нет API для снятия armed после смерти S: take_ownership его отвергает. Новые UUID не сбрасывают row.

DTO frozen/slotted/safe metadata: OwnerBinding(installation_id,owner_epoch); LaunchBinding(owner,launch_id,document_id,run_id,attempt_id,worker_instance_id,claim_fence=1); FenceView(revision,phase,installation_id,owner_epoch,binding|None); ClaimReceipt(claim:WorkerClaim|None,state:RunState,replayed=False); HeartbeatReceipt(accepted,state,heartbeat_at:datetime|None). Claim/source repr прежние private. Ошибки SupervisorStorageError только fixed codes: validation_error, storage_conflict, recovery_required, storage_unavailable, storage_error, queue_overflow. DocumentError scoped/lower-layer сохраняются sanitized.

## Ledger API

Все методы ниже explicit transactions; возврат только после COMMIT. expected_revision exact positive int<2**63-1; все UUID exact. Операция сравнивает phase/owner/полный binding/revision под FOR UPDATE. Повтор допустим лишь если текущая revision=expected+1 и **все** desired fields совпадают; возвращается то же состояние без нового UPDATE. Другие stale/reordered requests — storage_conflict. UUID не являются physical proof.

- `read_fence(engine)->FenceView`: ordered ledger lock/barrier, missing/invalid→recovery_required.
- `provision_new_database(engine,*,installation_id,expected_revision)->FenceView`: unprovisioned→clean с owner None, только при отсутствии записей во всех четырёх analysis tables. Доверенный installer должен дополнительно знать, что root/DB новые и legacy processes не запускались; код не выводит это из пустой таблицы. Advisory enqueue lock перед ledger; не устанавливает production provisioning.
- `take_ownership(engine,*,owner,expected_revision)->FenceView`: clean/drained, installation exact, owner_epoch заменяется новым под OS owner; armed/unprovisioned→recovery_required. При drained старый worker binding сохраняется, новый owner не получает права повторять inference. Binding DTO отражает новый owner.
- `arm_launch(runtime,claim,*,binding,expected_revision)->FenceView`: project→document→run→attempt→ledger. Validate local scope, accepted scope, exact claim/source/request metadata; running/fence1/live SQL lease, clean owner. Затем clean→armed с полным binding. S проверяет continuous budget до и после ACK; отсутствие ACK не разрешает create. Replay armed той же операции допустим как SQL receipt, не как разрешение повторного create.
- `record_drained(engine,*,binding,expected_revision)->FenceView`: ledger-only armed→drained, exact current binding; не читает status как substitute physical proof.
- `clear_drained(engine,*,binding,expected_revision)->FenceView`: ordered run/attempt locks, затем ledger; exact identity и terminal SQL outcome (existing expire допускается). Для success result row/digest/binding обязаны соответствовать terminal run. Затем clean без launch fields. Это reconciliation durable metadata, **не** source-backed UI result reconstruction; B2/C1B restore остаётся обязательным перед показом результата. Удалённый run/attempt, чужой binding, не terminal→отказ; ledger сохраняется. Replay clean с expected+1/owner exact допустим, пока не было следующей операции.

Ledger-only операции не ждут run locks. Ни один путь не получает ledger перед ожиданием project/document/run. Никакой сброс fence от reap/delete/cancel. Не брать advisory вместе с последующим обратным порядком locks.

## Scoped lifecycle API

`claim_exact(runtime,*,document_id,run_id,attempt_id,worker_instance_id,owner,limits=None)->ClaimReceipt`: фиксированный ID попытки генерирует S до job. Только указанный scoped queued run, без глобального claim_next. Первый ordered check → source/prepare_attempt вне locks → fresh ordered recheck + ledger clean owner check последним → atomic run/attempt. Бюджет/ошибки/constraints B3B сохраняются. То же running identity при потерянном ACK возвращает исходный claim/request/claimed_at/deadline/lease, без нового UPDATE/anchor/attempt. Expire не оживляет lease; foreign owner/worker/attempt не захватывает run. При terminal claim=None. S не использует replay для повторного inference; после restart running не возобновляется.

`heartbeat(runtime,claim,*,owner,stage=None)->HeartbeatReceipt`: exact scope/token, ledger owner+armed/drained binding, running/fence1/live lease, monotone stage. Тот же transaction clock_timestamp записывается heartbeat_at и возвращается в receipt вместе с lease; heavy source validation не выполняется в этой transaction. Rejected receipt heartbeat_at=None. `read_heartbeat(...)` — тот же ordered barrier без продления; пригоден лишь с сохранённым original s_h, не новый anchor от чтения. Source/run claim fields повторно не доверяются без SQL bindings.

`snapshot_queued(engine)->tuple[QueuedRun,...]` под старым advisory lock, sorted IDs, limit17; >16→queue_overflow без частичного допуска. `retire_queued(engine,item)->RunState` после освобождения advisory: обычные unscoped internal ordered locks/recheck, queued→failed/interrupted либо existing expiry/cancel/terminal; running не переисполняется. Это startup-only privilege S, не пользовательский endpoint. Old global reap_expired остаётся reusable, без изменения его реализации.

## Database API

`create_engines(settings:DatabaseSettings)->SupervisorEngines` лениво создаёт три разных engine admission/control/publication, pool_size1/max_overflow0/pool_timeout0.5s, connect_timeout2s. Только один explicit local endpoint (Unix socket или numeric loopback); DNS/multi-host/service lookup и подмена options не принимаются. Startup options: lock_timeout500ms, statement_timeout2s, idle_in_transaction_session_timeout2s, transaction_timeout5s, synchronous_commit=on. Caller явно передаёт уже загруженные настройки; import/construction не читает ~/secrets.env/сеть/БД, URL не выводится в repr/error/log.

`check_database(engine)` explicit read-only probe: PG>=17, fsync/full_page_writes/synchronous_commit on, writable primary и V11. Неподтверждённое→recovery_required/storage_unavailable. Это не global SET. `.dispose()` только после завершения всех jobs caller; не прекращает чужой active connection и не доказывает rollback. Тайм-аут не создаёт replacement job/connection. Per-job ownership и общий caller wait budget — F3.
