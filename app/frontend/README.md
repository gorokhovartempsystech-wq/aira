# AIRA — фронтенд

Интерфейс настольного приложения AIRA. Он работает поверх API бэкенда и клиентских модулей `app/backend/src/ara/desktop/client`. Объём функций соответствует [current-product-scope.md](../backend/docs/current-product-scope.md) (F03–F12).

Это обычные HTML/CSS/ES-модули: без сборки и без внешних зависимостей. Нужен браузерный движок Chromium 105+ или Safari 17.2+ — ради CSS Custom Highlight API, которым подсвечиваются замечания.

## Запуск на Windows (dev-стенд)

Нужны Python 3.12 с `app/backend/requirements.lock` и PostgreSQL 18 (тестовая база на `127.0.0.1:15435`, пользователь `postgres` без пароля).

```powershell
powershell -ExecutionPolicy Bypass -File app\frontend\dev\start-dev.ps1          # тестовый анализ (fixture)
powershell -ExecutionPolicy Bypass -File app\frontend\dev\start-dev.ps1 -Analysis model   # модель из app/backend/ml_bundle
powershell -ExecutionPolicy Bypass -File app\frontend\dev\start-dev.ps1 -Reset   # пересоздать тестовую базу
```

### Настоящая модель

Веса в Git не хранятся, они лежат в релизе `models-0.2m` приватного репозитория. Нужен доступ и `gh auth login`.

```powershell
gh release download models-0.2m -R gorokhovartempsystech-wq/aira --dir C:\AIRA-models   # архив + .sha256
Expand-Archive C:\AIRA-models\aira-models-0.2m.zip C:\AIRA-models
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -m pip install -r engine\requirements-engine.txt
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" tools\prepare_ml_bundle.py --models C:\AIRA-models\models-0.2m --destination app\backend\ml_bundle
powershell -ExecutionPolicy Bypass -File app\frontend\dev\start-dev.ps1 -Analysis model
```

Библиотеки модели (onnxruntime, tokenizers, numpy) ставятся в тот же Python, которым запускается сервер: воркер анализа использует его же.

Если при запуске появляется `Application startup failed` с `recovery_required`, значит, предыдущий сервер был остановлен во время работы и тестовая база осталась в состоянии восстановления. Запустите скрипт с `-Reset`: тестовые документы удалятся.

Откройте `http://127.0.0.1:8017/aira/` — именно `127.0.0.1`, а не `localhost`: клиентские модули принимают только этот адрес.

Сервер запускайте **обычным Python 3.12, а не `.venv\Scripts\python.exe`**. На Windows файл из `.venv` — это лаунчер-посредник, и через него нативный воркер анализа завершается без результата (`adapter_error`).

Сервер собирает [aira_host.py](aira_host.py): то же приложение, что `serve_local_model.py`, плюс раздача фронта (`/aira/`), клиентских модулей (`/aira/client/`) и токена сессии (`/aira/connection`). Им пользуются и dev-стенд, и установщик.

Dev-стенд [dev/serve_dev.py](dev/serve_dev.py) дополнительно даёт:
- имитацию лицензии (`/desktop/license*`). Ключ `USED…` — «активирован на другом устройстве», ключ короче 16 символов — «не найден»;
- тестовые страницы `/aira/dev-pages/`.

Это не продакшен-хост и не реализация лицензирования.

## Установщик для Windows (пилотная сборка)

```powershell
powershell -ExecutionPolicy Bypass -File app\frontend\packaging\windows\build.ps1 `
    -ModelDir C:\AIRA-models\models-0.2m -PgDir C:\pgsql      # → AIRA-Setup-0.1.0.exe (~310 МБ)
```

Нужны Python 3.12 (обычная установка, с tkinter), портативный PostgreSQL 18 для Windows, распакованная модель `models-0.2m` и [Inno Setup 6](https://jrsoftware.org/isinfo.php). `-NoModel` собирает без модели (тестовый анализ), `-StageOnly` — только папку без setup.exe.

Что внутри: Python с зависимостями бэкенда и модели, PostgreSQL (bin, lib, share), бэкенд **без изменений**, модель (`prepare_ml_bundle.py`), фронтенд и запускатель [aira_launcher.pyw](packaging/windows/aira_launcher.pyw).

Как работает установленная AIRA:
- ставится для текущего пользователя без прав администратора в `%LOCALAPPDATA%\Programs\AIRA`, ярлык в «Пуске» (и по желанию на рабочем столе);
- данные — в `%LOCALAPPDATA%\AIRA`: база, рабочие файлы проверки, журналы `logs\aira.log` и `logs\postgres.log`;
- AIRA открывается **в собственном окне** (pywebview + WebView2 — движок Edge, есть в Windows 10/11). Окно поднимает PostgreSQL (порт 47432) и сервер (`127.0.0.1:47017`), показывает заставку и затем приложение. Через мост `window.pywebview.api` страница получает адрес и токен (без `/aira/connection`), системные окна «Открыть» и «Сохранить как». Крестик окна сначала вызывает `prepareToClose()` (запись правок, остановка проверок); если запись не подтверждена, окно не закрывается. Затем сервер и база останавливаются;
- запасной режим — если WebView2 нет или окно не создалось: маленькое окно управления и AIRA во вкладке браузера (принудительно: `AIRA_BROWSER_MODE=1` или `--browser`);
- повторный запуск ярлыка выводит открытое окно AIRA на передний план;
- самопроверка сборки: `AIRA_SELFTEST=<секунды>` — окно загрузится, состояние страницы и закрытие запишутся в `aira.log`;
- если прошлая проверка упала и оставила блокировку (`recovery_required`), окно предложит её снять — только когда тот запуск уже завершён;
- удаление через «Программы» останавливает базу и спрашивает, удалить ли документы;
- русские буквы в пути (например, профиль `C:\Users\Анна`): встроенный PostgreSQL с ними не работает — `initdb` падает с `invalid byte sequence for encoding "UTF8"`. Поэтому запускатель передаёт PostgreSQL короткие латинские пути Windows (8.3). Если их на диске нет, база переносится в `C:\ProgramData\AIRA\<хеш пользователя>`, а установщик по умолчанию предлагает `C:\AIRA`.

Ограничения пилота: нет лицензирования и цифровой подписи (Windows SmartScreen предупредит при запуске setup: «Подробнее» → «Выполнить в любом случае»). Маршрут `/aira/connection` остаётся для запасного режима, и любой локальный процесс может получить через него токен. Готовые установщики — в Releases репозитория (`aira-desktop-*`).

## Сурикат и обучение

- **Ошибки и предупреждения** (`toast(..., 'error' | 'warn')`) показывает сурикат. Он выглядывает из норки в правом нижнем углу, удивлённо смотрит на сообщение и предлагает действие («Повторить») или «Понятно». Обычные сообщения остаются строками внизу. Ошибки в шторке проверки и на экране лицензии тоже показываются с удивлённым сурикатом.
- **Обучение** запускается при первом старте: 7 шагов по стартовому экрану. При первом открытии документа — ещё 6 шагов по редактору и проверке. После обучения карточка «Учебный пример» уходит со стартового экрана; кнопка «?» справа вверху открывает меню «Пройти обучение» и «Открыть учебный пример». Пройденные шаги запоминаются в `localStorage` (`aira.tour.start`, `aira.tour.doc`).
- Анимации отключаются, если в системе включено «уменьшить движение».

## Список документов

У бэкенда нет запроса на удаление документа: есть только удаление черновика правок. Поэтому «Убрать из списка» (значок глаза) скрывает документ только в списке и только на этом компьютере (`localStorage`, `aira.hiddenDocs`). Скрытые можно показать и вернуть. Для настоящего удаления нужен маршрут в бэкенде — это вопрос к Никите.

## Как работает редактор

- Набор текста внутри абзаца браузер применяет сразу. Примерно через 0,6 с после паузы правка уходит одной командой `range_edit`.
- Enter, Shift+Enter, Backspace/Delete на стыке абзацев, вставка нескольких строк, отмена и повтор, стили и списки — отдельные команды бэкенда (`enter`, `insert_soft_break`, `join_previous`/`join_next`, `paste_text`, `undo`/`redo`, `format`). После каждой команды документ перечитывается из `/view`.
- Если бэкенд отказал (защищённая разметка Word, ячейка таблицы и т. п.), текст абзаца возвращается к серверной версии и показывается понятное сообщение. Если исход неизвестен, правка блокируется, а в строке статуса появляется «Повторить» — он повторяет **тот же** запрос.
- Автосохранение: через 5 секунд без правок версия документа сохраняется сама (как «Сохранить», молча). Кроме того, `createDocxSession` раз в 2 минуты записывает рабочую копию.
- Масштаб (A−/A+) работает как в Word: растут текст, ширина и поля листа, а боковые панели при увеличении сужаются. Файл не меняется.

## Отказы проверки и журнал

- Предварительный список элементов Word (`BLOCKERS` в `docx-assets.mjs`) носит информационный характер. Он **не блокирует** кнопку «Проверить» и не требует удалять содержимое. Решение принимает бэкенд по структуре исходного DOCX.
- После PR21 поддерживаются мягкие переносы, неразрывные дефисы, позиционные табуляции, известный символ галочки Wingdings, простые текстовые формулы и перечисленные ранее свойства стилей. Это не универсальная поддержка всех формул и символов: неизвестные глифы, сложная математика, VML и альтернативные описания изображений могут получить явный отказ. Исходный Word-файл Ани с неизвестным дополнительным блокером по-прежнему нужен для отдельной проверки.
- Подтверждённый `not_admitted` завершает попытку. Повторная проверка, обычный экспорт и настоящее закрытие вкладки работают через клиент бэкенда; прежний обход с закрытием только в интерфейсе удалён. Неопределённый исход запроса сохраняет защитные ограничения клиента.
- Перед закрытием интерфейс также дожидается загрузки замечаний: результат модели и получение списка замечаний заканчиваются в разные моменты.
- **Журнал диагностики:** `aira_host.DiagnosticLog` пишет запуски и отказы проверки, ошибки API с кодами, а страница — сообщения сурката и ошибки скриптов (`POST /aira/diagnostics/client`). Скачать: меню «?» → «Скачать журнал» (`GET /aira/diagnostics/log`, нужен токен сессии); в установленной версии — также кнопка «Журнал» в окне AIRA. Текст документов в журнал не пишется.
- Ошибки клиентских модулей (`transport_error`, `busy`, `conflict`, `session_expired`, HTTP 409/413/422/503) переводятся в понятные сообщения (`why()` в `main.mjs`).
- При ошибке сурикат говорит «Ой-ёй!» голосом Windows (если есть русский) или коротким сигналом; не чаще раза в 3 с, выключается в меню «?».
- Таблицы показываются полностью, текст в ячейках можно править. Картинки и другие объекты Word показываются и сохраняются, но не меняются.

## Мост к оболочке приложения

Оболочка (Electron, Tauri и т. п. — ещё не выбрана) определяет `window.airaHost` до загрузки страницы:

```js
window.airaHost = {
  connection: async () => ({ origin: 'http://127.0.0.1:<port>', sessionToken: '<64 hex>' }),
  openDocx: async () => ({ name, bytes /* Uint8Array */ }) | null,         // системный выбор файла
  saveDocx: async (suggestedName, bytes) => ({ saved: true|false, path }), // «Сохранить как» + запись
  onCloseRequest: handler => { /* перед выходом: await handler() === true → можно закрывать */ },
};
```

Перед выходом оболочка обязана вызвать обработчик из `onCloseRequest` (или `window.AIRA.prepareToClose()`) и закрывать окно, только если он вернул `true`. Обработчик:
1. отправляет недописанный текст;
2. останавливает идущие проверки;
3. дожидается текущих операций клиента и закрывает вкладки через `workspace.close()` — запись рабочих копий с подтверждением.

Если запись не подтверждена, пользователю предлагается «Повторить» или «Не закрывать»; принудительного выхода нет. Токен сессии нельзя сохранять, класть в URL или писать в логи.

Без `window.airaHost` (dev-стенд) используются выбор файла и загрузка средствами браузера. В этом случае успешную запись файла подтвердить нельзя, и интерфейс так и сообщает.

## Решения по комментариям UX (Анна) и сверка с требованиями

- **Фильтры:** «Все» и по одному типу (формулировки, дубли, противоречия) плюс «Вопросы»; чип с нулём неактивен.
  - Типы сохраняются в бэкенде для каждого документа и меняют только отображение.
  - «Вопросы» — режим показа на клиенте: бэкенд скрывает вопросы вместе с замечаниями, к которым они привязаны.
  - После новой проверки фильтр сбрасывается на «Все», чтобы свежий результат был виден целиком и были известны числа на чипах.
- **Слева** — открытые документы и список сохранённых, панель скрывается. Отдельный стартовый сценарий «недавние» требования исключают, поэтому это список документов (F12). Учебный пример в список не попадает.
- **Шторка проверки** сворачивается в полосу с иконками, как в макете.
- **Размер шрифта** (A−/A+) меняет только масштаб в редакторе: бэкенд не меняет кегль в DOCX.
- **Импорт** — только .docx и только со стартового экрана; название документа задаётся при создании и импорте.
- **Вставка таблиц и картинок:** кнопки панели вызывают `insert_table` и `insert_image`. Поставьте курсор без выделения в обычный абзац вне таблицы. Таблица: 1–100 строк, 1–32 столбца, не более 1024 ячеек. Изображение: PNG/JPEG до 4 МиБ; содержимое дополнительно проверяет бэкенд. Изображения добавляются без альтернативного описания. Работают отмена/повтор, экспорт и повторный импорт. Вложенная вставка и замена существующей картинки этим интерфейсом не предусмотрены.
- **Не добавлено**, потому что исключено требованиями: автооткрытие последнего документа, отметка частичной проверки как отдельная функция, история версий с откатом, выдуманный процент прогресса. Неполное покрытие проверки (`analysis_coverage: partial`) всё равно честно показывается.

## Проверено

На Windows 10 с настоящим бэкендом (PostgreSQL 18.3, тестовый анализ) прогнаны сценарии `dev/pages/smoke.html`:
- лицензия, создание документа, набор текста, Enter, стиль заголовка, сохранение;
- учебный пример, проверка, этапы, замечания и вопрос, фильтры, скрытие и показ, подсветка, устаревание после правки, свёрнутая шторка;
- импорт DOCX с таблицей и картинкой, правка ячейки, вставка нескольких строк, склейка абзацев, отмена, экспорт;
- закрытие приложения через `prepareToClose`;
- обучение целиком (оба тура), всплывающий сурикат при реальном предупреждении, скрытие и возврат документа в списке (сценарии `tour`, `tourshot`, `mascot`).

С настоящей моделью 0.2m (CPU, Windows 10) тестовый документ проверяется примерно за 13 с: 9 замечаний к формулировкам, противоречие «2 с / 10 с», 10 вопросов. Подсветка, фильтры, вопросы и отметка устаревшего результата работают. Модель пропустила дубль «2 секунды» и противоречие про уведомления: это ограничения модели, а не интерфейса.

Не проверено:
- качество модели на реальных ТЗ;
- нативная оболочка macOS (браузерный сценарий на macOS проверен 9 ноября);
- нативная оболочка и системный выбор файлов;
- визуальное открытие экспортированного файла в Word;
- IME (ввод через систему составления символов) и проверка орфографии на длинных документах.

```bash
AIRA_UI_ORIGIN=http://127.0.0.1:8017 AIRA_EXPECT_REAL_MODEL=1 node app/frontend/dev/tests/integration.mjs
```

Можно задать `PLAYWRIGHT_MODULE` (путь к существующему модулю Playwright) и `AIRA_CHROME_EXECUTABLE` (путь к Chrome). Без них используются обычный импорт `playwright` и его Chromium. Выгрузки и скриншот пишутся в игнорируемую папку `dev/tests/results/`.

Проверки: Word preflight → реальная модель → немедленное закрытие; вставка таблицы сразу после набора текста, размеры, правка ячейки, отмена/повтор; картинка, отмена выбора, повреждённый PNG и устаревшая позиция; экспорт → повторный импорт → анализ; отказ на alt text → экспорт → фактическое закрытие workspace. Отдельно воспроизводятся два временных `503 editor_busy` при чтении картинок: интерфейс ограниченно повторяет безопасное чтение и показывает изображение. Экспорт с таблицей и изображением отрисован LibreOffice и визуально проверен; это не проверка Microsoft Word или установщика.
