# Windows: лицензированный пилот, кандидат 0.2.7

Это исходники следующей сборки; готовый EXE здесь не объявляется выпущенным. По решению Никиты от 12 ноября 2026 Аня выполняет сборку и нативную приёмку на Windows. Публикация на сайте и в updater ждёт её результата.

## Изменения относительно опубликованных 0.2.0/0.2.1

- Реальный `LicenseClient` использует HTTPS origin из установленного `launcher/release-config.json`. Настройки профиля его не переопределяют. Ключ не записывается в конфигурацию; `ActivationStore` хранит публичную идентичность активации.
- На каждом запуске лицензия проверяется заново. До активации или при отказе доступны экран лицензии и статические файлы, продуктовые API закрыты существующим `LicensedApplication`.
- Сессионный токен передаётся в WebView2 через native bridge. HTTP `/aira/connection` недоступен. Мост отклоняет запросы, когда основное окно открыто вне локальной страницы AIRA.
- После истечения лицензии в уже открытом окне сохранение и выгрузка остаются доступными по существующему preservation-контракту. Новый запуск без онлайн-проверки доступ не получает.
- Проверка обновлений WinSparkle происходит перед запуском backend. Завершение ждёт остановки ASGI и клиента лицензии; при неподтверждённой остановке PostgreSQL не останавливается как будто завершение успешно.

**Для этого лицензированного Windows-пилота обязателен Microsoft Edge WebView2 Runtime.** Старый браузерный fallback не запускается: иначе нельзя сохранить выбранную схему передачи capability через native bridge. `--browser` и `AIRA_BROWSER_MODE` дают понятную ошибку, а не незалицензированный редактор. Автоматическая установка WebView2 этой правкой не добавляется; наличие runtime и сообщение при его отсутствии входят в нативную приёмку.

## Сборка Аней

После ревью зафиксировать один commit SHA для общей поставки. PR #29 с отдельным ML-прототипом автоматически в неё не включается. Кандидат следующего общего номера — 0.2.7; Mac при пересборке получает build больше 5. Перенумерация прежнего EXE не заменяет сборку из этой ревизии.

Нужны Python 3.12 с tkinter, Inno Setup 6, portable PostgreSQL 18 x64, распакованная модель `models-0.2m` с `manifest.json` и WebView2 Runtime для запуска. Из корня согласованной ревизии, с путями конкретной Windows-машины:

```powershell
$airaPythonHome = "$env:LOCALAPPDATA\Programs\Python\Python312"
$airaBuildRoot = "$env:USERPROFILE\AIRA-dev\build-0.2.7"
& "$airaPythonHome\python.exe" app/frontend/packaging/updates/fetch_sdk.py windows "$airaBuildRoot\winsparkle"
& app/frontend/packaging/windows/build.ps1 `
  -Python $airaPythonHome `
  -ModelDir "$env:USERPROFILE\AIRA-dev\models\unpacked\models-0.2m" `
  -PgDir "$env:USERPROFILE\AIRA-dev\pgsql" `
  -WinSparkleDir "$airaBuildRoot\winsparkle\WinSparkle-0.9.4" `
  -Out $airaBuildRoot -Version 0.2.7
git rev-parse HEAD | Set-Content "$airaBuildRoot\source-revision.txt" -Encoding ascii
Get-FileHash "$airaBuildRoot\AIRA-Setup-0.2.7.exe" -Algorithm SHA256
```

Не использовать `-NoModel` для пользовательского выпуска. Signing seed не нужен Ане для сборки EXE и не передаётся через чат или установщик. Подпись updater и публикацию выполняет оператор по [общей инструкции](../updates/README.md).

## Проверки

Переносимая проверка без PostgreSQL и без настоящих ключей:

```powershell
python -m pip install -r app/backend/requirements.lock
python -m pytest -q app/frontend/packaging/windows/test_licensing.py
python -m unittest discover -s app/frontend/packaging/updates -p "test_*.py" -v
```

`test_licensing.py` использует настоящий backend-клиент лицензий и boundary, но синтетические устройство, часы и transport. Тест Server wiring использует fixture ASGI thread, а не готовый EXE. CI выполняет эти переносимые проверки и на Windows, и на Mac. Это не сквозная проверка пользовательских кнопок.

До публикации готового EXE на Windows проверить:

1. Установка стандартным пользователем, кириллический профиль, уже установленная версия и сохранность её документов.
2. Чистый профиль: неверный ключ отклонён; действующий ключ активирует это устройство через публичный HTTPS-сервер.
3. Полное закрытие и новый процесс: повторный ввод ключа не нужен, срок прежний. Без сети и после серверного отзыва новый запуск закрыт.
4. Через кнопки: импорт синтетического DOCX с таблицей и изображением, правка абзаца и ячейки, реальная проверка, скрытие замечания, повторная проверка, сохранение и повторное открытие.
5. Экспорт через системный диалог в реальный файл; открытие в Word и сверка текста, таблицы, изображения и оформления. Отмена выбора файла не считается сохранением.
6. Истечение лицензии при открытом документе: сохранить и выгрузить уже сделанные правки можно, новая проверка/правка закрыта.
7. Штатный выход, сбой запуска и обновление: процессы завершаются, данные и активация сохраняются. Без WebView2 показана ошибка и не открыт обходной браузерный режим.
8. Updater: отмена/сбой загрузки, неверная подпись, установка поверх прежней версии и повторный запуск. Пользователи Windows 0.2.0/0.2.1 устанавливают первый EXE с updater вручную.

В отчёте указать версию, commit SHA, Windows/архитектуру, SHA-256 EXE и модели, результат каждого шага, скриншоты и журнал без реальных ключей и текста пользовательских документов. Подпись Ed25519 updater не заменяет Microsoft Authenticode; подпись издателя этой правкой не добавляется.
