# F02-UPDATES-01 — обновления и скачивание AIRA

Решение Никиты в чате, 9 ноября 2026: приложение само проверяет и получает обновления, сайт содержит рабочие ссылки на доступные установщики. Коммит или merge в GitHub **не публикует обновление**: сначала собирается и проверяется установщик, затем оператор подписывает и публикует его.

## Поведение

- macOS: Sparkle 2.10.1, автоматическая проверка/загрузка, установка при штатном закрытии. В меню есть «Проверить обновления…». Перед заменой редактор выполняет `prepareToClose()`, backend завершает работу и останавливает PostgreSQL. Отказ сохранить оставляет приложение открытым. Для асинхронной подготовки используется отложенный install handler Sparkle; `terminateLater` не применяется из-за вложенного run loop AppKit.
- Windows: WinSparkle 0.9.4 проверяет, скачивает и запускает обновление **до** открытия backend и редактора. Отмена/ошибка/отсутствие новой версии продолжают обычный запуск. Установщик сохраняет прежний AppId, каталог установки и пользовательские данные; после автообновления запускает AIRA снова.
- Папка приложения заменяется отдельно от пользовательского профиля, базы и лицензии. Никаких команд удаления данных updater не содержит. Проверка лицензии остаётся независимой от обновления.
- Каждый архив/EXE проверяется по Ed25519. Mac appcast также подписан. Только HTTPS, без токенов GitHub в клиенте. Проверка и скачивание не отправляют документы, лицензионный ключ или логи. Стандартный updater может передавать версию приложения и ОС; профилирование Sparkle отключено.
- Существующие Mac ≤0.2.3 и Windows 0.2.0 не содержат updater: первая установка новой версии выполняется вручную.

## SDK и сборка

Python 3.12, для служебных release-скриптов — `python-dotenv` из backend окружения.

```sh
python app/frontend/packaging/updates/fetch_sdk.py macos /absolute/build/sparkle
python app/frontend/packaging/updates/fetch_sdk.py windows /absolute/build/winsparkle
```

Скрипт проверяет закреплённые SHA-256 официальных архивов перед распаковкой. Не коммитить SDK, модель, установщики или private key. Mac `build.py` принимает `--sparkle /absolute/build/sparkle`, `--version 0.2.4`, `--build 3`. Каждая следующая Mac-сборка получает строго больший целочисленный build. Windows `build.ps1` принимает `-WinSparkleDir C:\build\winsparkle\WinSparkle-0.9.4 -Version 0.2.4`.

`release-config.json` содержит только публичный ключ и HTTPS-адреса. Сервер лицензий встроен в Mac, ручной `license-origin.txt` в профиле больше не нужен. Windows-лицензирование не добавляется этим изменением.

## Подпись и публикация

Единственный источник секретов — `~/secrets.env`, переменная `AIRA_UPDATE_ED25519_SEED`. Её потеря лишает возможности подписывать следующие обновления для уже установленных клиентов. Не заменять ключ при обычном релизе. В установщик попадает только открытый ключ.

Подготовка public-key helper (Mac, рядом с официальным `sign_update`):

```sh
swiftc app/frontend/packaging/updates/public-key.swift -o /absolute/build/sparkle/bin/aira-public-key
python app/frontend/packaging/updates/prepare_keys.py --public-key-tool /absolute/build/sparkle/bin/aira-public-key
```

Последняя команда создаёт seed **только при отсутствии**, дописывает его в `~/secrets.env` с правами 0600 и выводит только public key. Для существующей установки не менять public key в config.

```sh
python app/frontend/packaging/updates/make_appcast.py /absolute/releases/AIRA-0.2.4-apple-silicon.dmg --platform macos-arm64 --version 0.2.4 --build 3 --sign-update /absolute/build/sparkle/bin/sign_update --output /absolute/releases/updates
```

Для Windows аналогично: `AIRA-Setup-0.2.4.exe`, `--platform windows-x64`. Сначала нужен нативный Windows-прогон. Непроверенный EXE в канал не публиковать.

Порядок публикации: загрузить установщик под временным именем вне публичной выдачи; сверить SHA-256 на сервере; переименовать в итоговый файл; проверить HTTPS/размер/range-запрос; затем атомарно заменить соответствующий appcast и ссылки сайта. Архивы имеют версионные неизменяемые URL. Appcast не кешировать. При ошибке сначала снять новый appcast, сохранив предыдущие архивы. Уже установленную версию автоматически не понижать.

Ключи подписи не передаются на сервер скачивания. На сервере лежат только публичные файлы. Для новой версии: сборка → нативные тесты → подпись → публикация; merge PR сам по себе не обновляет пользователей.

## Приёмка

```sh
python -m unittest discover -s app/frontend/packaging/updates -p 'test_*.py' -v
bash app/backend/scripts/check.sh
```

Нативный Mac: установка DMG, запуск/закрытие, проверка новой версии, скачивание и проверка подписи, отложенная установка, повторный запуск, сохранность профиля. Проверить отмену закрытия и испорченный архив. Windows: выполнить тот же цикл на Windows, включая fallback без WebView2, стандартного пользователя, кириллический профиль и существующий путь установки; проверить отмену загрузки, отсутствие сети, испорченную подпись и повторный запуск после установки. Portable tests используют fake DLL и не заменяют эту приёмку.

Ограничения распространения: пилотные сборки ещё без Apple Developer ID/notarization и Microsoft Authenticode. Подпись обновлений Ed25519 проверяет происхождение архива, но не заменяет подпись издателя для Gatekeeper/SmartScreen. Intel Mac и Windows ARM пока не выпускаются. Результаты текущей приёмки фиксируются в PR, без обещания непроверенных платформ.
