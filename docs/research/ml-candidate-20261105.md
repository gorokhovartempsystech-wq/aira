# ML-кандидат и подключение к backend — 5 ноября 2026

Здесь собраны проверенный локальный адаптер и стабильный режим NLI поверх backend из PR #17. Рабочие веса 0.2m не переобучались. Режим `local_model` явно отличается от fixture; отсутствие весов/ошибка модели не подменяется успешной тестовой проверкой.

## Подготовка пакета

Из корня репозитория, используя уже полученный пакет моделей:

```bash
python tools/prepare_ml_bundle.py --models /path/to/models-0.2m --destination app/backend/ml_bundle
```

Скрипт проверяет размеры и SHA-256 каждого файла manifest, запрещает выход из каталога моделей и отказывается перезаписывать непустой destination. В bundle входят `engine.py`, `lint.py`, `stable_nli.py`, `__init__.py` и проверенные веса. Ни скачиваний, ни системной установки скрипт не выполняет. `app/backend/ml_bundle` исключён из Git.

Идентичность исполнения включает код stable_nli.py, а не только номер модели. Это важно: веса прежние, способ расчёта изменился. Исправление устанавливается только в подготовленную копию приложения; запущенный стенд автоматически не переключается.

## Windows-стенд реальной модели

Нужны зависимости backend и ML-runtime из соответствующих requirements, Python 3.12 и отдельная локальная тестовая PostgreSQL. Сервер работает на loopback. Пример запуска из `app/backend` (PowerShell):

```powershell
$env:PYTHONPATH = 'src'
python scripts/serve_local_model.py --runtime-root C:\AIRA-dev-runtime --pg-port 15435 --initialize-test-database
```

Команда использует отдельную БД `aira_native_test` и синтетического локального пользователя. `--initialize-test-database` явно разрешает миграции и создание тестовых записей. Она не нужна для подключения к существующей подготовленной БД. Доступ без пароля относится только к локальному development-стенду с заранее настроенной тестовой PostgreSQL; это не инструкция по публичному развёртыванию. Порт приложения по умолчанию 8017; редактор — `/editor`.

На macOS есть native путь worker; сборка, лицензирование и полный macOS-сценарий этого изменения не приняты. Linux/WSL не выдаётся за native целевую платформу.

## Что измерено локально

На полном CRM (763 фрагмента; с тестовым разделом 771) 1 837 общих направленных входов NLI дали точно одинаковые оценки при изменении соседних пар. Порядок, разбиение и внешние размеры пакета 1/7/32 не изменили логиты. Кэш оценок не используется. Изоляция каждого направления убирает влияние соседей и их padding без изменения токенов/лимита 256.

Два искусственных числовых конфликта найдены, после ручной правки оба исчезли. Контроль разных сервисов не стал конфликтом. Backend принял ответы и сопоставил цитаты с исходным XML; старый snapshot отклонён для новых байтов. Прогон вне интерфейса занял примерно 37–39 секунд на использованной машине; это одиночные замеры, не универсальный benchmark.

Остались два ложных смысловых замечания CRM. Поэтому устойчивость не доказывает качество. На прежних диагностических наборах прямая NLI изменилась неодинаково: 130 и 48 пар — прежние количества находок; на 40 парах верных 2→3 и ложных 5→4; на 36 парах верных 6→5 и ложных 8→7. Порог не подбирался. Разметка предварительная, ассистентская, не экспертный gold.

## Проверки перед включением

`engine`: `python -m pytest -q` — синтетические проверки контракта, инвариантности, числовых случаев и сборки bundle без загрузки моделей.

`app/backend`: `bash scripts/check.sh` — lint, форматирование и вся backend-батарея. Большая PostgreSQL acceptance-батарея требует кластер по её защищённому протоколу, а native проверки — соответствующую ОС. Нельзя объявлять её зелёной на основании только сфокусированных тестов.

Перед пилотом нужны полный UI-сценарий, проверка native сборок, независимая оценка полезности подсказок и устранение ложных конфликтов между записями справочника. Примеры документов и локальные журналы запусков в Git не включены.

## Фактическая проверка перед публикацией

- Engine: 32 passed без скачивания весов.
- Backend Ruff: все проверки прошли, 1000 файлов соответствуют форматированию.
- Целевой набор изменённых adapter/DOCX/native/extension тестов: 109 passed; затем три ошибки PostgreSQL fixture в test_structured_runtime_edges. Отдельный тест идентичности stable_nli вместе с адаптером: 11 passed.
- Полная `scripts/check.sh` остановлена после массовых ошибок окружения: 2461 passed, 373 skipped, 18 failed из-за отсутствующего macOS kqueue в Linux, 940 ошибок подготовки PostgreSQL fixture. Это не зелёная полная приёмка. Протокол fixture и platform-тесты не ослаблялись.
- Реальный CRM на коде публикуемой ветки: полный reader, 763 фрагмента, 50 замечаний, ONNX 0.2m, StableNli; ответ принят строгим backend-валидатором и сопоставлен с источником, около 32,74 с. Исходник сохранён. Файл и цитаты не включены в Git.

Для проверки хранения частичных результатов есть отдельный opt-in тест с AIRA_TEST_PG_SOCKET и новой одноразовой базой. Автоматически подменять им обязательный защищённый PostgreSQL gate нельзя.
