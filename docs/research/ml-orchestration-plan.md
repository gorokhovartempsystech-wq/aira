# Оркестрация AIRA: предложение для следующего эксперимента

AIRA ускоряет поиск мест, требующих внимания системного аналитика. Решение и исправления остаются у человека. Это предложение, не реализованный LLM-путь.

Текущий опубликованный путь: сохранённый DOCX → поддерживаемый reader → правила, embeddings и NLI → валидация цитат → замечания. CPU-пакет0.2m; облачных вызовов нет.

Предлагаемая оркестрация — фиксированный workflow, а не автономные агенты:
1. Reader сохраняет структуру и координаты, отмечает неподдержанные части.
2. Retrieval ищет связанные фрагменты; статус/версия фильтруются до выводов.
3. Быстрые правила и NLI дают кандидатов, но не окончательные исправления.
4. LLM вызывается только на неоднозначном случае с ограниченным контекстом. Возвращает объект, атрибут, условие, исключение, событие отсчёта, число/единицу и точные ссылки на исходные фрагменты; разрешён ответ unknown.
5. Детерминированный валидатор проверяет схему и принадлежность цитат; математический модуль сравнивает границы лишь после разрешения общего контекста.
6. Интерфейс показывает возможное расхождение или вопрос с источниками. Пользователь решает сам.

Не поручать LLM арифметику, статус успешной полной проверки, изменение файла или автоматическое снятие всех NLI-замечаний. Структурированный JSON гарантирует формат, но не истинность извлечённого объекта. Инструкции внутри анализируемого документа трактуются как данные, не команды. Вызов без инструментов записи/сети, лимит времени/контекста/повторов, кэш по хешу документа и версии модели. При сбое LLM локальный результат остаётся доступен и не превращается в «ошибок нет».

Проверка пользы: одинаковый замороженный набор и три варианта — текущий движок; движок + строгие правила; движок + LLM-извлечение + валидация/математика. Отдельно измерять правильность объекта/условия/единицы, полноту конфликтов, ложные замечания, отказы, p50/p95 и память. Проверять случаи с несколькими объектами и косой чертой, исключениями, несовпадающими точками отсчёта, ложными ссылками. Оценивать с системным аналитиком. Прежний небольшой LLM-бенчмарк не доказал надёжного решения и содержал ложные вопросы: выбор модели ещё не принят.

Начать с уже имеющейся локальной LLM как экспериментом извлечения. Облачная обработка документов не включается автоматически: это отдельное решение по данным и продукту. Никаких документов заказчиков в облако без разрешения. Текущий desktop-MVP сохраняет локальный анализ.

Обоснование архитектуры: Anthropic, Building effective agents — рекомендует простые композиционные workflows для определённых задач и усложнение только при измеримой пользе: https://www.anthropic.com/research/building-effective-agents . Это архитектурная рекомендация источника, не подтверждение качества AIRA. Все численные критерии приёмки должны быть согласованы отдельно.
