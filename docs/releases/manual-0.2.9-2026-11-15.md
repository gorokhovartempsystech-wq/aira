# MANUAL-RELEASE-029 — ручной выпуск AIRA

Решение Никиты в чате 15 ноября 2026: пока GitHub Actions недоступен из-за
исчерпанной квоты, собирать и публиковать обновления вручную. PR №25 уже слит
в main; его исправление направления обмена включено в этот Mac-выпуск.
PR №43 с автоматической публикацией остаётся отдельной незавершённой работой.

## Что опубликовано

Mac Apple Silicon 0.2.9, build 9, macOS 14+:

- URL: https://51.250.81.70/downloads/AIRA-0.2.9-apple-silicon.dmg
- Размер: 889326803 байта.
- SHA-256: 992fe478af05d2d7364fc813c492a8a023f4ed2172db69078be068978fb4b0a2.
- Исходники приложения: 13312d96f5ffe6c0afa4a2b4de6f93a19380cf74,
  основаны на main 96a8c865d55c848384309915f3a5fc4c4d25283f с одной правкой
  форматирования защищённых маршрутов; AST до и после одинаков.
- Сайт: dd0384fa44b3ebe71a62016cdadbbdef934814df.
- Модель остаётся зашифрованной, адрес лицензирования и ключ проверки обновлений
  сохранены. Ключ подписи прочитан только из ~/secrets.env на Mac и не передан
  на сервер или в установщик.

Проверено: backend Ruff check и форматирование 1048 Python-файлов; 59 тестов
лицензирования/профиля/обновлений с 8 subtests; 40 тестов движка, включая 6
регрессий PR №25; 2 набора frontend JS; минимальная macOS 14 для 504 нативных
файлов; codesign/hdiutil; независимая проверка Ed25519 установщика и appcast.

Runtime именно из DMG проверен через его локальный HTTP API на синтетическом DOCX:
чистый профиль требует лицензию, публичная HTTPS-активация, настоящий анализ
зашифрованной моделью, правка и экспорт, повторный запуск без ввода ключа и
сохранение документа. Отдельный чистый профиль дважды открыл экран активации
в настоящем WKWebView. Временная тестовая лицензия отключена. Это не полный
проход редактора по кнопкам и не проверка установки Sparkle поверх старой версии.

Полный общий backend gate заново не подтверждён; ранее одновременные нативные
кластеры упирались в shared memory лимит этого Mac. В основной рабочей папке
scripts/check.sh останавливается на трёх прежних E501 в bundle.py; эти чужие
незакоммиченные файлы не использованы для сборки. GitHub CI остаётся заблокирован
квотой. Подпись обновлений Ed25519 не заменяет Apple Developer ID/notarization
или Microsoft Authenticode.

Публикация выполнена через SSH оператора: файл проверен до переключения ссылок,
оба appcast и releases.json лежат в одном новом каталоге каналов, пять файлов
лендинга — в новом каталоге сайта. Существующие current-ссылки переключены
атомарно в своих каталогах; при ошибке HTTPS-проверок предусмотрен возврат.
Код Caddy, лицензирование и права сервисов не менялись. Все четыре сервиса
после публикации активны, публичные SHA-256 и размеры совпали.

## Windows — сборка на компьютере команды

На сайте пока остаётся проверенный Windows 0.2.8: это прежний EXE, без PR №25.
Новый Windows EXE на Mac не собирался и не объявляется проверенным.

На Windows x64 нужны Git checkout этой ветки, Python 3.12 x64 с tkinter,
Inno Setup 6 и существующий Windows runtime PostgreSQL 18 (bin/lib/share).
PgDir можно указать на pgsql внутри уже установленной AIRA; старое приложение
скрипт не устанавливает. Ключ подписи обновлений на Windows не нужен.

Из корня checkout запустить в PowerShell, подставив реальные пути:

~~~powershell
.\tools\manual_release_windows.ps1 -Python "$env:LOCALAPPDATA\Programs\Python\Python312" -PgDir "$env:LOCALAPPDATA\Programs\AIRA\pgsql" -Iscc "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" -Work "C:\AIRA-build-029"
~~~

Если AIRA установлена в C:\AIRA, путь PgDir будет C:\AIRA\pgsql.
Work должен быть новым каталогом с латинским путём. Скрипт не удаляет
существующие каталоги и не использует пользовательские документы или профиль.
Модель и WinSparkle скачиваются по закреплённым URL с проверкой SHA-256.
Проверки запускаются в отдельном Python-окружении; секреты не загружаются.

Результат: release/AIRA-Setup-0.2.9.exe и windows-manual-receipt.json внутри Work.
До этого выполняются тесты лицензирования, 6 регрессий направления обмена,
проверки startup/shutdown и два нативных запуска staged runtime до экрана
активации. При наличии Node также запускаются frontend JS-тесты, что отражается
в receipt. Новый EXE скрипт автоматически не устанавливает и не публикует.

После сборки команда устанавливает полученный EXE и проверяет первый вход,
анализ синтетического документа, правку/экспорт DOCX, закрытие и повторный вход.
Затем оператор получает EXE и receipt, проверяет SHA-256, подписывает на Mac
существующим ключом и отдельно публикует Windows. До этой проверки заменять
публичный Windows 0.2.8 новым номером нельзя.
