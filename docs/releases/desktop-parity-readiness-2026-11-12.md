## Наш блокер до передачи новой Windows-сборки

1. Подключить реальный клиент лицензий к Windows lifecycle: встроенный HTTPS-адрес, идентификатор устройства, сохранённая активация, новая онлайн-проверка каждого запуска.
2. Закрыть продуктовые API до подтверждения лицензии; передавать capability через native bridge. Экран активации, истечение срока и сохранение уже открытого документа должны использовать существующий backend-контракт.
3. Отдельно проверить browser fallback: он сейчас получает connection по HTTP. Нельзя объявлять защищённый native-only режим готовым, оставив незакрытый fallback или потеряв его без явной фиксации изменения.
4. Проверить teardown клиента лицензий, backend и PostgreSQL при ошибке, закрытии окна и обновлении. Существующий пользовательский профиль должен сохраняться.

Пока эти пункты не реализованы и не проверены, готовность Windows к общему лицензированному выпуску **не подтверждена**. Они не перекладываются на Аню как якобы простая команда пересборки.

## Перед сборкой Аней

После снятия блокера фиксируем **один commit SHA** с общими backend, frontend и пакетом модели для обеих платформ. Не примешивать PR #29 или другую ML-модель автоматически. Записываем SHA пакета модели и toolchain в отчёт сборки.

Кандидат следующего общего номера — `0.2.7`; Mac build должен быть больше 5. Это резерв номера, не опубликованная версия. Не переименовывать старый EXE и не изменять VERSION внутри уже собранной поставки.

Нужны Windows x64, Python 3.12 с tkinter, portable PostgreSQL 18 x64, распакованный models-0.2m и Inno Setup 6. Точные рабочие пути Аня задаёт по своей машине. Пример из корня согласованной ревизии, **после** реализации Windows-лицензирования:

```powershell
$airaPythonHome = "$env:LOCALAPPDATA\Programs\Python\Python312"
$airaBuildRoot = "$env:USERPROFILE\AIRA-dev\build-0.2.7"
& "$airaPythonHome\python.exe" app/frontend/packaging/updates/fetch_sdk.py windows "$airaBuildRoot\winsparkle"
& app/frontend/packaging/windows/build.ps1 `
  -Python $airaPythonHome `
  -ModelDir "$env:USERPROFILE\AIRA-dev\models\unpacked\models-0.2m" `
  -PgDir "$env:USERPROFILE\AIRA-dev\pgsql" `
  -WinSparkleDir "$airaBuildRoot\winsparkle\WinSparkle-0.9.4" `
  -Out $airaBuildRoot -Version 0.2.7
Get-FileHash "$airaBuildRoot\AIRA-Setup-0.2.7.exe" -Algorithm SHA256
```

Не использовать `-NoModel` для выпуска пользователям. Команда выше не добавляет отсутствующее лицензирование. Закрытые ключи подписи остаются у оператора в `~/secrets.env`; Аня передаёт проверенный EXE, контрольную сумму и отчёт, а не signing seed.

## Обязательный сценарий кнопками на обеих платформах

На синтетическом DOCX с абзацами, таблицей и изображением записать результат каждого шага:

- Установка из скачанного файла; первый запуск на чистом профиле; версия и журнал.
- Неправильный ключ отклонён; правильный активирует это устройство; текст ключа отсутствует в журнале.
- Полное закрытие и новый процесс: ключ не вводится повторно, срок не продлевается. Без сети и после серверного отзыва новый запуск отклоняется.
- Импорт DOCX, ручная правка обычного абзаца и ячейки таблицы, запуск реальной проверки, просмотр и скрытие замечания, повторная проверка.
- Сохранение, закрытие, повторное открытие: правки и пользовательские решения сохранены.
- Экспорт через системный диалог в реальный DOCX; открыть результат в Word и сверить правки, таблицу, изображение и оформление. Диалог отмены не должен выдавать успех.
- Обновление поверх предыдущего приложения: сохранность документов и активации; ошибка загрузки/подписи не устанавливает повреждённый файл.
- Windows отдельно: стандартный пользователь, кириллический профиль, уже установленная AIRA и согласованное поведение без WebView2.
- macOS отдельно: первая загрузка с карантином Gatekeeper, ручное разрешение пилота и реальные системные диалоги открытия/сохранения.

В отчёте: версия, commit SHA, версия ОС и архитектура, SHA-256 установщика/модели, passed/failed по шагам, скриншоты и журнал без ключей и текста реальных документов.

## Ограничение проверки Mac в этой сессии

Доступное средство управления интерфейсом 12 ноября вернуло `apps: []`: поддерживается только браузер, native computer APIs отключены. Поэтому запуск → активация → импорт → правка → экспорт **через реальные окна Mac-приложения** здесь не пройден. Backend/API-проверки и прежний QA-клон с заменёнными файловыми диалогами не считаются заменой этой приёмки.
