## Подтверждённые проверки

1. Mac DMG собран, устанавливается копированием AIRA.app из образа. Проверены целостность образа и `codesign --verify --deep --strict`. Приложение открывает настоящий WKWebView и экран активации, штатно завершает Python/backend/PostgreSQL.
2. Отказ `prepareToClose()` сохраняет окно и работающий backend. Последующее подтверждение закрывает их штатно. Нативный harness использует отдельный синтетический профиль.
3. Официальный `sign_update` принимает подписанный файл и отказывает после изменения его байтов. Проверена подпись Mac appcast.
4. Четыре группы portable тестов: нет новой версии, ошибка, отмена, закрытие диалога, успешный запуск установщика, тайм-аут; неправильный ключ не позволяет запустить updater; очистка заканчивается до запуска backend.
5. GitHub Actions `desktop-updates` прошёл на macOS 26 и Windows: компиляция настоящей Mac-оболочки со Sparkle, portable tests на обеих ОС и Native Windows DLL contract: загружается настоящая WinSparkle DLL, все используемые функции доступны, неверный ключ отклоняется, открытый ключ выпуска принимается. Это не тест EXE/WebView2/установки.
6. Общая backend-команда `bash scripts/check.sh` с остановкой на первой ошибке: Ruff и форматирование прошли; 4081 passed, 26 skipped, 1 failure — тайм-аут `test_owned_merged_cell_edit_check_preserves_source_parts`. Отдельный неизменённый тест прошёл за 12.12 с. Оставшиеся 3194 случая из того же набора: 3173 passed, 21 skipped; 24 subtests passed. Суммарно 7255 passed и 47 skipped, все 7302 случая учтены. Первый полный запуск не был зелёным; тайм-аут отмечен, критерии не ослаблялись.
7. Windows-файл совпал с оригиналом GitHub по размеру 326805641 байт и SHA-256. На сервере контрольная сумма совпала; проверены HTTPS, Content-Length и byte-range. Неполные `.part` не выдаются. Сервер лицензий сохраняет прежние маршруты и корректные ответы.
8. Сайт проверен в браузере при 1280×720: обе ссылки и справка, отсутствие переполнения страницы. Указаны реальные версии и ограничения платформ.

9. Реальное Mac-обновление через публичный HTTPS: тестовая копия с тем же updater, но уменьшенным build 2, получила подписанный DMG, проверила подпись и подготовила установку. Штатный запрос закрытия прошёл через `prepareToClose()` и остановку backend. Sparkle заменил приложение на 0.2.4/build 3; исполняемый файл совпал с финальным DMG, `codesign --verify --deep --strict` прошёл. Это не обновление старой выпущенной 0.2.3, в которой updater отсутствует.
10. После замены отдельный процесс backend из нового bundle подтвердил онлайн-лицензию с прежними ID и сроком; ранее импортированный синтетический DOCX экспортировался с прежним SHA-256. Первую попытку этой проверки исправили в одноразовом harness: запрос `/desktop/license/verify` требует JSON `{}`, а не пустое тело. Продуктовые проверки не менялись.
11. Публичная страница открывается в браузере без входа в GitHub, показывает реальные версии и ограничения. Обе службы Caddy и лицензирования активны после публикации.

12. Повторный запуск обновлённой нативной оболочки: smoke на новом профиле показал экран активации и завершился кодом 0. На активированном профиле этот smoke неприменим — он ожидает именно поле ключа; такая попытка закончилась тайм-аутом. Сохранность активированного профиля проверена отдельно в пункте 10.

## Ограничения

Старые Mac ≤0.2.3 и Windows 0.2.0 не умеют обновлять себя: первый переход ручной. Windows 0.2.0 не содержит лицензирования. Для следующего Windows EXE нужна нативная приёмка установки/обновления с документом, WebView2, обычным пользователем и кириллическим профилем. Пилоты без Apple Developer ID/notarization и Microsoft Authenticode; Ed25519-подпись обновления не заменяет подпись издателя ОС. Нативные Windows/backend gates, явно пропущенные на Mac, не объявляются пройденными. Merge PR сам по себе не публикует обновления.
