# MVP: десктопный редактор требований с ревью

Версия: обсуждение команды 24.10.2026.

## Сценарий

1. Пользователь вставляет текст требований (из Confluence, Word, задачи) или открывает `.md` / `.docx`.
2. Текст открывается в редакторе — можно поправить, дописать.
3. По кнопке «Ревью» — список замечаний справа: тип, светофор, объяснение, предложение.
4. «Исправить» у замечания меняет текст (с историей и отменой).
5. Правка пункта → «Проверить влияние» → что ещё в документе нужно обновить.
6. Список «Что уточнить» — вопросы к бизнесу и технике.
7. Сохранить документ (`.md`, `.docx`).

## Что внутри (движок, `engine/`)

| проверка | как | где |
|---|---|---|
| формулировки (ISO/IEC/IEEE 29148, INCOSE) | правила | CPU, мгновенно |
| дубли | близость эмбеддингов | CPU |
| противоречия между пунктами | NLI-модель, дообученная на требованиях | CPU |
| **что задето правкой** (ядро) | поиск по словам и смыслу + классификатор пары | CPU, ~0,2 с |

Пакет моделей — около 400 МБ, работает без интернета, память процесса ~800 МБ.

## Почему так (из исследований)

- Пробел на рынке — поиск мест, задетых изменением требования. Проверку формулировок
  бесплатно делает ChatGPT, она — бесплатный «вход», а не ценность.
- Главный барьер — доверие: показываем мало и с основанием, правку предлагаем, не применяем.
- Безопасность: локальные модели — документы не уходят с компьютера (ответ на требования ИБ и NDA).
- Первый сегмент: студии заказной разработки и интеграторы на 20–100 человек с 1–5 аналитиками.

## За рамками MVP

Автофикс всего документа; экспорт с комментариями (гипотеза); ревью диаграмм (MVP+, сначала
drawio); подключение к Confluence и Jira (есть рабочий прототип коннектора); генерация ТЗ из
протоколов встреч (требует LLM — уровень Pro / сервер).
