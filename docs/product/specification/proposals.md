## Как предлагать изменения

1. Открыть PR с изменением текстовой спецификации и ссылкой на ID требования.
2. В описании указать проблему, предлагаемое поведение и проверку приёмки.
3. Обсудить изменение с ответственными за продукт, интерфейс и ML.
4. После согласования обновить статус предложения и при необходимости выпустить новую DOCX-версию. Исходный DOCX от 4 ноября сохранять как исторический снимок.

Текстовая версия в Git предназначена для дальнейшего согласования; исходный DOCX фиксирует полученную версию. Наличие требования в документе не означает, что функция реализована.
