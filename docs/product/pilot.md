# Пилот: как проверяем пользу

- **Клиент:** одна команда с 2–5 аналитиками (лучше заказная разработка или интегратор).
- **Срок:** 2 недели живого потока доработок + ретро по прошлым багам.
- **Где работает AIRA:** у пользователя на компьютере (десктоп, локальные модели). Документы
  клиента к нам не попадают. Облачная LLM — только с письменного согласия и с маскированием.

## Метрики (пороги договариваемся до старта)

| метрика | как считаем | порог (предложение) |
|---|---|---|
| полезные находки | «полезно, я бы пропустил» на одну доработку | ≥ 1 на 2 доработки |
| шум | доля «шум» среди находок | ≤ 50 % |
| время | минуты на просмотр ответа | ≤ 10 мин |
| использование | доля доработок, прошедших через AIRA без напоминаний | ≥ 70 % на 2-й неделе |
| срок жизни задачи | от передачи аналитику до выпуска (так меряют руководители) | для отчёта |
| ретро | сколько из 5–10 прошлых багов «из-за требований» поймали бы | для отчёта |

## Ход

1. День 0 — договорённость: NDA, где работает AIRA, пороги. Схема потоков данных — службе ИБ.
2. Дни 1–2 — установка, показ, как AIRA разобрала их документы.
3. Недели 1–2 — работа, оценки находок в приложении; созвон раз в неделю.
4. День 14 — итоги: метрики против порогов, разбор шума, разговор о цене.

## Роли

Никита — договорённость с клиентом и итоговая встреча; Артём — установка, модели, метрики;
Анна — обратная связь аналитиков, интервью до и после.
